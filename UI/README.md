# K12Agent 界面原型（UI/）

> 由 Pencil 画布 `pencil-new.pen` 的选中帧生成，用于**界面布置准备**。
> **暂不接线**：本目录不依赖 `desktop/` 的 IPC、preload 与冻结契约运行时，也不依赖 `server/`。

## 怎么跑

```bash
cd UI
npm install
npm run dev           # http://localhost:5273
npm run typecheck     # vue-tsc --noEmit
npm run build         # 生产构建（同时跑 typecheck）
npm run check         # typecheck + 对比度 234 项 + 死按钮审计（提交前跑这个）
npm run gen:tokens    # 由 tokens.source.json 重新生成两轴 CSS 变量
node scripts/audit-layout.mjs   # 骨架指纹 + 焦点 + 字号档位 + 主路径提示
```

**`audit-layout.mjs` 是什么**：**静态**读每个页面的 `<template>` 与 scoped `<style>`，
回答一个具体问题 —— **「这些页面是不是都用同一种骨架搭的」**（"处处等价卡片"）。
它输出每页的版式原型（分栏 / 表格 / 等价卡片矩阵…）、卡片数、字号档位，
并断言四件事：

1. **骨架指纹**不雷同（同类上限 4 页；当前 12 页 10 种指纹，最大同类 2 页）
2. **焦点**：内容区最大字号 ≥22px 且严格大于顶栏 chrome（15px）—— 内容不得被外壳压住
3. **字号档位**：11px 只落在角标语义上（见上）
4. **主路径提示**：每个内容页有一行 12px 的"先做什么、再做什么"

⚠️ 它**不是渲染度量** —— 不算真实布局、不看窗口宽度。
真实观感由逐页实拍核验。**测不准的地方宁可说测不准，也不硬凑指标。**

### 布局体检探针（渲染后才知道的问题）

`audit-layout.mjs` 只读声明，看不见"撑破 / 裁掉 / 叠在一起"。
`scripts/layout-probe.js` 补这一半：它在**真实浏览器**里量几何，查四件事 ——
内容溢出盒子、元素跑出视口、同级元素互相叠压、`overflow:hidden` 把内容切掉。

它不是 npm script（要注入浏览器上下文才能跑）。起 dev server 后任选一种：

```js
// ① 浏览器控制台：粘贴 layout-probe.js 全文，然后
__layoutProbe()

// ② Playwright / chrome-devtools MCP：
await page.addScriptTag({ url: 'http://localhost:5273/scripts/layout-probe.js' })
const r = await page.evaluate(() => window.__layoutProbe())
```

**要扫 1440 / 1280 / 1120 三种宽度。** 本项目 `#app` 有 `min-width: 1120px`、
媒体查询断点在 1279px，窄端最容易坏 —— 实测就是在这个区间发现了
「学习档案的 hero 被媒体查询强制堆成三行」（53px → 170px）。

## 技术栈

| 项 | 选择 | 说明 |
| --- | --- | --- |
| 框架 | Vue 3.5 + TypeScript 5.9（strict） | 与 `desktop/` 保持一致，便于后续整体迁入渲染进程 |
| 构建 | Vite 7 | 与 `electron-vite@5` 的 peer 一致 |
| 组件库 | **Element Plus 2.14.5** | **按需引入**（unplugin 自动导入），承担控件层（见下） |
| 图标 | **lucide-vue-next** | 画布中所有图标都是 lucide |
| 路由 | vue-router 5（hash 模式） | hash 模式提前对齐 Electron 的 `file://` 加载 |
| 状态 | Pinia 4 | 只有主题一个 store |
| 字体 | **本地自托管 woff2**（可变字重） | Inter / Noto Sans SC / JetBrains Mono，**零 CDN**（断网演示硬约束） |

**为什么用可变字体**：画布大量使用 550 / 620 / 650 这类中间字重，静态字重包没有这些档位。

### Element Plus 承担什么

**控件层归 EP，布局与视觉归手写 CSS。** 手写的那部分是同构的（玻璃面、极光背景、两轴配色），
换成 EP 拿不到收益；而控件（按钮 / 输入 / 表格 / 进度条 / 折叠 / 时间线）自己写就是重复造轮子，
还会漏掉键盘与 aria 语义。

实际用到的 EP 组件：`el-button` `el-input` `el-form` `el-radio-group` `el-config-provider`
`el-segmented` `el-progress` `el-table` `el-timeline` `el-descriptions` `el-tag` `el-steps`
`el-collapse` `el-alert` `el-empty` `ElMessage`。

**EP 按需引入是硬要求**：若在 `main.ts` 里写 `app.use(ElementPlus)` +
引入 `element-plus/dist/index.css`，主 chunk 会从 **154 kB 涨到 1035 kB**（gzip 61 → 342 kB）。
中文语言包走 `App.vue` 的 `<el-config-provider :locale="zhCn">`。

> ⚠️ **EP 的色阶必须整套映射**，不能只映射 `--el-color-primary`。
> `el-button--primary` 的 hover / active 用的是 `--el-color-primary-light-3` / `--dark-2`，
> 只映射主色的话，**hover 主按钮会掉回 EP 默认蓝**。`base.css` 现在用 `color-mix()`
> 从项目 token 派生 primary / success / warning / danger 的全套色阶。

## 视觉体系：画布的浅色分层

### 层次是四层，不是一种卡片

| 层 | 是什么 | token |
| --- | --- | --- |
| **page** | 页面底色 —— **带学段色**（初中 `#ECEDFE`、小学低 `#FFF2E4`…） | `--k12-page` |
| **surface** | 白卡片 + 1px 边框 + 浅投影 | `--k12-surface` |
| **surface-2** | 卡片内的嵌入块（浅色高亮底、表格头、工具面） | `--k12-surface-2` |
| **float** | 浮层（对话框 / 菜单 / 悬浮追问窗） | 白 + 更强投影 |

**规则：任何"一块内容"必须是这四层之一，不许出现第 5 种自定义表面。**

### ★ 为什么"分不清组件边界"（这一轮修掉的根因）

根因不是边框太细，而是**页面底色也被做成了白的** —— 白卡片压在白页面上，
只能靠 6% 透明度的细线分隔，等于没有分隔。而且同一个卡片配方被手写了 **16 遍**，
值还各不相同（边框有的用 `--k12-border`、有的用 6% 的 fg）。

画布原本的设计正是"**带色的页面底色 + 白卡片**"，这一版恢复了它。
恢复之后边界不靠加粗描边就成立了：白卡片浮在淡紫页面上，一眼一块。
同时把 16 处手写卡片统一成 `--k12-border` + `--k12-shadow-card` 的标准取值。

### 两支学段色：一支"被看"，一支"被读"

| token | 来源 | 用途 |
| --- | --- | --- |
| `accent` | **画布原值**（`#4F46E5` 等） | 边框、浅底、大片装饰 —— "被看"的东西 |
| `accent-ink` | 由 accent 与 fg 插值**算出来的压深版** | 文字、按钮填充、进度、节点 —— "被读"的东西 |

画布的 accent 是为**大面积色块**定的，直接当小字色用不达标
（小学低 2.8:1、品牌绿 2.5:1，AA 要 4.5:1）。所以配了一支 ink：
色相不变、明度压到 5.0–6.3:1。**明快感留在 accent，可读性交给 ink。**

规则：改颜色时先问"这个元素是要被看还是要被读"。

### 对比度：机器校验

```bash
node scripts/check-contrast.mjs           # 报告
node scripts/check-contrast.mjs --strict  # 不达标 exit 1
```

**234 项全部达标**：accent-ink 压在 4 种可能的底上（白 / 页面底色 / 嵌入块 / 浅色高亮底）、
chip 文字、语义色（压在自己的浅底上与压在白上）、正文三级。
18 组 × 十几个 key 有几百个组合，手算查不过来 —— 这是它存在的理由。

### 卡片头 / 卡身 / 卡脚

`SurfacePanel` 提供 `head` / `body`（默认槽）/ `foot` 三个插槽，
**卡头带浅色底 + 下边框**。上一版很多卡片只有一个标题文字、与内容连成一片，
这是边界糊掉的第二个原因。

### 页面操作栏

`PageActions` 统一放在内容区顶部：左说明、右操作。**不重复页面标题**（顶栏已经有了）。
此前多页要么没有页面级操作，要么把操作藏进卡片头（比如动画页的"重新生成"），
使用者找不到"这一页能做什么"。现在**每一页的操作都在同一位置**。

长页面（学习档案 / 依赖图谱）滚动后它**吸顶**，操作始终在手边 ——
"导出报告""重建索引"正是看完内容之后才想按的。
吸顶条的分隔线只在真的吸住时出现，由 `AppShell` 在滚动容器上挂 `.is-scrolled` 驱动
（纯 CSS 判断不了 sticky 是否已吸住）。

各页内边距不同，所以由使用页覆盖两个变量对齐：

```css
.pf { --pa-pad-y: 18px; --pa-pad-x: 22px; }  /* 规格页用 16px / 20px */
```

### ★ 操作位置约定（改页面时遵守）

| 位置 | 承载什么 | 例 |
| --- | --- | --- |
| **`PageActions`**（页顶，吸顶） | **页面级**操作 | 导出报告 / 重建索引 / 刷新 |
| **卡片头** | **对象级**操作（作用于这一条） | 展开 / 重新生成 / 追问 |
| **卡脚** | **状态提交** | 保存 / 提交批改 / 运行 |

判据：**这个操作作用于"整页"还是"这一块"？** 作用于整页的进 `PageActions`；
只作用于某一个对象的留在那个对象的卡上。放错位置比没有更糟 ——
使用者会去 `PageActions` 找一个只对某条生效的按钮。

## 排版尺度

字号 8 档，**正文基准 14px**：`micro 11 / xs 12 / sm 13 / md 14 / lg 16 /
title 15 / xl 22 / 2xl 28`。

**档位与用途一一对应，这是本轮的返工起点**（改之前先读这张表）：

| token | 值 | 用途 |
| --- | --- | --- |
| `2xl` | 28px | 仅对话页空态问候（全站唯一） |
| `xl` | 22px | **页面身份行** / hero 数字 |
| `title` | **15px** | **仅顶栏页面名**（chrome）—— 必须**小于**内容区的身份行 |
| `lg` | 16px | 卡片 / 区块标题 |
| `md` | 14px | 正文 |
| `sm` | 13px | 次级正文、列表项 |
| `xs` | 12px | meta、单位、脚注、主路径提示 |
| `micro` | **11px** | **仅角标（≤4 字）** |

**为什么 `title` 从 18px 降到 15px**：内容区最大字号原本是 16px，
而顶栏 18px 的页面名比内容还重 —— **外壳压着内容**，眼睛不知道该从哪读起。
现在内容区的最大字号由各页顶部的身份行（22px）承担，chrome 退后。

**11px 只给角标**。它曾是全站**最高频**字号（被用来写 id、关系、说明），
于是 meta 与角标同权、层级整个塌掉。判据有两条出路：选择器名含角标词
（badge / chip / tag / pill / count / num / dot / step / idx / key / mark / level），
或在声明 11px 的规则里显式写 `k12-mark` 注释。
守卫：`node scripts/audit-layout.mjs`。

圆角 5 档：`flat 4`（角标 / chip / 代码片）/ `inset 6`（卡片内嵌入块）/
`card 10`（卡片）/ `control 12`（按钮、输入框）/ `pill`（状态标签）。
**控件比卡片更圆** —— 卡片是"承载内容的平面"，控件是"拿起来的物件"。

**阅读节奏三档**（`--k12-gap-block` 20 / `--k12-gap-msg` 36 / `--k12-gap` 16）：
块之间 20px（正文→步骤→要点→引用→卡片）、消息之间 36px（一轮对话是一个单元）、
并列卡片之间 16px。**段落之间不用 token** —— 行高 1.7 自身就产生了停顿。
依据：眼睛靠**间距差**分辨层级，不靠字号差。返工前对话页的段落视觉间距是 35.8px，
而消息之间只有 20px（更小）、块间与段落同为 12px，四个层级里三个挤在同一个值上。

**精密细节**：小标签加 `0.02em` 字距（`.k12-label`）、数字用等宽并右对齐
（`.k12-num` / `.k12-readout`）。成本极低，但一个数字列如果不对齐，
整页都会显得潦草。

> **完整契约见 `LAYOUT-CONTRACT.md`**（字号 / 节奏 / 身份行 / 焦点规则 / 材质 /
> 操作位置 / 模态焦点 / 验证命令）。那是并行改造期间的冻结约定，改页面前先读它。

> **为什么底稿是 12.5px、这里却是 14px**：底稿按 1440×900 画，早期实现是
> 「窗口窄于 1440 就对整个界面 `transform: scale(w/1440)`」，于是 1100px 窗口下
> 正文实际只有 ~9.5px。改成真响应式断点后字号不再被二次压缩，于是按桌面阅读距离重定基准。

## 动效：几乎为零

**这一版刻意几乎不含动效** —— 没有入场 `animation`、没有页面切换过渡，
逐字输出与自动播放也停掉了。全站只剩三处动效，且都有明确理由：

| 处 | 是什么 | 为什么留 |
| --- | --- | --- |
| `EmptyState` 的转圈 | 加载中（`tone="loading"`） | 表达"正在进行中"，不转就等于卡死 |
| `ModelPicker` 的转圈 | 「拉取模型」进行中 | 同上 |
| 两处模态淡入 | `opacity 120ms var(--k12-ease-state)` | 让遮罩的出现可被眼睛跟上 |

三个转圈都做了 `prefers-reduced-motion: reduce` 降级（`animation: none`）。
**唯一允许的时长与曲线是 `--k12-dur-state` / `--k12-ease-state`**，不要在组件里各写一套。

理由：**动效会掩护静态设计的缺陷。** 让它动起来时，人不容易看出层次、间距与
排版的问题；去掉之后，界面必须靠材质、留白、字体层级与信号色自己站住。
这一轮的美学重做就是在这种"裸奔"状态下做判断的 ——
重排只靠**间距差与字号档位**建立层级（见「排版尺度」一节的节奏三档），
没有用任何过渡或位移来"演"出层级。

保留的只有**状态本身**（`:hover` / `:focus-visible` 的颜色与描边变化）——
那不是动效，是"现在处于什么状态"的信息。

需要恢复动效时注意几点（前一版的规格仍有效，落在 `git log` 里）：
- 用 `@starting-style` + `transition` 而不是 `@keyframes`（后者在快速插入的元素上会从零重启、不可打断）
- `prefers-reduced-motion` 必须在 **JS 侧**也读一次 —— 它杀不掉 `setInterval`
- hover 动效要加 `@media (hover: hover) and (pointer: fine)` 门禁

## 响应式：真断点，不是等比缩放

| 宽度 | 行为 |
| --- | --- |
| ≥1440 | 外壳铺满，阅读栏弹性（上限 `--k12-w-reading: 820px`） |
| 1280–1439 | 对话右栏可折叠；阅读栏在 720–820 之间 |
| <1280 | 侧栏收成 64px 图标条；对话右栏改为**浮层 + 遮罩**，进入该区间自动收起 |
| <1120 | 出横向滚动（`#app { min-width }` 兜底；接线时由 Electron 窗口 `minWidth` 承接） |

**字号在任何宽度下都恒定**（这是废掉等比缩放的直接原因）。
右栏的自动收放用 `matchMedia` 监听断点，但**不覆盖用户手动开合的选择**。

## 路由结构（三区）

| 区 | 路径 | 内容 |
| --- | --- | --- |
| 产品主线 | `/app/*` | **对话课堂（默认主界面，`/` 直接落到这里）**、动画讲解、编程环境、闯关练习、学习档案、设置 |
| 产品主线（不占导航） | `/app/knowledge`、`/app/dependency` | 教材知识库、依赖图谱 |

### ★ 对话是主界面，三种辅助形态是卡片展开视图

这是本次改造的核心 IA 决策：

- **`/` 直接落到 `/app/chat`**。原「学习台首页」（`/app/home`）已撤：四入口磁贴的职责
  由**对话空态的能力入口**承担，「继续学习 / 掌握度 / 本周活动」并入**学习档案页**。
  理由是三个入口并列会稀释「以对话为主」这件事 —— 学生打开应用应该直接能提问。
- **动画 / 编程 / 闯关三页保留**，但导航上同属「能力」分组，且页面内部是**内联卡的放大版**：
  同一套术语与数据形状，卡片右上角「展开」即进入对应页。形成「对话 → 展开」一条主线。
- 侧栏导航**由路由表 `meta` 推导**（`nav` / `section` / `icon` / `badge`），不在组件里另写清单。
  `section: ''` 的项独占一组且不渲染组标题（对话是主入口，不该被归进某个分组）。

原 `/app/workbench`（多模态工作台）**已删除**：它的「四交互同屏」叙事被新的对话主导 IA 吸收，
且那一页是假 UI 最集中的地方（命令条不是输入框、输入条是死的、模式切换只换一张写死的卡）。
需要的话可以从 git 历史取回。

## 学段：无人工入口（按架构修正）

`AGENTS.md §5.1` 明令：**学段没有人工选择入口、没有确认、没有纠偏**，唯一写路径是服务端推断。
画布上有两处与之冲突，本原型**按架构修正**（不是遗漏）：

| 画布位置 | 画布上的样子 | 本原型的处理 |
| --- | --- | --- |
| 「1. 对话课堂」顶栏 | `Segmented`（初中 / 高中 / 小学高）选择器 | 换成 `GradeIndicator` 只读指示器 |
| 「2. 学段自适应」提示条 | 「确认调整」/「保持初中」两个按钮 | 改为**只读说明条**，两个按钮删除 |

**学段说明不再重复三遍**：此前「顶栏指示器 / 对话顶部横幅 / 右栏学段页」三处都在讲同一件事，
现在只在**空态**（首屏最需要解释的时刻）与**右栏**出现。

`stores/theme.ts` 把「配色轴」与「学生学段」拆成三个概念，避免误用：

- `inferredGrade` —— 学生的真实学段（领域事实，来自服务端推断；原型为 mock）；
- `grade` —— 配色轴（跟随 `inferredGrade`，开发期可在开发页临时改）；
- `displayGrade` —— 指示器实际显示的学段。

**开发模式门禁是两层的**：
1. 页面本身在 `/dev/theme`，不在学生端导航；侧栏底部有「开发工具」入口；
2. 必须先点「开启开发模式」，否则 `setGrade()` 直接拒绝并警告；
   关闭开发模式时配色轴**复位到学生真实学段**，避免开发态残留影响验收。

## 与冻结契约的关系

`src/types/contract.ts` 是**手写的对照镜像**，字段名逐字对齐 `server/app/contracts.py`
（camelCase 出参）。`src/mocks/index.ts` 的形状也对齐契约，内容尽量取自仓库真实资产：

- 知识点 / 章节 / 小节名 ← `server/_data/shared/kb.sqlite` 的 `chunk` 表
- 依赖边 ← `server/knowledge/manifest.json` 的 `dependencies`（47 条，`from` 是前置）
- 题目 ← `server/resources/quizbank/junior.json`
- **动画模板 ← `server/resources/templates/*.json`（8 个，id 与标题为真实值）**

> **接线时**：`openapi-typescript` 生成的类型应**取代** `contract.ts`（票 04 的防漂移链），
> `mocks/` 目录整体删除，改为 IPC 事件流 + sidecar HTTP 响应。

### 镜像尚未覆盖的字段（临时在页面内补，接线即消失）

| 字段 | 处 | 说明 |
| --- | --- | --- |
| `providerId` | `SettingsView` | 后端明确要求**不能与 `providerName` 合并**：`providerId` 进 Pi（决定 provider 定义），`providerName` 只用于显示 |
| `apiKey`（掩码） | `SettingsView` | 后端出参里有掩码字段，镜像未收 |

### 对话消息模型对齐 6 事件

`ChatView` 的消息结构是**按事件形状**建模的（`Block` 联合类型），接线时只换数据源：

| 事件 | 落到哪里 |
| --- | --- |
| `delta` | 往最后一条 assistant 消息的尾部 `text` 块追加文字 |
| `citation` | 追加 `citations` 块（**5 字段投影，不显示相关度分数** —— 契约里没有该字段，显示了等于承诺一个送不到的值） |
| `payload` | 追加 `payload` 块（`kind` 由 Tool 名映射） |
| `blocked` | 该条替换为 `notice(blocked)`，用 `blocked.safeText` 作正文 |
| `done` | 收尾：解除 streaming |
| `error` | 追加 `notice(error)`，带 degraded |

## 交互完成度：界限在哪

原型的**引擎不接**（不跑 Anime.js、不加载 Pyodide、不发 LLM 请求），但**界面层要完整** ——
"看起来能点、点了没反应"比"没有这个按钮"更糟。所以每一处都遵循两条规则：

**① 能真做的就真做。** 数据都在前端，就没有理由假做：

| 功能 | 行为 |
| --- | --- |
| 导出依赖边 CSV / 学习报告 Markdown | 真下载文件 |
| 下载代码 `.py` / 复制代码 | 真写文件 / 真进剪贴板 |
| 导入教材 | 真打开文件选择器并解析标题层级 |
| 模型切换 | 真改变全局状态（顶栏、输入条、设置页同步） |
| 探测可用性 | 给出确定结论与延迟，**并注明"原型未发真实请求"** |
| 重建索引 / 生成动画 / 提交批改 / 运行代码 | 完整状态机：进行中 → 成功 **或失败** |
| 复制代码 | 真写系统剪贴板（`navigator.clipboard`） |

**② 做不了的要说清去哪儿做。** 结果文案写的是"接线后由后端实测"，而不是假装成功。

### 二级界面（此前一个都没有）

审计发现**全站没有任何 `el-dialog` / `el-drawer`** —— 于是所有需要"看得更细"的地方
都只能干瞪眼。现在有四类：

| 界面 | 从哪打开 | 内容 |
| --- | --- | --- |
| **模型选择器** | 顶栏模型指示器 / 输入条模型 chip | 候选清单（与 Pi 目录一致）+ 探测结果 + 去设置页兜底 |
| **教材原文** | 点击引用行 | chunk 全文 + 命中学段 + 相关度 + 检索方式 |
| **知识点详情** | 右栏掌握度行 | 掌握度 / 答题数 / 最近练习 + 「去闯关」「看依赖」 |
| **做题记录** | 闯关页操作栏 | 每次作答的时间、对错数、判分方式、掌握度增减 |

### 契约里有、界面上必须看得见

这几个字段此前**一条都没渲染过** —— 契约定义了、后端会返回、界面当作不存在，
等于那条功能在原型里是空白的。现在都有落点：

| 契约字段 | 展示位置 |
| --- | --- |
| `CodeEvaluation.error`（CodeError：type / message / line / rawTraceback） | 编程卡的**报错分支**：错误类型 + 行号 + 人话解释 + 原始报错可展开 |
| `CodeEvaluation.nextHint` | 报错后紧接着的「建议的下一步」 |
| `AnimationPayload.fallbackText` | 动画卡的**降级态**：「动画没能生成，先看文字讲法」+ 重试 |
| `QuizQuestionOut.explanation` | 闯关结算里每题附「解析」（用左侧细线标出它是讲解不是作答） |
| `RagHit.text` / `score` / `degraded` | 教材原文抽屉 |

**这是"设计合理性"那 25% 的直接证据**：报错感知、降级兜底、引用可溯 ——
这三条都是执行文档里写明的设计点，现在在界面上都能当场演示。

**所有模态都能用 Esc 关闭**（6 处，`composables/useEscape.ts`）。
此前一个都不能 —— 对 `role="dialog"` 来说，不能用键盘关掉是硬伤。

**确认对话框**（`ConfirmDialog` + `stores/confirm.ts`）是 Promise 语义的：
`if (!await confirm.ask(...)) return` —— 让"确认 → 执行"成为不可跳过的序列。
目前用在**清空会话**上（此前一点就抹掉整段对话，没有反悔机会）。
空会话不弹确认 —— 滥用确认会训练人无脑点确定。

### 关于 uiverse galaxy 组件库

[demo 按钮形态](https://github.com/uiverse-io/galaxy) 参考过（描边反转、hover 填色那一类），
但**没有直接引入它的 CSS**。原因写在这里，免得后面有人再问一次：

- 它的按钮卖点是 **hover 动效**（`translateY(-10px)`、旋转方块滑入），
  而本项目按需求**动效为零**；引入等于把刚删掉的东西装回来；
- 色值是**写死的**（`#FF5858`、`rgb(20,87,244)`），会破坏 token 单一来源；
- 圆角 20–50px，与"硬边纸本"的形状语言冲突；
- 1200+ 个文件按随机代号命名（`0x3ther_heavy-dragon-56`），没有 npm 包也没有分类，
  "采用"实际是复制代码进来自己维护 —— 对 15 天的项目是负债。

**采用的是形态、不是代码**：`.mp__probe-btn`（描边按钮，hover 反色）与
`ConfirmDialog` 的按钮对都按这个形态做的，但颜色走 `--k12-*`、零动效、方角。

> 顺带一提：`scripts/audit-buttons.mjs` 会扫描全站的 `<button>`，找出既无 `@click`
> 也无 `disabled` 的。它**跳过 CSS 注释** —— 否则注释里写的 `<button>` 会被当成真按钮
> 报假阳性（实测踩到过）。当前 65 个按钮全部合格。

## 已知取舍

- **不加密色模式**：画布只定义了 18 组**亮色**主题，配一套暗色等于新造一套配色，
  会破坏「配色以画布为唯一来源」这条约束。`base.css` 保留了 `prefers-reduced-transparency`
  与 `prefers-reduced-motion` 两个无障碍分支，但没有 `prefers-color-scheme: dark`。
- **`--k12-btn-*` 已接上**：画布为主按钮定义的三件套此前零引用，于是「素净」档本该是
  【白底 + 学段色文字 + 柔和描边】的主按钮从未出现过。现在主按钮走这套 token。
- **favicon 缺失**：`vite preview` 会报一条 404，无影响。
- **`UI/.shots/`** 是验收截图的工作目录，不入库。
