## 问题清单（按严重度）

### P0-1 便携版重启后学生数据全部丢失【数据丢失】

- **现象**：关掉便携 exe 再启动，顶栏回到「未配置」、学段回到「还没认出年级」、聊天页回到最初空态、重建过的知识库消失。
- **取证**：
  - 首次运行期间 `%TEMP%\k12-agent-desktop-portable\data\` 下有 `config.json`、`shared/kb.sqlite`、`students/student_001/learning.db`；
  - 关闭后重启，`data/` 内所有内容重建时间为 17:19:xx，`config.json` 与 `shared/` **不存在**，
    解压目录里的 `k12-agent-desktop.exe` 创建时间也是 17:19:19（= 启动器重新解压了一份干净副本）；
  - UI 截图：模型 chip「未配置」、学段 chip「还没认出年级」、空态问候语与首次启动完全一致。
- **机制**：`src/main/index.ts` 的 `applyPortableDataDir()` 把 userData 指到 **exe 同级 `data/`**，
  而便携单文件形态下 `exe` 位于**启动器的临时解压目录**（`PORTABLE_EXECUTABLE_DIR` 在 Electron 侧拿不到，代码注释已说明）
  → 数据落在临时目录，启动器每次重新解压即等于清空。代码注释自称这种形态「只能当一次性试跑」，
  但 `npm run build:portable`（本仓库唯一的本地出包命令）产出的**正是**这一个形态。
- **影响**：与「数据全本地」「重启后进度/徽章/掌握度都在」的验收口径直接冲突；演示现场一重启就回到出厂状态。
- **建议**：便携形态把 userData 指到真实持久目录（启动器 `--data-dir` 显式传给主进程），
  或改以 zip 绿色形态作为可持久形态，并在 UI/文档写明「单文件 exe 不保存数据」。

### P3 级（不影响主链路）

- **P3-1** 对话内答题卡片一次列 114 关进度，卡片被拉得极长（题目在上、进度在下）。
- **P3-2** 动画目录个别条目文案重复/截断（a11y 文本形如「…：从底往上，一层层层价值：从底往上，一层…搭」）。
- **P3-3** 闯关页 `重做本关` 后本轮小结清零，但题目的上次选择仍高亮（可能误按旧选择直接提交）。
- **P3-4** 启动后 `data/students/` 同时出现 `student_001` 与 `student_002`（同一秒创建，原因未查明）。

- **P3-6** 动画舞台内换行出现孤字（如「如果检索材料质量/差」）。

## 结论

主链路（配置 → 流式对话 → 动画 → 编程实跑 → 闯关闭环 → 学习记录 → 图谱 → 教师视角重建索引）**在便携版上全部跑通**；
发现的问题集中在两类：**便携形态的数据持久性**（P0-1，最要紧）与**学生面文案/状态兜底**
（原始报错、英文占位、Markdown 原文、内部 id 泄漏、空态漏字）。修复后这些条目可提升为
`docs/report-material/pitfalls.md` 的正式 P-xxx 条目。
