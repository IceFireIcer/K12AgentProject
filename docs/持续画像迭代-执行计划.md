# 持续画像迭代（Adaptive Profile Loop）· 执行计划

> 目标：把画像从「冷启动一次性概括」升级为**持续在跑的自适应回路** ——
> 每 N 轮对话把「用户输入 + 助手输出」交给 subagent 概括，产出新标签 / 修正旧标签，
> 且**永不覆盖学生亲口说过的话**。
>
> 状态：**待评审**（2026-09-30）。用户三项裁决：
> ① 触发节奏 = **每 N 轮自动跑**；② 写入策略 = **分档（自述不覆盖，其余可更新）**；③ 交付 = **先出计划**。

## 一、你的诉求 → 机制拆解

### 1.1 你要的原话，拆成四件事

> 「根据用户输入的对话和你输出的文本，保留下来，然后比如说五轮或者十轮对话，再扔给 subagent，
>   我们持续要对这个画像进行精细化调整和补充」

拆成：

| # | 要素 | 我的理解 |
|---|---|---|
| ① | **保留对话** | 滚动窗口。不是「记住每一句」，而是「最近 N 轮的 (用户说, 我答) 这两条文本」 |
| ② | **每 N 轮触发** | N=5 或 10（做成常量，可调）。攒满就触发一次概括 |
| ③ | **扔给 subagent** | 让 subagent 看真实对话（不是只看答案），提炼画像信息 |
| ④ | **精细化调整与补充** | 不只是「加新标签」，**还要能改旧的** —— 但改有档位纪律 |

### 1.2 ⚠️ 一个必须先讲清的边界

**「精细化调整」≠「让模型推断性格心理」**。这条线我们在上一轮已经确认过，本轮**不移动**：

- subagent **只能**把「学生自己说过 / 表现出来过的东西」**归位到白名单 25 个键**上；
- 它**不能**推断性格、心理状态、家庭情况、智能水平（概括 prompt 第 7~8 条，本轮保留）；
- `inferred` 来源的键**仍然只限**情绪/风格类白名单键（禁做清单 #10）。

「精细化」在这里的含义是：
- 更**准**（「喜欢例子」→「喜欢生活中的例子，但排斥纯公式推导」）
- 更**全**（覆盖到之前没填的维度）
- 更**新**（偏好变了能跟得上）

**而不是**「更深入地分析这个孩子是个什么样的人」。

## 二、机制设计

### 2.1 整体数据流

```
学生第 N 轮提问 ──► 主 Agent 正常作答 ──► agent_end 钩子（已存在）
                                              │
                                              ├─ ① 写学习记录（既有）
                                              └─ ② 【新增】累计轮次 + 把本轮 (用户说/我答) 存进环形缓冲
                                                     │
                                        轮次数 % N === 0 ?
                                                     │ 否 → 什么都不做（零额外开销）
                                                     │ 是 ↓
                                        【新增】把「画像 + 最近 N 轮对话」交给 subagent
                                                     │
                                        subagent 回 [{key, value, confidence, action}]
                                                     │
                                        【新增】分档写入策略（见 2.3）
                                                     │
                                        upsert_tag（既有守卫：白名单/闸/取值域/推断限键）
                                                     │
                                        profile_tag_history 自动记一笔（既有，零改动）
```

### 2.2 触发机制（「每 N 轮」怎么算）

**问题**：轮次必须**跨会话、跨重启单调**，否则「每 5 轮」会因重启而错乱。

**方案**：复用 `grade_signals` 的 `id`（AUTOINCREMENT，全局单调、跨会话连续）——
这正是 `profile_tags.turn_mark` 当初的做法（见附录 B.3 的裁决）。**不新建计数器表**。

```ts
// 落点：main/agent/profile-refresh/turn-clock.ts
/** 本轮会话内的轮次序号（从 1 开始）。 */
export function noteTurn(sessionId: string): number
/** 是否到了该概括的轮次（turn % N === 0）。 */
export function shouldRefresh(turn: number): boolean
export const PROFILE_REFRESH_EVERY_TURNS = 5   // ★ 常量，可调 5 / 10
```

⚠️ **为什么用「本地计数 + 后端 id 校准」双保险**：
- 本地计数快、零 IO，应付正常的连续对话；
- 但它**跨重启会丢**。所以启动时用后端 `grade_signals` 的 `max(id)` 校准一次，
  保证「重启后不会因为计数归零而提前触发」。

### 2.3 写入策略（分档 —— 这是本次的核心纪律）

用户裁决：「**自述不覆盖，其余可更新**」。落到代码上是一张**优先级 + 可覆盖**矩阵：

| 现有标签来源 | 新标签来源 | 处理 | 理由 |
|---|---|---|---|
| `declared`（学生说的） | 任意 | **绝不覆盖** | 学生亲口说的就是真相，推测不得推翻 |
| `observed`（系统量的） | `observed` | 可更新（值变了才写） | 掌握度本来就是动态的 |
| `observed` | `inferred` | **不覆盖** | 量到的 > 猜的 |
| `inferred` | `observed` | **可覆盖**（升级） | 观察坐实了猜测 |
| `inferred` | `inferred` | 可更新（置信度更高才写） | 猜测可以被更好的猜测取代 |
| （无） | 任意 | 新增 | 补充 |

**实现落点**：后端 `store/learning.py` 加一个 `upsert_tag_from_summary()`，
**不修改既有 `upsert_tag`**（它有 6 处调用点，改它风险外溢）：

```python
# 新增，不动既有 upsert_tag
def upsert_tag_from_summary(self, student_id, key, value, *, source, confidence, reason) -> bool:
    """带**来源分档**的写入（持续画像迭代专用入口）。

    ★ 与 upsert_tag 的关系：本函数**内部仍调 upsert_tag**（白名单/闸/取值域照过），
      只是在调用前多一道「该不该覆盖」的判断。
    ★ 为什么不在 upsert_tag 里加这个判断：它有 6 个调用点，其中「人工纠错」
      （PUT /tags/{key}）的语义就是「学生明确要求改」—— 那是唯一**允许**覆盖 declared 的路径。
      把分档写进 upsert_tag 会把纠错也挡掉，那是功能倒退。
    """
```

⚠️ **`declared` 保护必须写在最前面并单独测试** —— 这是整条回路的安全底线。

### 2.3.1 来源怎么选（一期实现时浮现的关键裁决，2026-09-30）

一期写 `test_profile_tags.py` 的断言时发现一个**必须现在定死**的口径：概括产出到底
标 `observed` 还是 `inferred`？

**裁决：按证据的性质选，不按"是模型产出的"选。**

| 证据 | 来源 | 能写哪些键 |
|---|---|---|
| 学生在对话里**自己表达过**（原话里说他喜欢什么、想怎么学） | `observed` | **全 25 键白名单** |
| 模型**间接推导**（从他的行为模式猜一个偏好） | `inferred` | 只限情绪/风格 8 键（禁做 #10） |

★★ **为什么 `observed` 不是"系统量到的"专属**：`observed` 的语义是
「**观察到的事实**」，而"学生在对话里说了什么"就是一个可观察的事实 ——
与判分结果、元认知信号同属一类（都是"他表现出来过的东西"）。它与 `inferred`
的真正分界是：**这句话是不是他自己说的**。

- 「学生说：我就喜欢用太空的例子」→ `interest_topic=太空`，**observed**（他说的）；
- 「模型发现他每次讲太空都很来劲，于是猜他喜欢太空」→ 同一条，**inferred**（猜的）。

★ **为什么这条口径不能含糊**：`inferred` 受禁做 #10 限制，只能写 8 个键。
如果概括一律标 `inferred`，那它能写的就只有节奏/风格/情绪 —— 「兴趣」
「场景」「目标」「互动偏好」这些维度**永远填不上**，整个持续迭代的意义就没了。
反过来，如果为了填满维度就把 `inferred` 的限键放开，那是**移动安全边界**，
本项目的红线之一。所以唯一的正解是**在 prompt 里教模型分辨证据性质**，
并在二期让它据此选 `source`。

⚠️ 二期由此多一条 prompt 纪律（加进 §2.6）：
> 每条标签都要判断：这是学生**自己说过的**（source=observed），
> 还是你**从他行为里推出来的**（source=inferred）？后者只允许写
> 讲法/长度/节奏/练习/情绪/强度/起因/把握程度这 8 类。

⚠️ `declared` **绝不由概括产出**：那是"学生自述"的专属来源，只能来自五问那条
真实路径。契约层已硬挡（`RefreshApplyTag._no_declared` → 422）。

### 2.4 概括载荷（给 subagent 看什么）

**现状**：`buildSummaryPayload` 只发「五问的问 + 答」。

**新增**：`buildRefreshPayload`（**新函数，不动老的**，两者用途不同）：

```
system: 你是学生画像的整理助手。（与五问版同一套纪律，见 §2.6）
        输入是这位学生最近几轮的真实对话（已脱敏），以及他现在的画像。
        任务：把对话里**学生自己表达过的**偏好/兴趣/困扰，整理成画像标签。
        ★ 只输出「对话里有依据」的条目；没依据的一律不要。

user:   现在的画像：（key=value; …）
        最近 5 轮对话：
        [轮 1]
          学生：<已脱敏文本>
          助手：<助手文本>
        [轮 2]
          …
```

**三个必须做对的细节**：

1. **脱敏**：学生文本必须过 `sanitizeStudentText`（既有）；助手文本也过一次
   （助手可能复述了学生的话，比如「你刚才说你住在……」，漏了就是侧漏）。
2. **截断**：每条消息截到 `REFRESH_MSG_MAX_CHARS`（建议 500），
   否则 10 轮对话能把 token 预算吃光。**助手消息尤其长**。
3. **助手消息的定位**：助手输出**不是**画像证据的来源，它是**上下文** ——
   用来判断「学生那句话是在回应什么」。所以 prompt 要明说：
   「助手的话只帮你理解上下文，**不要把助手说的话当成学生的偏好**」。

### 2.5 产出与去重

subagent 回 `[{key, value, confidence}]`，与现有 `parseSummaryTags` **同一套宽松读 + 严格校验**：
- key 不在白名单 → 丢
- value 空 / 超长 → 丢
- 同 key 重复 → 留第一条

**新增两条**（相对五问版）：
- **`declared` 键提前剔除**：载荷里就告诉模型「这几个键已经有了，别碰」，
  同时在解析侧再挡一次（纵深防御，与既有风格一致）。
- **单次产出上限**：建议 `REFRESH_MAX_TAGS = 4`（比五问的 12 小得多）——
  持续迭代是**小步修正**，一次改 4 条以上说明模型在编。

### 2.6 纪律（不可移动的边界）

概括 prompt 必须包含且**保留**这几条（与 `summarize-llm.ts` 第 7~8 条一致）：

```
- 不要推断学生的性格、心理状态、家庭情况或智能水平；
- 不要输出真名、学校、班级、手机号、身份证号；
- 不要把助手说的话当成学生的偏好（助手的话只是上下文）；
- 宁可少写，不要为凑数而编。
```

**并且每次概括都要过既有的 14 条禁做守卫**（`onboarding-guards.test.ts` 的 G-H-13/14 扫源码）。

   `settings/runtime-config.ts`：既避免新增模块边，也保证用的是**热切换后真正生效**的配置。

**三期新增的四条实现裁决**：

1. **origin 与 source 正交，不合并**：`source`（declared/observed/inferred）说「多可信」，
   `origin`（cold_start/refresh/projection）说「从哪条路来的」。**加 origin 的充分理由只有一条**：
   `observed` 同时来自行为投影（`sync_observed_tags`）与持续迭代概括（`refresh-apply`），
   `source` 分不开这两者，而它们是两个不同的故事。
2. **旧行回填只做唯一可确定的映射**：`declared→cold_start`（五问是唯一写 declared 的路）、
   `inferred→refresh`（只有概括写 inferred）；**`observed` 留 NULL**（投影与概括都可能，
   猜不了就不猜 —— 延续 v6「历史无法追溯」的同一条纪律，不替过去编造）。
   读取侧把 NULL 折成一句中性中文「系统调整的」，**不编第四个枚举值**。
3. **出处只在后端折成中文**：`_TAG_ORIGIN_NOTES` 把三态 + 空串各折成一句现成中文进 `detail`；
   渲染层只拿 `origin` 驱动 `data-origin`（配色/图标），**一个枚举字面量都不写**
   （否则给 `student-view-discipline` 守卫开洞）。
4. **N 值保持 5，不调到 10**（裁决记录）：
   - 调大到 10 的**收益**：LLM 调用量**减半**（长对话成本线性下降）；
   - 调大到 10 的**代价**：画像在「学生刚表达完一个新偏好」后最多要再等 10 轮才更新 ——
     而一节课通常也就 10~20 轮，这意味着**一节课可能一次都不更新**，持续迭代退化成
     「下节课才生效」。对一个「持续精细化」的机制，这是**方向性错误**。
   - 省调用的正解不是调大 N，而是**已经做了的**那两件事：实质内容门槛（2 字）+ 差值语义。
   - 故 N 保持 5（常量在 `turn-clock.ts`，真要调也只改一个数）。

## 五、风险与守卫

### 5.1 五个真实风险

| # | 风险 | 后果 | 缓解 |
|---|---|---|---|
| 1 | **覆盖了学生自述** | 学生说的被猜测推翻，画像开始撒谎 | 分档矩阵 + 专门断言（G-M-1） |
| 2 | **助手文本侧漏**（助手复述了 PII） | 真名/住址进画像 | 助手文本也过 `sanitizeStudentText`（G-M-4） |
| 3 | **概括变「心理分析」** | 回退到我们拒绝过的那条线 | prompt 纪律 + 既有 G-H-13/14 扫源码 |
| 4 | **调用量失控** | 每 5 轮一次 LLM，长对话成本可观 | N 可调 + 只在「有实质新内容」时触发（见下） |
| 5 | **`runtime.ts` 改动引发回归** | 编排水线是最脆弱的地方 | 改动极小（一行 `void`）+ 全量测试 |

**关于风险 4 的一个优化**（建议做，成本低）：
**轮次只是必要条件，不是充分条件**。加一道「本轮有没有实质内容」的判断：
- 如果最近 N 轮全是「嗯」「好的」这类无内容的话 → 跳过本次概括，计数器顺延。
- 实现：`transcript-window` 记录每轮的学生文本长度/是否有实质词，`shouldRefresh` 里一并判断。

⚠️ **门槛取 2 字，不是 3**（一期实测修正，2026-09-30）：
  「不会」「不懂」「太快」这些**两字回答是真实的学习信号**（学生卡住了）——
  恰恰是最该记进画像的一类。门槛设 3 会把它们静默丢掉，那是把最有价值的信号
  过滤掉的错误优化。1 又太低（「嗯」「哦」全是单字）。所以正好取 2。

⚠️ **触发语义用「距上次概括的轮次差 ≥ N」而不是 `turn % N === 0`**（一期实现）：
  `% N` 在「某几次被实质内容门槛挡下」时会**一路错过触发点**（第 5 轮被挡→等第 10 轮，
  第 10 轮再被挡→等第 15 轮）。差值语义则「攒够 N 轮且窗口里有内容」就触发，不会漏。

### 5.2 必须写红的守卫（G-M 系列）

| 断言 | 内容 |
|---|---|
| **G-M-1** | `declared` 的标签**永不被** summary 写入覆盖（构造一个 declared，喂一个不同值的 summary，断言值不变） |
| **G-M-2** | `observed` 不会被 `inferred` 覆盖 |
| **G-M-3** | `inferred` 可被 `observed` 升级 |
| **G-M-4** | 助手文本里的 PII 经 `buildRefreshPayload` 后被脱敏（构造「你住XX路」的助手消息） |
| **G-M-5** | `buildRefreshPayload` 载荷里**不含** `displayName` |
| **G-M-6** | 轮次计数跨重启后不归零（用假的后端 `max(id)` 校准断言） |
| **G-M-7** | 概括 prompt 仍禁推断心理（扫源码文本） |
| **G-M-8** | `REFRESH_MAX_TAGS` 超出时只取前 N 条，且**不**静默补位 |

### 5.3 不该改的东西（防止「顺手」毁掉既有设计）

- ❌ **不改** `upsert_tag`（6 个调用点，语义各不同）
- ❌ **不改** `learning_history` 表（它是学习记录，**有意不存对话正文**，见 `extensions/profile.ts` 文件头）
- ❌ **不新建对话存储表**（Pi 会话文件已经是唯一真相，再存一份会漂）
- ❌ **不改** `EPHEMERAL_TTL_TURNS`（短期情绪 TTL 是禁做 #11 的实现）
- ❌ **不动** 五问的 `buildSummaryPayload`（用途不同，两条 prompt 别混）
