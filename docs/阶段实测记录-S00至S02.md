### 2.3 踩坑（已归档为 P-006 / P-007 / P-008）

1. **★ 打包后中文按 GBK 输出**（最有价值的坑）：PyInstaller bootloader 设置
   `Py_IgnoreEnvironmentFlag`，`PYTHONUTF8`/`PYTHONIOENCODING` **被完全忽略**
   （实测 `utf8_mode=0`、`encoding='gbk'`）。**必须在 Python 层 `reconfigure(encoding="utf-8")`**。
   → **修正了执行文档风险表 #3 的原始表述**（原文只写「spawn 时传 env」，实测不够）。
2. **重打包 `WinError 5`**：残留 sidecar 进程占用产物 `.pyd`/`.dll`，删不掉 → 打包脚本自动 taskkill 自愈。
3. **`collect_all` 返回值必须喂给 `Analysis`**，不能事后 `a.datas +=`（元组长度不一致会崩）。
4. **Node stdio 分片**把握手 JSON 切半 → `LineBuffer` 按 `\n` 缓冲。
5. `@quick-start/create-electron` 的交互式提示在无 TTY 下不可用 → 改为直接从 npm 包提取官方模板。

### 2.4 本 Stage 的方法论收获（**报告可用**）

1. **把「进程管理」这块最难测的逻辑抽成纯函数并写测试**（`sidecar-logic.ts`）：
   不依赖 Electron 即可验证，回归成本从「起一次应用」降到毫秒级。
2. **UI 验收改用 CDP 读真实 DOM 而非截图**：本机截图受前台窗口/DPI 影响，截到的常是别的窗口；
   DOM 断言是确定性的、可进 CI 的。并支持 `--expect failed` 断言「失败态不白屏」。
3. **确认文档结论需经实测校验**：风险表 #3 的表述就是这么被修正的。

## 3. S02 · 契约冻结 + 设置页 + 安全握手 + 事件通道（D2，已完成）

### 3.1 契约模型数量

`CONTRACT_MODELS` 显式登记**全部对外模型 + 枚举**：4 个枚举（`GradeLevel`/`Intent`/…）、
`LlmConfig`/`EmbeddingConfig`、`SettingsUpdateRequest`、Chat/Quiz/Code 请求响应、6 个 SSE `Sse*Data`。

> **★ 必须显式登记的原因（实现要点，别再踩）**：FastAPI 只把**路由可达**的模型放进
> `components.schemas`，而 SSE 的 `payload`/`citation` 载荷**不走 `response_model`**，天然不在 schema 里。
> 靠 `models_json_schema()`（BaseModel）与 `TypeAdapter(...).json_schema()`（枚举）合并注入。
>
> ⚠️ v2 变更：`Intent` 枚举已删除（路由改为 LLM 选 Tool）。

### 3.2 codegen 踩坑（3 个）

1. `openapi-typescript` 的 `node_modules/.bin` 是 **shell 包装脚本**，用 `node` 执行报
   `Invalid or unexpected token` → 改走**编程式 API**（`openapiTS` + `astToString`）。
2. `models_json_schema()` 的定义在 **`$defs`** 下，不是顶层。
3. 该函数**只接受 BaseModel**，传枚举报 `has no attribute '__pydantic_core_schema__'`
   → 拆成 models / enums 分别生成。

最终 `export_openapi.py --check` 能做**字节级比对**（paths 与 components 均排序，输出稳定）。

### 3.3 ★ 四个真 bug（**全部由端到端验收暴露，报告第 7 章的核心素材**）

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 无 token / 错 token 时前端看到 `TypeError: Failed to fetch` 而不是 401 | **Starlette 中间件是洋葱结构**，最后 `add_middleware` 的在最外层。CORS 加在鉴权内层 → 鉴权提前 return 的 401 **不带** `Access-Control-Allow-Origin`，浏览器把 401 **伪装成网络错误** | **CORS 必须最后 add**；补两条回归测试（401 带 CORS 头） |
| 2 | 日志模块抛 `TypeError: not all arguments converted during string formatting` | 脱敏过滤器改写 `record.msg`，把 `%s` 占位符擦成 `***`，`record.getMessage()` 的 `msg % args` 就崩了 | 保留 `%s`/`%(name)s`/`%d`（`_PLACEHOLDER_RE`）；补 6 条格式安全测试 |
| 3 | 最有用的鉴权日志被抹成 `Authorization: *** ***` | 脱敏把值位置的 `Bearer` 也当凭据擦了 | 加非凭据词白名单（`bearer`/`basic`/`token`/…） |
| 4 | 架构守卫的「禁止绕过统一客户端」正则**永远匹配不到** | `stripComments()` 顺手把模板字符串也抹掉了（`${base}/api/...` 变 `` ）→ 守卫形同虚设 | 修正正则；**修好后立刻抓出一处真实违规**（`Dashboard.vue` 手写 `fetch`） |

> **这四个坑的共同点**：都不是「写错了代码」，而是**只有在真实端到端运行时才暴露**
> （中间件顺序、日志惰性格式化、浏览器错误语义、测试自身的有效性）。
> **报告用法**：说明「为什么坚持端到端验收而不是只跑单测」。

### 3.4 验收证据

- **后端** HTTP 集成测试：真 uvicorn + 真 socket，**39 项断言**（401 / OPTIONS 预检 / 往返 / SSE 全事件）
- **前端** 单测 **71 项**（含架构守卫：禁 `EventSource`、契约漂移、Electron 侧风险隔离）
- **API Key 不入日志经真机验证**：27 行日志、**0 次**出现 key 与 token、`***` 存在
- **架构守卫的有效性经变异测试证明**：植入 `EventSource`、去掉 `stream: true`、篡改生成物、
  回退 `restart()` —— **全部被捕获**
  > 这一条很重要：**守卫自己也要被验证**，否则就是第 4 号 bug 那样的摆设。
