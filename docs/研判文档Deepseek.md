# 多模态 K12 人工智能通识课教学助手对话智能体
## 项目研判报告

**项目编号**：JBGS-2026-02  
**发榜单位**：中国移动通信集团浙江有限公司  
**报告性质**：基于五十三轮技术研讨的项目研判报告  
**日期**：2026年9月14日


## 一、项目概述

本项目旨在基于大语言模型，构建一个面向 K12 阶段（小学至高中）人工智能通识课程的对话智能体，为学生提供交互式、多模态、个性化的在线学习体验，充当“7×24 小时在线 AI 教师”。智能体需具备学段自适应能力，支持多模态内容生成与交互，通过对话、动画、编程实践、游戏化练习等形式辅助学生学习编程与人工智能知识，并形成个性化学习闭环。

经过五十三轮技术研讨，项目组已就总体架构、技术选型、模块划分、接口契约等关键问题达成共识。本报告对这些共识进行系统梳理，形成完整的项目研判结论。

- **部署形态**：Electron 全本地化单应用，前后端统一打包，暂不考虑服务器部署。

## 三、总体技术方案

### 3.1 架构风格

采用 **“Electron 全本地化 + LangGraph 多智能体协作 + SQLite 嵌入式 RAG”** 的总体架构。

- **前端**：Vue 3 + Pinia，对话优先布局，内联卡片 + 展开/全屏切换。
- **后端**：Node.js 主进程内运行 LangGraph，主 Agent 与 SubAgent 作为独立模块共存。
- **数据层**：SQLite + sqlite-vec 实现向量检索与知识图谱存储，每个学生独立数据库文件。
- **多模态**：sandboxed iframe 运行 Anime.js 动画，独立 Web Worker 运行 Pyodide 编程环境。
- **语音**：本地 ONNX 模型，sherpa-onnx 提供 ASR 与 TTS，纯 CPU 推理。

### 3.2 核心设计原则

1. **学段由前端按钮切换**，主 Agent 在路由时注入学段参数，SubAgent 不自行推断。
2. **主 Agent 负责路由和对话答疑**，SubAgent 按功能维度划分（动画、编程、练习）。
3. **所有跨模块调用经过统一 TypeScript 接口契约**，模块间通过事件总线异步通信。
4. **知识库检索严格按学段隔离，允许向上兼容但明确标注**。
5. **内容安全只做后端审核，采用流式输出 + 最终审核策略**。
6. **知识点依赖图同时服务于推荐路径规划和检索上下文扩展**。

## 五、核心模块设计

### 5.1 对话问答

- **交互形式**：对话优先布局，主界面为大对话区域，功能以卡片形式内联，支持展开/全屏。
- **流式输出**：DeepSeek API 逐 token 推送，前端实时显示。
- **内容安全**：流式输出 + 最终审核，生成结束后整段送审，违规则撤回并替换为安全提示。
- **学段适配**：主 Agent 根据学段注入不同的 System Prompt，调整语言风格和知识深度。

### 5.2 动画讲解

- **执行环境**：主线程 sandboxed iframe，通过 `sandbox` 属性限制权限。
- **动画库**：Anime.js（MIT 协议，可商用），操作 DOM/SVG。
- **生成策略**：大模型一次性生成完整 HTML 代码，System Prompt 内置少量高质量示例。
- **容错策略**：Worker 捕获错误后自动重试 3 次，仍失败则降级为文字 + 静态图讲解。
- **通信协议**：完整 RPC 式协议，支持播放、暂停、重播、进度回调、超时取消。

### 5.3 编程环境

- **编辑器**：Monaco Editor（VS Code 同款，功能完整）。
- **运行环境**：Pyodide（浏览器内 WebAssembly），单独开 Web Worker 与动画沙箱隔离。
- **预置包**：numpy、matplotlib 等常用包预打包进应用，离线可用。
- **代码模板**：按知识点类型预置不同模板（排序算法、神经网络、决策树等）。
- **求助机制**：自动感知报错 + 手动求助按钮结合，学生连续失败 N 次后主 Agent 主动介入。

### 5.4 游戏化练习

- **题目来源**：预置题库 + 大模型变式生成。
- **题型**：选择题、填空题 + 交互式题型（拖拽排序、连线匹配、代码填空）。
- **批改策略**：混合方案——客观题用专门逻辑批改，主观题由大模型辅助判断。
- **反馈机制**：自动批改，即时反馈，记录知识点掌握度变化。


## 六、知识库与 RAG 方案

### 6.1 知识库构建

- **教材格式**：Markdown 正文 + 配套元数据文件（声明学段、章节、知识点标签、依赖关系）。
- **分块策略**：按教材结构分块（章→节→段落三级），节级 chunk 控制在 300-600 token。
- **元数据 Schema**：`chunk_id`、`text`、`embedding`、`grade_level`、`chapter_title`、`section_title`、`knowledge_point`、`content_type`、`parent_chunk_id`、`token_count`。
- **父子 chunk 机制**：小子 chunk 做 embedding 检索，命中后返回父 chunk 作为生成上下文。

### 6.2 向量存储与检索

- **向量数据库**：SQLite + sqlite-vec（嵌入式，零依赖，纯 C 实现）。
- **嵌入模型**：BGE-M3（本地，通过 Ollama 拉取，中文效果好）。
- **检索流程**：学生查询 → 主 Agent 路由确定学段 → BGE-M3 生成查询向量 → sqlite-vec KNN 查询（WHERE 约束学段）→ 命中子 chunk → 通过 `parent_chunk_id` 获取完整节内容 → 注入 LLM 上下文。
- **学段策略**：严格隔离 + 允许向上兼容，兼容内容明确标注。

### 6.3 知识点依赖图

- **存储方式**：邻接表 + 内存缓存 + 递归 CTE 查询。
- **表结构**：`knowledge_dependencies (from_kp_id, to_kp_id, relation, weight)`。
- **用途**：
  - **推荐路径规划**：学生掌握“变量”后，根据依赖图推荐“循环”作为下一步。
  - **检索上下文扩展**：学生问“循环”时，自动将“变量”相关内容纳入检索范围。
- **循环检测**：教材元数据导入阶段用 DFS 遍历检测环，防止误标。


## 七、多模态交互实现方案

### 7.1 四种核心交互方式

| 交互方式   | 技术方案                               | 状态 |
| ---------- | -------------------------------------- | ---- |
| 对话问答   | DeepSeek 流式输出 + 后端审核           | 核心 |
| 动画讲解   | sandboxed iframe + Anime.js + RPC 协议 | 核心 |
| 编程环境   | Monaco Editor + Pyodide Worker         | 核心 |
| 游戏化练习 | 预置题库 + 变式生成 + 混合批改         | 核心 |

> 绘本生成与多模态教学资源推荐暂不纳入核心范围，聚焦现有四种做深做透。

### 7.2 语音交互

| 模块     | 选型                      | 大小 | 协议       | 运行方式         |
| -------- | ------------------------- | ---- | ---------- | ---------------- |
| ASR      | sherpa-zipformer-zh-14m   | 25MB | Apache 2.0 | ONNX Runtime CPU |
| TTS      | Piper zh_CN-huayan-medium | 63MB | MIT        | ONNX Runtime CPU |
| 触发方式 | 按键说话                  | —    | —          | —                |

- **集成路径**：sherpa-onnx 官方 Node.js 绑定，ASR 与 TTS 共用 ONNX Runtime 实例。
- **延迟预算**：音频采集 ~100ms，ASR ~200-400ms，LLM ~1-3s，TTS ~130-500ms，端到端 ~1.5-4s。


## 八、个性化学习与学段自适应

### 8.1 学段自适应机制

- **知识库分级**：同一知识点在不同学段对应不同深度标注。
- **交互风格切换**：System Prompt 按学段差异化设计（童趣模式/逻辑模式等）。
- **内容形态路由**：低学段优先绘本、语音、动画；中学段增加文档和视频；高学段增加编程实践。

### 8.2 个性化学习闭环

- **学生画像**：记录知识掌握度、易错点、学习偏好、学习节奏。
- **推荐引擎**：学情分析 Agent 更新画像 → 教学规划 Agent 根据画像和知识图谱决定下一步推荐 → 内容生成 Agent 执行。
- **数据隔离**：每个学生独立 SQLite 数据库文件，互不影响。
- **冷启动**：新用户无历史数据时，基于学段和初始测评推荐默认路径。

### 8.3 教师/家长入口

- **实现方式**：单独做一个轻量级导出功能，生成学习报告（PDF/图片）供家长查看。
- **内容**：答题记录、知识掌握度、学习时长、推荐下一步。


## 九、安全与合规

- **内容安全**：只做后端审核，流式输出 + 最终审核，违规内容撤回并替换。
- **数据合规**：K12 场景涉及未成年人数据，遵循数据采集最小化原则，不采集生物特征。
- **本地化部署**：全本地化架构天然支持数据不出设备，符合教育数据安全要求。
- **模型接入安全**：API Key 本地存储，支持用户自填配置，不经过第三方服务器。

## 十二、风险分析与应对

| 风险                     | 影响                 | 应对措施                                         |
| ------------------------ | -------------------- | ------------------------------------------------ |
| 动画代码生成失败率高     | 学生体验差           | 内置高质量示例，自动重试 3 次，降级文字+静态图   |
| SQLite 向量检索规模瓶颈  | 知识库扩大后性能下降 | 按学段/学科分区，必要时升级到专用向量库          |

| 多学生独立数据库管理复杂 | 数据膨胀             | 定期归档，提供数据库清理工具                     |
| 内容安全审核漏判         | 合规风险             | 后端审核 + 敏感词库 + 分类模型双重过滤           |
| 并行开发集成冲突         | 返工                 | 严格 TypeScript 接口契约，定期联调               |


## 十三、创新点与优势

1. **全本地化 Electron 架构**：无需服务器，数据不出设备，符合 K12 数据合规要求。
2. **学段自适应机制**：从知识库分级、交互风格、内容形态三个维度系统设计，非简单 prompt 切换。
3. **SQLite + sqlite-vec 嵌入式 RAG**：零依赖、纯 CPU、轻量高效，适合边缘部署。
4. **知识点依赖图双用途**：同时驱动推荐路径规划和检索上下文扩展，实现真正的自适应学习闭环。
5. **动画生成容错体系**：自动重试 + 降级策略，保证学生始终有内容可看。
6. **混合批改策略**：客观题用逻辑，主观题用大模型，兼顾准确性与灵活性。
7. **纯 CPU 语音交互**：sherpa-onnx + Piper，25MB ASR + 63MB TTS，低延迟、可商用。


## 十四、结论

本项目经过五十三轮技术研讨，已形成完整、可落地的技术方案。方案以 Electron 全本地化为部署形态，以 LangGraph 多智能体为编排核心，以 SQLite + sqlite-vec 为数据底座，聚焦对话问答、动画讲解、编程环境、游戏化练习四种核心交互方式，辅以本地语音交互和学段自适应机制，构建了一个符合 K12 教育场景需求的 AI 通识课教学助手。

技术选型充分考虑了比赛要求、硬件约束、开发效率和合规安全，具备较高的可行性和创新性。建议按照接口契约先行、模块并行推进、定期集成联调的策略启动开发，确保在比赛周期内交付高质量的系统原型和项目报告。
