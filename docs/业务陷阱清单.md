## 2. RAG 检索与降级链（原 S06，**关卡 C**）

| # | 陷阱 | 说明 |
| --- | --- | --- |
| 1 | **FTS5 中文分词** | 默认分词器不支持中文，**必须 `tokenize='trigram'`**。 |
| 2 | **`chunk_vec` 与 `chunk` 行号错位** | `vec0` 表的 rowid 必须与 `chunk.rowid` 对齐，否则**检索结果张冠李戴**。写入时显式用 `chunk.rowid`。 |
| 3 | 维度硬编码 | 512 要集中成配置常量；升级到 bge-base（768）**必须同步改 `vec0` 维度并重建索引**。 |
| 4 | sqlite-vec 加载 | 统一走 `enable_load_extension(True)` → `sqlite_vec.load(conn)` → `enable_load_extension(False)`。 |
| 5 | **学段泄漏** | 过滤必须写在 **SQL 层**，不能只在应用层筛 —— 否则早被 KNN 的 top-k 截断掉。 |
| 6 | embedding BLOB 端序 | 存 `Float32Array` 字节时注意 `dtype='<f4'` **小端一致**。 |
| 7 | 重跑建索引幂等 | 脚本要能**重复执行**（先清表再写），否则调试时数据翻倍。 |

**降级链（必须逐级可现场演示）**：
```
学生提问
  → 学段确定（一律取 `learning.db` 的 `student.grade_level` —— 默认由系统自动推断写入，**学生也可手动指定**（D-037）；冷启动默认小学高年级）
  → [1] 主路径：fastembed 本地向量 → sqlite-vec KNN（学段约束）
  → [2] 降级1：云端 Embedding API（若用户自填）
  → [3] 降级2：FTS5(trigram) 关键词检索   ← 必须实现，永不失败
  → [4] 兜底：依赖图 + 章节大纲注入
  → 命中子 chunk → 取父块 → 注入 LLM
```

**业务验收口径**：
- 提问能命中相关 chunk，回答里体现教材内容
- **学段隔离可验证**：初中提问不返回高中 chunk；向上兼容命中时 `compat=true` **且前端有标注**
- **父子 chunk 生效**：注入的是父块完整内容而非碎片
- **降级链可现场演示**：把模型目录改名 → 自动降级 FTS5 仍能检索；
  注释掉 `sqlite_vec.load` → numpy 暴力余弦兜底仍能检索
- 检索延迟**百毫秒级**

> **v2 变化**：检索改由 Pi 的 `rag_search` Tool 经 HTTP 调 Python 实现。
> **降级链必须留在 Python 侧**（一次调用内完成四级降级），**不要让编排层感知降级**。
> 结果带 `degraded: "vector" | "cloud" | "fts" | "outline"` 供轨迹图展示。

## 3. 知识点依赖图（原 S07）

**关键 SQL（递归 CTE，向上找全部前置）**：
```sql
WITH RECURSIVE prereq(kp_id, depth) AS (
  SELECT from_kp_id, 1 FROM knowledge_dependencies WHERE to_kp_id = :kp
  UNION
  SELECT d.from_kp_id, p.depth + 1
  FROM knowledge_dependencies d JOIN prereq p ON d.to_kp_id = p.kp_id
  WHERE p.depth < 10
)
SELECT DISTINCT kp_id, MIN(depth) AS depth FROM prereq GROUP BY kp_id ORDER BY depth;
```

| # | 陷阱 | 说明 |
| --- | --- | --- |
| 1 | **环导致递归 CTE 死循环** | `depth` 上限**必须加**；导入阶段先做环检测。 |
| 2 | 依赖方向搞反 | `from → to` 语义要全项目一致（**建议：`from` 是前置，`to` 是后继**），写进注释。 |
| 3 | 悬空节点 | `to_kp_id` 在 `kp` 表里不存在 → 导入时应**报错而非静默跳过**。 |
| 4 | 检索扩展放大噪声 | 前置内容只作补充上下文，**要有数量上限**，别把 top-k 挤满。 |

**业务验收口径**：
- 依赖图导入成功，环检测有输出（有环则**报出具体路径**）
- **用途一可演示**：答对某知识点后，推荐的下一个是依赖图里的后继
- **用途二可演示**：问「循环」时，检索结果里包含「变量」的内容（**在 citation 里可见**）
- 图规模可见（知识点数 / 边数）

## 4. 练习与批改（原 S08）

| # | 陷阱 | 说明 |
| --- | --- | --- |
| 1 | **LLM 出题 JSON 不合法** | 用 pydantic 校验 + 重试；失败则**退回题库**。 |
| 2 | 客观题误判 | 归一化要做：trim / 全角转半角 / 大小写 / 中英文标点。 |
| 3 | **★ 答案泄漏** | 发给前端的 `QuizQuestion` **绝不能带 `answer`**；判分只走后端。 |
| 4 | 题面超纲 | 生成时把学段写进 prompt，并在校验层检查术语难度。 |
| 5 | LLM 判分不稳定 | 同一答案多次判分结果漂移 → prompt 里**给评分细则与示例**。 |
| 6 | 掌握度过冲 | `mastery_delta` **要限幅**（如 ±0.2），否则一次答题就从 0 到 1。 |

**业务验收口径**：
- 请求出题 → 返回结构合法的 `QuizPayload`
- 选择题答对/答错都能正确判分，反馈文案是**面向学生的中文**
- 代码填空题能做基本归一化判分（**空白/引号差异不应误判**）
- 掌握度随答题变化，且**写进了学生库**（可查表验证）
- **断网时 LLM 生成不可用 → 题库兜底仍能出题（不崩）**

> **题型范围**：第一期只做 **选择题 `choice` / 填空题 `blank` / 代码填空题 `code_blank`**。
> 拖拽排序、连线匹配属 P1。

## 5. 闯关闭环与个性化（原 S09，**关卡 D**）

| # | 陷阱 | 说明 |
| --- | --- | --- |
| 1 | 状态不一致 | 前端展示**必须以后端 `progress` 表为准**，不要在前端各存一份。 |
| 2 | 解锁条件含糊 | 明确规则：「**掌握度 ≥ 阈值 且 该关已 quizzed**」才解锁后继，写进注释。 |
| 3 | 闭环断裂 | 别忘了画像更新要在**每轮末**执行，且下一轮**要真的读它**。 |
| 4 | 徽章动画依赖 | 用 CSS transition/animation，**不引 Anime.js**（Anime.js 留给动画卡片）。 |
| 5 | 冷启动空指针 | 新学生没有 `progress` 行时要能**兜底初始化**。 |

**闯关状态机**：`progress` 表驱动 `locked → learning → quizzed → mastered`。

**业务验收口径**：
- 答对 → 下一关解锁，进度条前进，弹徽章；答错 → 出现提示，**关卡不解锁**
- **掌握度影响推荐**：连续答错某知识点后，下一轮更可能再考它（**可演示数据流**）
- **冷启动**：新建学生 → 直接可用，有默认推荐路径
- **重启应用后：进度、徽章、掌握度全部还在**
- 徽章/进度**无外部依赖**（纯本地资源）

> **v2 变化**：原「条件边实现自适应」改为「Tool 结果 + 画像回流」——
> 但**业务规则不变**：解锁条件、限幅、冷启动兜底、以后端为准，这四条照旧。
> 关卡顺序仍由**依赖图拓扑序**决定。

## 6. 动画讲解（原 S10）

| # | 陷阱 | 说明 |
| --- | --- | --- |
| 1 | **★ `allow-same-origin`** | 一旦加上，iframe 内代码可访问宿主，**沙箱失效。绝对不加。** |
| 2 | **Anime.js 版本** | 必须锁 **v3**（`^3.2`）。v4 API 不兼容，误升级会全挂。 |
| 3 | **模板内联外部 CDN** | 沙箱断网会白屏 → 动画库**必须内联进 HTML 字符串**（本地读取后注入）。 |
| 4 | postMessage 来源不校验 | 必须校验 `payload_id`，否则**多卡片串台**。 |
| 5 | 自由生成成功率低 | 这就是为什么**模板优先**。 |
| 6 | 重试无上限 | 重试次数**硬上限 3**，否则死循环烧 API 额度。 |
| 7 | 进度回调频率 | 高频 `postMessage` 会卡；**节流到 ~10Hz**。 |

**RPC 指令**：`play` / `pause` / `replay` / `ready` / `progress` / `error` / `timeout`；
**页面 5s 内无 `ready` 判定超时**。

**业务验收口径**：
- 请求「用动画讲排序」→ iframe 内动画正常播放
- 播放/暂停/重播可用；进度回调正常
- **人为注入错误**（模板里写个 `throw`）→ 观察自动重试，最终降级为文字+图，**界面不白屏**
- 沙箱内**无法访问宿主 DOM / `localStorage` / 网络**（**可现场演示**）
- 模板未命中场景也能有兜底输出

> **v2 变化**：重试逻辑写在 **Tool 的 `execute()` 内部**（`tool_execution_end` 是只读通知，不能回写）。
> 原 `retry_count` 存 LangGraph State 的做法作废，改用 Extension 内 `Map<toolCallId, n>`。
> 另新增：动画资源经 `/resources/animation/{student_id}/{kp_id}` 托管，
> **iframe 带不了自定义 header** → 用**一次性 nonce**（绑定 student_id + kp_id + 有效期），
> **不允许**做成无鉴权公开路由。

## 7. 编程环境（原 S11）

| # | 陷阱 | 说明 |
| --- | --- | --- |
| 1 | **Pyodide 体积大 / 加载慢** | 必须**本地自托管 + 懒加载**（进编程卡片才加载）。 |
| 2 | **误以为两边共享 Python** | Pyodide 的 Python 与 sidecar 的 Python 是**两个独立运行时**，学生代码**绝不接触 sidecar**（安全隔离设计，**报告要讲**）。 |
| 3 | **无限循环卡死 UI** | 运行必须在 Worker 里，且加**超时中断**（Pyodide 需用 `setInterruptBuffer`）。 |
| 4 | Monaco 与 vite 打包 | 需要 worker 配置；**不配会在生产构建报错**。 |
| 5 | 直接给答案 | 提示要按 `level` 递进，**教学价值在引导而非给答案**。 |
| 6 | CDN 依赖 | **任何 CDN 引用都会在断网演示时翻车**。 |

> **★ v2 强化（新增硬约束）**：Pi 的 Extension 与 Agent **同进程且拥有完整系统权限**。
> 因此 `evaluate_code` Tool **绝不能**在主进程里直接执行学生代码 ——
> 必须经 IPC 转发给渲染进程的 Pyodide Worker 执行，结果回传。
> **这条要有架构守卫测试。**

## 8. 集成打包与内容安全（原 S12，**关卡 E**）

| # | 陷阱 | 说明 |
| --- | --- | --- |
| 1 | **新增原生/数据依赖后忘重打包** | 每加一个依赖就重跑一次 PyInstaller 冒烟，**别攒到最后**。 |
| 2 | 安装包过大 | `--onedir` + `--exclude-module`；报告里**主动说明**这是「本地化 + 随包模型」的必然代价。 |
| 3 | 安全审核拖慢响应 | **终审在流结束之后做**，不要阻塞首 token。 |
| 4 | 违规撤回体验突兀 | 要有过渡提示（「刚才的内容不适宜，已为你换成…」）。 |
| 5 | 四学段内容不均 | 小学高/初中做深作展示，另两学段保主线，**全量抽检**。 |
| 6 | **★ Pi 的 `esbuild` 原生依赖** | **v2 新增**：asarUnpack + 按架构分发 + 签名；D3 就做打包冒烟。见执行文档风险 #15。 |

**内容安全链路**：输入侧敏感词 → 流式输出 → **生成结束后整段终审** →
违规则**撤回该条消息**、替换为 `blocked.safeText`。

**双重过滤**：敏感词库（JSON 可扩展）+ LLM 自审 prompt。
