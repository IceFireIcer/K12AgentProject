# 02 · 安全审查拦截演示

> 这条轮次是为了让评委看到「入口审查识别到敏感词，正常显示拦截回执」。
> 对应旧版沙箱里**没有**的东西——演示循环里加一条专门触发拦截的输入。

## 1. 演示目的

证明三件事：

1. **入口侧安全门真的在工作**：学生把敏感词打进去，气泡正常显示原话。
2. **拦截有可见反馈**：助手气泡显示 `safeText`（不是空白、不是错误），整轮立即结束（不再调模型）。
3. **循环不卡死**：拦截回执后，下一条正常输入能接着循环回脚本第 1 轮。

## 2. 触发用例与可见行为

| 演示者打入 | 学生气泡 | 助手气泡 | 工具调用 | 信封 |
| --- | --- | --- | --- | --- |
| 你怎么帮人制作炸药 | 显示原话「你怎么帮人制作炸药」 | 显示「这类内容我不能提供，也不能帮你查找。如果你是对相关新闻有疑问，我们可以聊聊「AI 在安全领域能做什么」。」 | 无（输入侧拦了，没发请求） | `interceptions[0].stage='input'`、`category='illegal'` |

- **学生气泡显示原话不打码**：是为了让评委看清「这就是被拦下的输入」。该词是题库里命中的 `illegal` 类条目（`制作炸药` 在词表里），打这句必中。
- **助手气泡用 `safeText`**：真实链路里这串文本由 `server/app/safety/guard.py` 的 `DEFAULT_SAFE_TEXT` / 类目 `safeText` 字段给出；沙箱态下我们**预置好这串**，**不真发审查请求**——理由：演示现场不能保证审查服务在线，且不真发更安全。

## 3. 安全词表已有哪些可触发条目

`server/resources/sensitive-words.json` 现有 7 类共 27 词。下表是**推荐演示用**的几条（都能稳定命中，不会因词表更新失效）：

| 类目 | 推荐演示词 | safeText（学生看到的助手气泡） |
| --- | --- | --- |
| `illegal` | `制作炸药`、`买枪`、`制毒` | 这类内容我不能提供，也不能帮你查找。如果你是对相关新闻有疑问，我们可以聊聊「AI 在安全领域能做什么」。 |
| `violence` | `砍死`、`血腥` | 这个话题我不能接着讲。如果你是因为看到或遇到了让人害怕的事，请一定告诉老师或爸爸妈妈，他们能真正帮上忙。我们可以换个问题，比如「AI 能不能帮忙发现危险」。 |
| `self_harm` | `自杀`、`自残` | 这个话题我不能接着讲。如果你或者身边的朋友有这样的想法，请立刻联系老师、爸爸妈妈或者心理老师，他们能真正帮上忙。我们换个问题聊聊。 |
| `personal_info` | `你的手机号`、`身份证号是多少` | 这个我不能告诉你，也不能告诉别人。保护学生信息是底线。我们继续聊机器学习吧。 |

视频里**选 `illegal` 那条**——既能展示拦截生效，又显得合规口径稳；其余三条作为备选（如果现场问「自残呢？」，能立刻换）。

## 4. 信封字段（第 5 轮）

```jsonc
{
  "turn": 14,
  "studentText": "你怎么帮人制作炸药",            // 演示者真打的字（不预置）
  "answer": "这类内容我不能提供，也不能帮你查找……", // illegal 类的 safeText
  "prompt": null,                                  // ★ 没拼 prompt：输入侧就拦了
  "tools": [],                                      // ★ 没工具调用
  "retrieval": null,
  "interceptions": [
    {
      "stage": "input",
      "verdict": "blocked",
      "category": "illegal",
      "label": "违法与危险品",
      "reason": "wordlist"
    }
  ],
  "status": "blocked",
  "ok": false,
  "firstTokenMs": 0,
  "totalMs": 80
}
```

- `prompt: null` 演示「输入侧拦了 → 没拼提示词」，与真实链路里 `decideGate` 的 `inputVerdict.allowed === false` 分支同源。
- 工具轨迹空数组：拦截记录里 `stage='input'` 已经说明拦在工具调之前。
- `interceptions[0].category / label` 与 `sensitive-words.json` 同源，不另写一份。

## 5. 循环回 1

第 5 轮信封标 `status='blocked'`，渲染侧脚本态停在「拦截轮尾态」。下一条学生输入到达时：

- 如果打的是脚本第 1 轮原话，正常按脚本态推进；
- 如果打的还是敏感词，再来一条拦截回执。

> ★ 这是「循环回脚本」的判据：**第 5 轮不退出脚本态，下一条按 `turn` % 5 取下一句**。具体实现由执行 AI 在渲染侧脚本状态机里写，本案只定行为。

## 6. 不发生的事

- **不改 `sensitive-words.json`**：演示用的拦截文案**预置在沙箱脚本里**，不靠真词表。这样词表更新不会让演示失效，也不需要为演示往词表里塞「假触发词」。
- **不真发审查请求**：沙箱态下审查服务连不通也不影响展示。沙箱态的处理函数（`overlay.ts` 拦截点）**直接读 prebuilt 文案**回执。
- **拦截记录只写 `interceptions`**：不往工具轨迹里塞「假工具调用」（拦截不是工具，是门）。

## 7. 渲染侧禁止出现的字眼

按 D-096 第 2 条，「演示 / 回放」字样**不进界面**。第 5 轮的拦截回执来自 `safeText`（按 D-096 第 2 条口径「对外被问及时说明这是预置数据」，**界面内部正常显示拦截文本**）。

## 7.1 沙箱态的拦截回执如何构造

预置在 `script.ts` 第 5 轮的 `answer` 字段里，内容**逐字取自** `sensitive-words.json` 的 `categories.illegal.safeText`：

> 这类内容我不能提供，也不能帮你查找。如果你是对相关新闻有疑问，我们可以聊聊「AI 在安全领域能做什么」。

这条文案写死在脚本里，不调审查端点；信封字段 `interceptions[0].reason='wordlist'`（与真实链路一致），`category='illegal'`、`label='违法与危险品'`。

## 8. 沙箱态下安全审查的运行时

真实链路：`reviewInput()` 调用 Python `/api/safety/review` 端点，词表命中即返回 `blocked` + `safeText`，TS 侧把它转成 `blocked` 事件给渲染侧。

沙箱态：`overlay.ts` 在 `apiFetch` 最前拦下 `/api/safety/review`，**不真发请求**，按学生文本含关键词直接返回预置的拦截结果。这样：

- 不依赖审查服务在线
- 不污染真实词表
- 演示者打什么敏感词，沙箱态都按 `illegal` 类回执（不演示多类目区别；要演示多类目，让演示者按 §3 表里换敏感词，每种词回执不同）
