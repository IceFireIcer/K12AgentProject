# 05 · 动态生成变式题（预置好，沙箱载入即插）

> 学生做第 4 轮闯关时，主流程会按画像出 3 题机器学习闯关题（来自题库 `machine-learning-sr-q1/q2/q3`）。
> 但题库只有 3 题，做完就没了。
>
> 真实链路里有个 `generate_variants` Tool 可以**动态生成**同知识点的变式题（经 LLM 现出 + 登记）。
> 沙箱态下不能真调 LLM——所以**提前把变式题预置好**，沙箱载入时一并插进学生的题库。
>
> 这样视频里学生点「我想再练几道」时，能立刻拿到一份精挑细选的预置变式题，
> 而不是看到一个「正在生成…」的转圈。

## 1. 预置变式题清单（3 道，对应机器学习知识点）

按 `variantQid(kpId, index, seed)` 的格式生成 qid（执行 AI 在落地时按 `quiz.ts` 的实现填）：

| qid（示例） | 题型 | 题面 | 选项 | 答案 |
| --- | --- | --- | --- | --- |
| `gen-machine-learning-sr-<seed>-0` | choice | 监督学习和强化学习的根本区别在于什么？ | ['监督学习需要标签，强化学习靠奖励信号', '监督学习用于图像，强化学习用于文本', '监督学习要大数据，强化学习要小数据'] | 监督学习需要标签，强化学习靠奖励信号 |
| `gen-machine-learning-sr-<seed>-1` | choice | 下面哪个例子属于无监督学习？ | ['把学生做题记录按行为聚类找出共性薄弱点', '用标注好的猫狗图片训练分类器', '让 AI 通过试错学下围棋'] | 把学生做题记录按行为聚类找出共性薄弱点 |
| `gen-machine-learning-sr-<seed>-2` | choice | 训练时如果损失一直在降但验证集损失开始上升，说明什么？ | ['过拟合了，应该早停', '欠拟合了，应该加层', '学习率太大了'] | 过拟合了，应该早停 |

## 2. 题面设计理由

- **题 1**：考「三类学习的根本判据」——比真题 q1「对照维度是什么」更具体一步。
- **题 2**：考「无监督学习场景识别」——比真题 q2「拍照识题属于哪类」更难一档（场景描述更长）。
- **题 3**：考「过拟合的现象识别」——是真题 q3「过拟合控制手段」的应用题，需要先看出过拟合。

难度梯度：真题（基础）→ 变式 1（中等）→ 变式 2（中等）→ 变式 3（中难）。

## 3. 沙箱态接入路径

真实链路里 `generate_variants` 走：

```
LLM 出题 → POST /api/quiz/variants（登记答案进 learning.db） → 返回对外形态
```

沙箱态下走预置：

```
overlay.ts 拦下 POST /api/quiz/variants → 直接读预置 JSON → 返回对外形态（无答案）
```

预置 JSON 落在 `desktop/src/main/demo/quiz-variants.json`（执行 AI 创建），结构：

```json
{
  "kp_id": "machine-learning-sr",
  "variants": [
    {
      "qid": "gen-machine-learning-sr-demo-0",
      "type": "choice",
      "stem": "监督学习和强化学习的根本区别在于什么？",
      "options": ["监督学习需要标签，强化学习靠奖励信号", "监督学习用于图像，强化学习用于文本", "监督学习要大数据，强化学习要小数据"],
      "answer": "监督学习需要标签，强化学习靠奖励信号",
      "rubric": "三类学习的根本判据是反馈形式：监督=标签、强化=奖励、无监督=无反馈。"
    },
    { ... 题目 2 ... },
    { ... 题目 3 ... }
  ]
}
```

## 4. 信封字段（变式题登记轮）

如果视频演示里点了「我想再练几道」按钮，会产生一条额外的工具轨迹：

```jsonc
{
  "turn": 13,
  "tools": [
    { "seq": 1, "name": "get_student_profile", "ok": true, "latencyMs": 240 },
    { "seq": 2, "name": "generate_quiz", "ok": true, "latencyMs": 380 },
    { "seq": 3, "name": "generate_variants", "ok": true, "latencyMs": 720 }  // ← 这条
  ]
}
```

> ★ 如果演示者不点「再练几道」，就不挂第 3 条工具轨迹——按现有「不编没发生过的调用」纪律。

## 5. 与真实链路的一致性

- 题目结构（qid / type / stem / options / answer）逐字段与真实 `register_variants` 端点对齐
- `qid` 必须带 `gen-` 前缀（与 `variantQid()` 同源），否则会被真实链路判为「伪装成题库真题」
- 答案只进 `learning.db`，对外载荷（题目展示）不带 `answer` —— 沙箱态预置也按此口径，**渲染侧拿不到答案**

## 6. 不进沙箱态变式题清单的事

- ❌ 不预置开放题（变式题里允许开放题，但沙箱态判分被拒，演示会卡）
- ❌ 不预置跨 KP 变式题（演示主线只讲机器学习一个 KP）
- ❌ 不预置过难的变式题（难度梯度不超过真题 q3）

## 7. 沙箱态变式题的「判分」回执

学生做完变式题，沙箱态下「提交」按钮**不真跑判分**（写操作被 `demoBlocked()` 拦），返回预置结果：

- 题 1（基础对照）：演示时默认选对 → 显示「答对了」
- 题 2（场景识别）：演示时默认选错 → 显示「这题再想想，无监督学习的特点是没标签」
- 题 3（过拟合识别）：演示时默认选对 → 显示「答对了」

预置结果写在 `script.ts` 里，不调真端点。

## 8. 沙箱态变式题数量

3 题（与真题 3 题合计 6 题）。不再多——演示视频不必做完所有题，重点演示「动态生成真的能拿到题」这条机制。

## 9. 与现有动态出题功能（2026-10-01 落地的练习页生成）的关系

- 练习页的「做完内置题自动追加」是真实功能，对应 invoke 通道 `quiz:generate-auto` / `quiz:generate-more`
- 沙箱态预置变式题**也走这两条通道**（不新增通道），只是返回值是预置好的
- 沙箱态下两条通道的 `demoBlocked()` 拦截：**不阻塞**（返回预置变式题列表），与练习页的真实行为一致

> ★ 这条与 2026-10-01 落地的练习页动态出题方案配套（见 `.workbuddy/memory/2026-10-01.md`）：
> 真实链路用 `agent/quizgen/` 的 subagent 出题；沙箱态用预置 JSON 顶替。
> 两条路径**共用通道、共用渲染**，只是数据来源不同。
