### B.2 【接受】TTL 单位不同：Python 秒 / TS 毫秒

`EPHEMERAL_TTL_SECONDS = 24*60*60`（Python）与 `EPHEMERAL_TTL_MS = 86400000`（TS）。
**语义一致**（秒 × 1000），且两边各自单位都在**本语言惯用侧**：
Python 侧 `ts` 来自 `int(time.time())`（秒），TS 侧 `Date.now()`（毫秒）。
强行统一单位反而要在一边写 `* 1000` 的转换 —— **转换点才是 bug 的温床**。
守卫按「秒 × 1000 == 毫秒」断言，已覆盖。

### B.3 【接受并采纳】`profile_tags.turn_mark` 是报告 DDL 的**缺陷修补**

报告 §0.6.2 的 DDL **没有**这一列，但 §0.6.5 同时要求「TTL = 3 轮会话**或** 24 小时，取先到」——
**没有单调轮次量就无法实现「3 轮」那一半**。A 补的 `turn_mark`
（写入时 `grade_signals` 的最大 id）与迁移 v3 的 `signal_mark` 是**同一套思路**：
`id` 是 AUTOINCREMENT，全局单调、跨会话连续，于是「过了几轮」不需要跨会话相减。
⇒ 这是**正确的修补**，正式纳入口径。报告 §0.6.2 的 DDL 视为不完整，**以本实现为准**。
