## 1. Problem Statement（问题）

从使用者视角看，今天要解决的问题是四个具体的缺口：

1. **优质 AI 通识师资供给不足。** 中小学要开人工智能通识课，但能讲这门课的老师少、备课成本高。学生课后遇到问题，没有人能 7×24 地接着讲下去。
2. **个性化停留在口号。** 同一个班里，小学低年级需要童话式比喻，高中需要严谨推导；而现成的学习产品给所有人同一套内容、同一种语气、同一条路径。
3. **学生自主学习缺引导。** 学生不知道该学什么、下一步学哪里、哪里还没掌握；做完题只知道对错，不知道自己卡在哪个概念上。
4. **家长与老师看不见过程。** 学习类工具通常只给结果（分数），说不清「这一轮回答依据了什么、孩子最近在学什么、哪几条是孩子自己说的、哪几条是系统猜的」。
5. **未成年人数据的合规红线。** 学生数据不能上云、不能被用于训练、不能跨学生混放；同时不能因为合规就把产品做成「什么都记不住」的废物。

## 2. Solution（方案）

一台**单机运行的 Windows 桌面应用**（产品名「智团团」，吉祥物是抱着蜂窝的小熊），扮演「7×24 小时在线的 AI 老师」。

**四条核心交互线**（学生直接使用）：

| 交互线 | 学生看到什么 |
| --- | --- |
| **对话问答** | 用自己学段的语气讲知识、追问、举例；回答带教材出处；可随时回看历史会话、分叉重问 |
| **动画讲解** | 概念被「演」出来（变量是盒子、梯度是下山）；模板优先、可现场生成、可复用 |
| **编程环境** | 在真实编辑器里改两行代码就能跑，报错被翻成中文，卡住有分级提示 |
| **游戏化练习** | 按教材章节组织的关卡：教材题 + AI 现场出的题；规则判分 + 主观题批改；掌握度、徽章、错题本、「还想再练练」 |

**三条支撑能力**（让上面四条成立）：

- **教材检索（RAG）**：四学段教材入库，检索**严格按学段隔离**（写在 SQL 层），回答带引用；模型/向量任一环节不可用时走**四级降级链**并如实告知「本次检索能力受限」，不静默降级。
- **学生画像**：掌握度、偏好、错误类型、兴趣**每轮进提示词**；模型可主动记偏好；学生能看见「我记住了什么」并逐条纠错；冷启动用**五个问题**把画像从零建起来。
- **学习档案**：学习报告、错题本、章节进度、学习地图、历史会话，六分页可查；可导出 Markdown。

**三条产品级立场**（不是技术细节，是需求约束）：

1. **默认不要求学生做任何事，但他想做的时候必须有地方可做** —— 学段默认自动推断并自动生效，同时保留手动指定入口。
2. **诚实优先于好看** —— 检索降级、动画生成失败、判分失败、按钮未接线，全部如实说明并给出下一步，绝不假装成功。
3. **数据全本地、一人一份** —— 学生库与 AI 会话树按学生隔离；**对话正文不入库**（唯一例外见 §5.4）。

## 3. 角色（Actors）

| 角色 | 谁会用到 | 关心什么 |
| --- | --- | --- |
| **学生**（小学低年级 / 小学高年级 / 初中 / 高中） | 主用户 | 听得懂、跟得上、有反馈、能自己往下走 |
| **家长** | 监护人 | 孩子学了什么、系统记住了什么、能不能关掉「记忆」 |
| **教师 / 答辩者** | 演示与评审 | 教学机制可查、过程可解释、证据可导出 |
| **开发者 / 维护者** | 本项目团队 | 契约不漂移、边界不被越过、回归能拦住、出包可用 |
| **系统自身** | — | 安全终审、降级、限幅、自愈、数据隔离 |

## 4. User Stories（需求条目）

### 4.1 首次启动与账号

1. 作为学生，我希望打开应用就能选「我是谁」，以便我每次进来看到的都是自己的进度。
2. 作为学生，我希望没有账号时能直接新建一个，以便不用注册、不用密码、不填手机号就能开始。
3. 作为学生，我希望能改自己的显示名，以便昵称写错了随时改。
4. 作为学生，我希望删账号前被拦一道并让我先导出，以免误删掉几个月的学习记录。
5. 作为同一台电脑上的第二个学生，我希望切换账号后看到的是完全属于我的数据，以便和同学共用一台机器也不串。
6. 作为家长，我希望本地账号**不是**安全边界这件事被明确说明，以便我不把它当登录密码用。

### 4.2 冷启动五问

7. 作为刚进来的学生，我希望助手先问我五个问题，以便它不用猜就能知道我的年级、目标、偏好与基础。
8. 作为学生，我希望这五个问题是**对话里的下一条消息**而不是一张弹窗表单，以便我像聊天一样回答。
9. 作为学生，我希望能重答任何一问，以便我说错了可以纠正。
10. 作为学生，我希望答完之后系统把我的回答概括成画像标签给我看，以便我知道它记住了什么。
11. 作为学生，我希望**没有「跳过」这个入口**，以便我不会因为随手一跳而让后面所有内容都失去依据。
12. 作为学生，如果我没答完就离开，我希望下次回来它接着问没答的那一问，以便不用从头再来。
13. 作为家长，我希望系统**不推断性格与心理**，只记录我说过的事，以便它不会给我的孩子贴标签。

### 4.3 对话问答

14. 作为学生，我希望助手边想边说（流式），以便我不用盯着空白等很久。
15. 作为学生，我希望回答里提到的教材内容能点开看原文，以便我知道它不是瞎编的。
16. 作为学生，我希望助手按我的学段说话，以便小学生听到的是比喻、高中生听到的是推导。
17. 作为学生，我希望一轮回答没结束前再发消息会被排队而不是被丢弃，以便我手快也不丢问题。
18. 作为学生，我希望回答被安全规则拦下时看到一句人话解释，以便我知道发生了什么、下一步怎么办。
19. 作为学生，我希望中途出错时这一轮能恢复，而不是整个对话卡死。
20. 作为学生，我希望历史会话都在左边列着，点一条就能接着聊，以便我换话题后还能回到原来那段。
21. 作为学生，我希望关掉应用再打开能自动续上最近一段对话，以便我不必每次重新找。
22. 作为学生，我希望能从某一条消息**重新问一次**（分叉），以便我想换个问法而不污染原来的记录。
23. 作为学生，我希望新会话开始时助手先提一句「我们从哪里开始」，以便我不用自己想第一个问题。
24. 作为学生，我希望那句开场必须**有依据**（依赖图推荐的知识点）；没有依据时宁可不发，以便我不收到一句对谁都成立的寒暄。
25. 作为学生，我希望能把一段对话导出，以便我留档或打印。

### 4.4 教材检索与引用（RAG）

26. 作为学生，我希望助手只使用我学段（及更低学段）的教材，以便它不会超纲。
27. 作为学生，我希望「用了哪些教材段落」写在回答旁边，以便我核对。
28. 作为学生，我希望检索能力受限时被明确告知，以便我知道这次回答的可靠度。
29. 作为教师，我希望看到这一轮检索走到了哪一档（向量 / 云端 / 全文 / 大纲），以便排查「为什么没引用到」。
30. 作为维护者，我希望检索的降级过程被记录成可见的档位与耗时，以便我能证明它没有静默降级。

### 4.5 学段自适应

31. 作为学生，我希望系统从我的用词和提问深度自动判断学段，以便我什么都不用设置。
32. 作为学生，我希望可以手动指定学段并**立刻生效**，以便系统判断错时我能纠正。
33. 作为学生，我希望手动指定之后有一段时间不再被自动改动，以便我的选择不会被一次误判推翻。
34. 作为学生，我希望看到系统是从哪句话判断出我的学段的，以便我理解它为什么这么讲。
35. 作为教师，我希望看到学段判定的四类信号分值与判定来源，以便解释机制的可靠性。
36. 作为维护者，我希望学段变更受硬约束（置信度门槛、连续同向、冷却轮次、单次只动一级），以便它不会来回跳。

### 4.6 章节软偏好

37. 作为学生，我希望选定「我现在在学哪一章」，以便回答与检索优先围绕这一章。
38. 作为学生，我希望章节只是**软偏好**而不是硬过滤，以便我跨章提问也能得到回答。
39. 作为学生，我希望换学段时章节自动清空，以便不会出现「高中在学小学章节」的鬼状态。

### 4.7 动画讲解

40. 作为学生，我希望能对任意知识点说「用动画讲一下」，以便抽象概念能看见。
41. 作为学生，我希望动画是**真时间轴**而不是淡入淡出，以便它真的在演示过程。
42. 作为学生，我希望动画按学段换视觉语言（小学插画化、中学工程图），以便它看起来不违和。
43. 作为学生，我希望同一个知识点再要一次能立刻复播，以便我不用等第二次生成。
44. 作为学生，我希望动画生成失败时降级成文字 + 静态图而不是白屏，以便我仍然学到东西。
45. 作为学生，我希望动画在沙箱里运行、拿不到我的数据，以便它再花哨也不越界。
46. 作为教师，我希望看到动画是「命中模板」还是「现场生成」，以便判断成本与稳定性。

### 4.8 编程练习

47. 作为学生，我希望在真实编辑器里写代码并按一个键就跑，以便练习像真的编程。
48. 作为学生，我希望代码在本地沙箱里执行，以便我的机器与我的人都不受影响。
49. 作为学生，我希望报错被翻成看得懂的中文，以便我不被英文栈吓退。
50. 作为学生，我希望卡住时有**分级提示**（先点拨、再给方向、最后给答案），以便我尽量自己想出来。
51. 作为学生，我希望有可直接开始的代码模板，以便我不必从空白文件写起。
52. 作为学生，我希望运行超时被明确处理（不是无限转圈），以便我知道是代码卡住了。
53. 作为教师，我希望学生代码**绝不在主进程或后端执行**，以便安全边界可证明。

### 4.9 练习与闯关

54. 作为学生，我希望练习按教材章节组织成关卡，以便我知道学到哪了。
55. 作为学生，我希望客观题由规则判分（快、可复现），以便我立刻知道对错。
56. 作为学生，我希望主观题由模型按评分要点批改并给分档反馈，以便开放题也能练。
57. 作为学生，我希望每道题被判完后，系统按我的作答轨迹**再出几道同类题**，以便我做错的点能立刻再练一遍。
58. 作为学生，我希望自动追加有上限（单关最多 20 题）且编号连续，以便列表不会被撑爆。
59. 作为学生，我希望做完之后还能点「还想再练练」再来一批（每次 +10），以便我想加练时不用换关。
60. 作为学生，我希望生成出来的题也**存下来**，以便我换关再回来它还在、不用重新生成。
61. 作为学生，我希望答错的题进错题本，以便我复习时只看该看的。
62. 作为学生，我希望看见掌握度变化与闯关徽章，以便我有进度感。
63. 作为学生，我希望重做同一题时不被重复计分，以便我的进度是诚实的。
64. 作为学生，我不希望为了让我「有题做」而在生成失败时拿旧题凑数，以便我做的每道题都是真的。
65. 作为教师，我希望生成题**先登记成功再下发**，以便屏幕上出现的题一定能在库里判分。
66. 作为教师，我希望生成题的评分要点只留在本机、不进下发给学生的载荷，以便答案不泄漏。

### 4.10 学习档案

67. 作为学生，我希望看到最近一段时间的正确率、错题与薄弱点，以便我知道该补哪里。
68. 作为学生，我希望看到每个知识点的掌握度，以便我判断「这关能不能过」。
69. 作为学生，我希望看到学段变化的历史，以便理解系统对我的判断是怎么变的。
70. 作为学生，我希望有学习地图把知识点先后关系画出来，以便我知道下一步学什么。
71. 作为学生，我希望档案能导成 Markdown，以便我给家长或老师看。
72. 作为家长，我希望孩子的学习记录**只在这台机器上**，以便它不会被传到任何服务器。

### 4.11 知识图谱与参考资料库

73. 作为学生，我希望点一个知识点就能看到它的前置与后继，以便我按顺序学。
74. 作为学生，我希望从图谱直接发起一节学习计划，以便「看到 → 学到」不用换页重找。
75. 作为学生，我希望参考资料库能按学段搜索教材原文，以便我自己查证。
76. 作为教师，我希望参考资料库里不出现任何技术性内部信息（内部 id、诊断串），以便学生看到它不会误解。

### 4.12 学生画像

77. 作为学生，我希望看到「我记住了什么」：当前话题、知识点掌握、错误类型、讲解节奏偏好，以便它不是一个黑箱。
78. 作为学生，我希望每一条都标出**来源**（我告诉它的 / 它从我的学习里看到的）与把握度，以便我能分辨事实与推测。
79. 作为学生，我希望推测出来的条目能一键撤回，以便它不会一直拿着一个错误印象当依据。
80. 作为学生，我希望画像**每轮都在起作用**（影响讲解方式与难度），以便它真的个性化。
81. 作为家长，我希望有一个开关能关掉「记忆」，以便我能决定系统是否长期记住我的孩子。
82. 作为家长，我希望关闭记忆之后，标签、时间线、事件这些读出口**全部为空**，以便这个开关是真的有用。

### 4.13 视角与演示

83. 作为学生，我希望界面上不出现「工具调用」「降级档位」「诊断串」这类词，以便我不会以为界面坏了。
84. 作为教师，我希望有一个只读的「这一轮怎么跑出来的」浮窗，以便我当场解释机制。
85. 作为答辩者，我希望有一页「运行透视」摊开后端每一步（调用、耗时、结论），以便演示时能自证。
86. 作为答辩者，我希望有演示沙箱，能把外部依赖换成预置数据，以便断网也能完整演示。
87. 作为开发者，我希望有操作日志面板，以便复现问题时知道刚才发生了什么。

### 4.14 设置与模型

88. 作为用户，我希望在设置里填供应商、地址、模型、Key，以便我用自己买的模型服务。
89. 作为用户，我希望能从内置供应商预设里挑一个（地址与模型清单自动带出），以便我不用手抄端点。
90. 作为用户，我希望保存时真的去探一次连通性，以便我不会带着一个错的配置上课。
91. 作为用户，我希望 Key 只存在本机、界面只显示掩码、渲染进程拿不到明文，以便它不会被别的页面偷走。
92. 作为用户，我希望没配 Key 时应用**仍然可用**（讲知识、判客观题、跑代码），以便我不被一个配置卡住整个产品。

### 4.15 交付与运维

93. 作为维护者，我希望契约只有一处定义（后端模式）并自动生成前端类型，以便两端不会漂移。
94. 作为维护者，我希望架构边界写成会失败的测试，以便新代码越界时立刻红。
95. 作为维护者，我希望每条守卫都做过「改坏 → 确认变红」的变异验证，以便守卫本身不是摆设。
96. 作为维护者，我希望出包时校验「包里的后端」与源码一致，以便不会打出「新前端 + 旧后端」的包。
97. 作为维护者，我希望本地只出一条便携版、安装包交给 CI，以便日常验证快且不误发。
98. 作为维护者，我希望文档里登记的数字（知识点数、契约数、通道数）与磁盘一致并被检查，以便文档不会变成谎言。

### 4.16 明确不做（负向需求）

99. 作为学生，我不希望这里出现「课程」这个概念 —— 教材只是参考，我想问什么就问什么。
100. 作为家长，我不希望产品生成绘本、视频这类多模态资源推荐（已砍单），以便范围可控、质量可保证。

## 5. Implementation Decisions（实现决策）

> 按 PRD 惯例，这里只说**模块与接口的形状**，不写文件路径与代码片段。
> 少数被内联的「形状」是**已冻结的契约**（不是原型草图）：它们本身就是决策，用散文描述会失真。

### 5.1 分层与四条硬边界

| 层 | 职责 | 明确不做 |
| --- | --- | --- |
| **渲染层**（Vue 单页，无路由库） | 全部界面与交互；**学生代码只在这里执行**（Pyodide Worker）；动画在 sandboxed iframe 里跑 | 不直连后端、不用 Node 能力、不拿明文密钥 |
| **主进程**（TypeScript 编排） | AI 编排、提示词、工具注册、事件映射、身份注入、出网（仅两个口） | 不读写数据库、不算向量、不执行学生代码 |
| **数据域**（Python sidecar） | 数据、检索与降级、嵌入、判分、学习记录、内容安全词表、知识库导入与重建 | **不调用任何 LLM** |
| **契约层** | 后端模式定义 → OpenAPI → 生成前端类型；工具参数与后端模式一致 | 不允许手写兜底接口 |

出网只有两个口：**只打本机 sidecar**（带启动时新铸的随机 token）与**只打用户配置的模型服务**；两条路不许串味。

### 5.2 关键契约形状（冻结）

**对话事件词表恰好六个词**：

```
delta | citation | payload | blocked | done | error
```

- `done` 是**唯一终态**；取消/停止不在词表内。
- 安全终审排在 `done` **之前**：违规则先发 `blocked`（替换正文）再补 `done`，否则「先说完再撤」会静默失效。

**对话请求的字段集合恰好一个**：

```
ChatSendRequest = { text }
```

学段、章节、学生身份**都不许混进对话请求** —— 它们各自走独立通道；学生身份由主进程注入。

**通道与白名单**：主进程通道名单是唯一来源，渲染层只能经白名单方法访问；通道数与白名单方法数**必须逐一对齐**（有守卫与文档数字自检）。

**降级标记**：`degraded` 有两个语义（检索档位 / 生成降级），事件里如实回传，界面据此换文案而不是假装正常。

### 5.3 数据与存储

| 存储 | 内容 | 归属 |
| --- | --- | --- |
| 知识库（只读，随包） | 知识点、父子分块、向量、全文索引、依赖图、题库 | 全体共享，构建产物 |
| 学习库（每人一份） | 学生、掌握度、学习历史、闯关进度、偏好、学段信号与历史、身份本地副本、画像标签与时间线、冷启动问答、生成题、已存动画、已存代码模板 | **按学生隔离** |
| AI 会话树（每人一份） | 完整对话（含工具轨迹与会话摘要） | **按学生隔离** |
| 账号表、诊断流水 | 本地账号；剥掉正文的诊断信封 | 本机 |

**对话正文不入库**是硬约束，唯一例外是冷启动五问的问答（作用域只有那五条、一次性、有界）。

### 5.4 状态机（三处关键）

- **闯关**：`learning → quizzed → mastered`（已取消 `locked`）；判分产生掌握度增量 → 进度与徽章随之变化。
- **冷启动**：`not_started → in_progress → done`；`done` 是唯一终态；历史遗留的 `skipped` **也算没答完**（没有跳过入口）。
- **学段推断**：每轮三路信号入库（无证据也写中性占位行以打断「连续同向」）；判定受四道约束 —— 置信度门槛、连续 N 轮同向、冷却轮次（自动 / 手动不同）、单次只动一级；前若干轮由规则判，之后由模型定方向而规则做安全网；无 Key 时整层跳过并标 `no_llm`。

### 5.5 生成类能力（动画 / 编程 / 出题）的共同模式

`生成 → 结构校验 → 失败重试（共享总预算）→ 仍失败则降级`，且**先登记成功再下发**：

- 出题：单关自动追加有个数上限，追加批次有固定批量；**失败绝不回退到题库凑数**；评分要点只留本机。
- 动画：模板优先（命中即免生成）→ 校验 → 降级为文字 + 静态图；按「知识点 + 学段 + 请求指纹」按学生存档复用。
- 编程：模板优先 + 三级提示 + 报错中文翻译；后端**没有执行原语**（执行只在前端沙箱）。

### 5.6 数值型不变量（写死在实现里，PRD 视作需求）

输入长度有上限；题库单次取题数与生成批次有上限；掌握度单次增量有上下限、答错不减分；重复作答不二次计分；提示词里注入的画像标签有条数与轮次节奏；报告时间窗有默认值与上限；各类超时（判分 / 模型 / 运行 / 加载）各自独立。

### 5.7 视觉与文案决策

- **视觉边界三件套**：底色差（主）+ 两支线（副）+ 只给结构分面的单侧投影（副）；三者不许单独拿掉。
- **设计令牌唯一来源**：颜色/间距/圆角/字号都由一份令牌源生成，页面**不许写死字号与色值**；改令牌要同步重建动画皮肤。
- **光影效果是 opt-in**（默认不打扰、尊重「减少动效」）。
- **三档视角**：学生 < 教师 < 调试；判据只有「当前档位 ≥ 该页要求」。技术证据一律进「教师门」，学生面禁技术词与内部 id。
- **失败文案必须经统一翻译**：翻掉的是状态码与服务器路径，不是「发生了什么、下一步做什么」。

## 6. Testing Decisions（测试决策）

### 6.1 什么算好测试

- **只测外部行为**：测「事件按六词表送达」「契约字节一致」「学段隔离在 SQL 层生效」，而不是「某个函数被调用了几次」。
- **守卫写成正向断言**：断言「必须经白名单通道」，而不是「禁止某个已删除的旧实现」—— 后者会随重构腐烂。
- **每条修复配一条变异**：把修复改回坏写法，确认测试真的变红；否则这条断言不算数。
- **界面断言走真实渲染**：用 CDP 探针在真应用上量几何、取色、查 DOM 属性，而不是给组件打桩。

### 6.2 接缝（seams）——优先复用既有的，不新开

本项目的既有接缝（**由高到低**，新需求应当落在最高的那一个）：

1. **契约接缝**：后端模式 → OpenAPI → 前端类型 + 字节比对。跨层行为一律在这里验。
2. **事件流接缝**：渲染层看到的六事件流 + 白名单方法。对话/生成/判分的行为断言挂在这里。
3. **数据面桥接缝**：渲染层 → 主进程 → sidecar 的调用边界（也是能力探测与失败文案的唯一入口）。
4. **UI 探针接缝**：真应用 + CDP，量几何/颜色/可达性/键盘路径。
5. **未开的接缝**：目前**没有**端到端「真模型 + 真后端」的自动化接缝（模型不确定、CI 无嵌入模型），因此这部分靠手工验收 + 契约层替身。

> 结论：**新功能一律不加新接缝**；能落在契约层的不落在事件层，能落在事件层的不写 UI 断言。

### 6.3 覆盖与先例

| 模块 | 测法与先例 |
| --- | --- |
| 契约与类型 | 生成物字节比对（`check:api`）+ 工具参数一致性（`check:tool-schema`） |
| 架构边界 | 成组的 G 守卫（数据域/编排域/出网口/通道白名单/会话落盘/构建顺序） |
| 数据层 | 后端单元测试（检索降级逐级断言、学段隔离、判分限幅、迁移） |
| 编排层 | 主进程单元测试（事件映射、提示词组装、生成校验与降级、先登记后下发） |
| 渲染层 | 组件/状态机单元测试 + 学生面文案纪律测试 |
| 界面 | CDP 探针（布局/滚动/繁忙态/属性/减少动效/性能基准） |
| 设计令牌 | 令牌生成物 diff + 342 项对比度严格检查 |

| 交付 | 安装器配置测试 + 变异验证（每条守卫都要能变红） |

### 6.4 已知测试缺口（不藏）

- CI 不下载嵌入模型 → 向量相关用例在 CI 里 **skip**，只有 nightly 真跑（等于「没验」）。
- 界面探针依赖 dev 服务器 + CDP，**不进 CI**。
- 「真模型输出质量」无自动化：出题/动画/概括这几条只有契约与结构校验，没有质量断言。
- 生成题的**答案泄漏**由结构（不下发）保证，但「模型是否把答案写进题干」只有提示词软约束。
