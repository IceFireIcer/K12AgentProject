⚠️ **A2 有硬约束要绕**：项目有一条「禁做清单第 10 条」——`inferred` 类标签只允许出现在情绪/风格，**不许系统主动推断学生的性格/心理**。守卫在 `desktop/tests/onboarding-guards.test.ts:664-797`（G-H-10~14，含「不许情绪操控」「不许心理诊断」「不许依赖诱导」）。所以 A2 的「判断画像」**只能限于学生自己说过的内容**，不能变成性格分析。

### 问题 B：「点选即提交」与「回答时模型照常回」是**互斥**的

你选了「学生点选项就提交」，又选了「回答时模型照常回一句」。这两个凑在一起会产生一个你可能没预料到的效果：

```
现在（点选 = 只填输入框，还要按发送）：
  [团团] 你现在上几年级呀？  (小学低年级)(小学高年级)(初中)(高中)
  [学生点"初中"] → 输入框里出现"初中"，学生按回车
  [学生气泡] 初中
  [团团气泡] 好，初中的内容，我心里有数了。

改成「点选即提交」后：
  [团团] 你现在上几年级呀？  (小学低年级)(小学高年级)(初中)(高中)
  [学生点"初中"] → 立刻发出去
  [学生气泡] 初中
  [团团气泡] 好，初中的内容，我心里有数了。
  [团团] 最近在学什么呀？有没有特别想搞懂的？  (数学)(语文)(英语)(科学)
```

**读起来其实是自然的**（像真人在一问一答）。但代价是：

1. **每次点选都会真的发一次对话给大模型**（一次云端往返 + 一条助手回复）。
2. 如果学生**打字**回答（不点选项），走的还是输入框 → 回车这条老路。于是「点选」和「打字」变成**两条提交路径**。
3. 这与现有的一条纪律**冲突**：`desktop/tests/renderer-onboarding.test.ts:578` 有一条守卫，断言「选项 chip 与打字走同一条提交路径」，并反向断言「chip 不许直接调 submitAnswer」。改成点选即提交，**这条守卫必须改写**——而它当初是为了防「两条路径漂移」才立的。

**我的建议：保持「点选 = 填进输入框」不变**（即你截图里的行为），只改**视觉形态**（去掉卡片壳）。理由：这是零风险的一步，且不破坏既有守卫。如果你确实想要「点选即提交」，我需要你明确接受上面 3 个代价。
