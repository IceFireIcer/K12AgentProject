# 卡片玻璃边缘光效（鼠标跟随角落内凹 + 定向高光）— 设计执行报告

> 验收标准都在这里，**不需要再回头问需求方**。与 `AGENTS.md` 冲突时以 `AGENTS.md`
> 为准；与 `项目执行文档.md` 冲突时以执行文档为准。

## 0. 需求一句话

给现有的圆角矩形卡片（`.k12-card` / `SurfacePanel`）加一套**鼠标跟随的动态光效**：

1. **角落内凹**：鼠标贴近卡片边缘时，四个角随指针接近程度**各自轻微内凹**，
   像软体/玻璃被指压的 3D 效果；
2. **定向高光**：边缘随鼠标位置发出高光，像**玻璃被阳光斜照**——离指针近的
   边缘亮、远的暗，光斑跟着指针走；
3. **动态计算**：不是 CSS `:hover` 换肤那种静态两态，而是指针位置 → 实时
   几何计算 → 平滑跟随（每帧插值），离开后弹回。

## 1. 现状探查结论（代码事实，已核实）

执行前不需要重新探查，以下事实 2026-09-30 已逐条核实：

### 1.1 卡片是「双轨制」，两轨都要覆盖

| 轨道 | 落点 | 说明 |
| --- | --- | --- |
| 全局类 `.k12-card` | `desktop/src/renderer/src/assets/base.css` L369 | 白底 + 1px `--k12-border` + `--k12-r-card`(12px) + `--k12-shadow-card`。消费者：`views/Chat.vue`（chat__entry，L961）、`cards/{AnimationCard,QuizCard,CodingCard,ProgressCard}.vue`、`components/ContextRail.vue`、`components/card/*` |
| 组件 `SurfacePanel` | `desktop/src/renderer/src/components/SurfacePanel.vue` | 全应用唯一的「一块内容」容器，根类 `.sf`（自带 `position: relative`），tone=`card` 时视觉配方与 `.k12-card` 同源。消费者：Animation/Coding/Dependency/Knowledge/Quiz/Settings 六个页面 |

两轨的圆角、边框、投影都引用同一批语义 token，所以**光效层做成独立能力类，
两轨都能挂**，不改各自的皮肤配方。

### 1.2 已有的 hover 行为（不要破坏，只叠加）

`base.css` L890–905：`.k12-card:hover` → `--k12-shadow-raise` + `translateY(-1px)`，
包裹在 `@media (hover: hover) and (pointer: fine)` 里；`prefers-reduced-motion` 下
退化为「只换阴影不位移」（L901–905 与 L948–950 两条，改一处必须同步另一处——
但本需求**不改这两条**）。

### 1.3 命名冲突警告（★★ 必看）

`.k12-glass` **已被占用**——`base.css` L415 的毛玻璃类（`backdrop-filter` 那套）。
新效果**禁止**叫这个名字，本方案统一用 **`.k12-shine`** / `--k12-shine-*`
（已 grep 确认全仓无冲突）。

### 1.4 令牌与阴影的「唯一来源」纪律（红线，详见 §5）

- `--k12-shadow-*` 只在 `base.css` 的 `:root` 定义一次（P-158：同一自定义属性
  两处定义会被后加载的静默覆盖）；
- `tokens.generated.css` 是 `scripts/design/tokens.source.json` 的生成物，**禁手改**；
- 本方案**不碰** `tokens.source.json`（不改色值就不需要重建后端动画皮肤），
  新变量与 `--k12-shadow-*` 同款待遇：写在 `base.css` 的 `:root`，用
  `color-mix` 从现有 token 派生。

### 1.5 现成的相关基建（直接复用）

- **减动效三档**：`composables/useReducedMotion.ts` 返回「有效值」（用户设置 ×
  系统偏好）。**JS 驱动的动效必须读它**——CSS 的 reduce 媒体查询收不掉 JS 定时器，
  这是仓库里写死的纪律（该 composable 文件头原文）；
- **指针媒体查询**：`@media (hover: hover) and (pointer: fine)` 是仓库现有的
  hover 态判据（触屏/无鼠标环境不出效果）；
- **composable 惯例**：单文件、文件头大段注释讲「为什么」、`onBeforeUnmount`
  清理监听、单例订阅避免多处重复绑定（参考 `useReducedMotion.ts` 的写法）。

### 1.6 会扫到本改动的守卫（改完必须全绿）

- `desktop/tests/visual-edges.test.ts`：断言 `.k12-inset` 规则体里必须有

  塞新声明可以，删/改既有声明不行**；本方案不碰 `.k12-inset`；
- `scripts/design/check-contrast.mjs --strict`（342 项）：只查 token 色对，本方案

- `npm run check:docs`（通道数）与 IPC 无关——本需求纯渲染进程，不新增通道。

## 2. 效果规格（设计定义）

### 2.1 效果 A：边缘定向高光（玻璃被阳光照射）

- 卡片边缘出现一条**发亮的细环**（约 1.5px，正好压在现有 1px 边框上）；
- 亮度不均匀：以指针为圆心、半径约 190px 的径向渐变衰减——**离指针近的边缘
  亮起，背对的边缘保持原样**，像一束阳光打在玻璃棱上；
- 高光色**带学段色**：从 `--k12-accent` 派生（学段切换自动换色），混白提亮，
  不是纯白也不是纯灰；
- 辅以一层**极弱的内部光泽**（白 wash，有效强度 ≤8%），让「玻璃感」从边缘
  渗到卡面——这层是可选加强项，对比度预算见 §2.3。

### 2.2 效果 B：角落内凹（软体按压）

- 指针接近某个角（有效半径约 120px）时，**该角的圆角半径动态增大**（最多 +5px），
  角的顶点向对角线内收——视觉上就是「角被压进去了」；
- 四角**独立计算、互不影响**：指针在右下角时只有右下角凹，左上角不动；
- 同时边缘环在受压位置叠一层**极弱的暗部**（从 `--k12-fg` 派生），让受压边缘
  读成「凹陷进阴影里」，3D 感由「圆角变化 + 暗部」两个信号共同承担；
- 边框、底色、投影跟着新圆角走（浏览器原生行为），所以凹得「物理正确」。

### 2.3 参数默认值表（可调，但先按这个落地）

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `MAX_DENT` | 5px | 单角最大内凹量。基础圆角 12px，+5 后 17px，肉眼「轻微」而不夸张 |
| 角落衰减半径 `FALLOFF` | 120px | 指针距角的距离超过它，该角完全不凹 |
| 角落衰减曲线 | 二次（t²) | `dent = MAX_DENT × (1 − d/FALLOFF)²`，只有真贴近才明显 |
| 高光半径 | 190px | 径向渐变半径，决定「光斑」大小 |
| 边缘环带宽 | 1.5px | `--k12-shine-edge`，压在 1px 边框上 |
| 内部光泽有效强度 | ≤ 8% 白 | `0.16 alpha × 0.5 opacity`，见下面的对比度预算 |
| 平滑系数 | 0.2 / 帧 | 指针状态到渲染值的 lerp 插值（约等于 ~100ms 跟随感） |
| 收敛阈值 | 0.01px | 所有增量小于它且指针不在卡上 → 停 rAF |

**对比度预算（为什么内部光泽封顶 8%）**：正文 `--k12-fg`(#1B2233) 对白 ≈15:1，
叠 8% 白后 ≈13:1，安全；但 `--k12-muted` 一档的浅色小字对白只有 ≈4.8:1，叠 8% 白
会逼近 4.5:1 红线。**验收时专门走查「卡片边缘处的 muted 小字是否发糊」**，
发糊就把内部光泽层砍掉（效果 A 的边缘环才是主效果，内部光泽是锦上添花）。

### 2.4 生效条件（三个门，缺一不可）

1. `@media (hover: hover) and (pointer: fine)`——触屏/无精确指针不出；
2. `useReducedMotion()` 为 false——减动效开启时**整个效果关闭**（跟随指针的
   连续动画正是减动效要收的对象；不做「降级版」，直接全关，简单且口径干净）；
3. 指针在卡片上（pointerenter 激活，pointerleave 回弹归零）。

## 3. 技术方案总览

```
pointermove（passive，仅 hover 中的卡片）
   │  归一化到卡片局部坐标 (px, py)
   ▼
requestAnimationFrame（单例调度，一帧最多算一次）
   │  纯数学：4 角内凹量 + 高光位置 + 近边强度
   │  lerp 平滑：cur += (target − cur) × 0.2
   ▼
写 8 个 CSS 自定义属性到卡片元素（只写 style property，不碰 class）
   │  --k12-shine-x / -y          光斑中心（局部 px 坐标）
   │  --k12-shine-inside          内部光泽整体透明度 0–0.5
   │  --k12-dent-tl/-tr/-br/-bl   四角内凹量 0–5px
   ▼
CSS 渲染（零 JS 参与，纯既有合成路径）
   ├─ ::before 边缘环：mask 挖出 1.5px 边框带 + 双径向渐变（亮环 + 受压暗部）
   ├─ ::after  内部光泽：低透明度白色径向渐变
   └─ 元素本体：border-radius 四角 calc(基础值 + 内凹量)，边框/投影自动跟随
```

**不用的方案及原因**（执行 AI 不要「优化」成这些）：
- ❌ SVG filter（feDisplacementMap 位移）：每帧重算 filter 极贵，且效果难以
  用 token 控制；
- ❌ `backdrop-filter`：贵，且 `.k12-glass` 语义已占用；
- ❌ CSS `transition` 驱动内凹：跟随会滞后一拍，且和 JS lerp 双重平滑打架；
  `transition` 只给 `opacity`（进出场的淡入淡出）；
- ❌ 改 `tokens.source.json` 走生成流水线：本效果是结构参数不是配色，且改色值
  会触发「重建后端动画皮肤」的联动义务，完全没必要。

## 4. 详细实现（施工级）

### 4.1 新建 `desktop/src/renderer/src/composables/useCardShine.ts`

```ts
/**
 * 卡片玻璃光效（2026-09-30 设计执行报告 §4.1）。
 *
 * 做两件事，全部通过写 CSS 自定义属性完成，DOM 结构不动：
 *   1) 边缘定向高光：--k12-shine-x/-y（光斑中心，卡片局部坐标）+ --k12-shine-inside
 *   2) 四角内凹：--k12-dent-tl/-tr/-br/-bl（0–MAX_DENT，px）
 *
 * ★ 纪律（与本仓既有约定一致）：
 *   · JS 驱动的动效必须读 useReducedMotion() 的**有效值**（三档开关 × 系统偏好），
 *     减动效开启时整个效果不挂监听——CSS 的 reduce 媒体查询收不掉 JS 的 rAF；
 *   · pointermove 必须 passive；rAF 单例调度（一帧只算一次）；
 *   · onBeforeUnmount 里解绑监听、取消 rAF（本仓 composable 惯例）；
 *   · 不读 layout 之外的任何 DOM 状态；每帧一次 getBoundingClientRect，
 *     先读后写，不与样式写入交错（避免强制同步布局）。
 */
import { onBeforeUnmount, onMounted, type Ref } from 'vue'
import { useReducedMotion } from './useReducedMotion'

/** 参数集中在顶部常量（对应报告 §2.3 的参数表，调优只改这里）。 */
const MAX_DENT = 5 // px
const FALLOFF = 120 // px：指针离角超过它，该角不凹
const LERP = 0.2 // 每帧插值系数
const EPSILON = 0.01 // px：收敛阈值

const clamp01 = (v: number): number => (v < 0 ? 0 : v > 1 ? 1 : v)

/** 单角内凹量：二次衰减（报告 §2.3）。纯函数，单测就测它。 */
export function cornerDent(px: number, py: number, cx: number, cy: number): number {
  const d = Math.hypot(px - cx, py - cy)
  const t = clamp01(1 - d / FALLOFF)
  return MAX_DENT * t * t
}

/** 近边强度（0–1）：决定内部光泽透明度。 */
export function edgeProximity(px: number, py: number, w: number, h: number): number {
  const edgeDist = Math.min(px, py, w - px, h - py)
  return clamp01(1 - edgeDist / 64)
}

export function useCardShine(el: Ref<HTMLElement | null>): void {
  const reduced = useReducedMotion()

  let raf = 0
  let frame = 0 // rAF 单例调度的标记
  let active = false // 指针是否在卡上
  // 平滑状态：光斑坐标 + 四角内凹 + 近边强度。位置存在才有意义，离开时全部归零。
  const cur = { x: 0, y: 0, tl: 0, tr: 0, br: 0, bl: 0, inside: 0 }
  const tgt = { ...cur }

  const setVars = (): void => {
    const node = el.value
    if (node === null) return
    node.style.setProperty('--k12-shine-x', `${cur.x.toFixed(1)}px`)
    node.style.setProperty('--k12-shine-y', `${cur.y.toFixed(1)}px`)
    node.style.setProperty('--k12-shine-inside', cur.inside.toFixed(3))
    node.style.setProperty('--k12-dent-tl', `${cur.tl.toFixed(2)}px`)
    node.style.setProperty('--k12-dent-tr', `${cur.tr.toFixed(2)}px`)
    node.style.setProperty('--k12-dent-br', `${cur.br.toFixed(2)}px`)
    node.style.setProperty('--k12-dent-bl', `${cur.bl.toFixed(2)}px`)
  }

  const tick = (): void => {
    // lerp：cur 向 tgt 逼近；不在卡上时 tgt 全零 → 自动回弹
    let settled = true
    for (const key of Object.keys(cur) as (keyof typeof cur)[]) {
      const delta = tgt[key] - cur[key]
      if (Math.abs(delta) > EPSILON) settled = false
      cur[key] += delta * LERP
    }
    setVars()
    // 收敛且指针不在卡上 → 停帧（不留常驻 rAF）
    if (settled && !active) {
      frame = 0
      return
    }
    frame = requestAnimationFrame(tick)
  }

  const schedule = (): void => {
    if (frame === 0) frame = requestAnimationFrame(tick)
  }

  const onMove = (e: PointerEvent): void => {
    const node = el.value
    if (node === null) return
    const rect = node.getBoundingClientRect()
    const px = e.clientX - rect.left
    const py = e.clientY - rect.top
    tgt.x = px
    tgt.y = py
    tgt.tl = cornerDent(px, py, 0, 0)
    tgt.tr = cornerDent(px, py, rect.width, 0)
    tgt.br = cornerDent(px, py, rect.width, rect.height)
    tgt.bl = cornerDent(px, py, 0, rect.height)
    tgt.inside = edgeProximity(px, py, rect.width, rect.height) * 0.5
    schedule()
  }

  const onEnter = (): void => {
    active = true
  }

  const onLeave = (): void => {
    active = false
    // 目标全部归零：光斑移出、四角弹回、光泽淡出
    tgt.x = -999
    tgt.y = -999
    tgt.tl = tgt.tr = tgt.br = tgt.bl = 0
    tgt.inside = 0
    schedule()
  }

  const bind = (): void => {
    const node = el.value
    if (node === null) return
    node.addEventListener('pointermove', onMove, { passive: true })
    node.addEventListener('pointerenter', onEnter)
    node.addEventListener('pointerleave', onLeave)
  }

  const unbind = (): void => {
    const node = el.value
    if (node === null) return
    node.removeEventListener('pointermove', onMove)
    node.removeEventListener('pointerenter', onEnter)
    node.removeEventListener('pointerleave', onLeave)
    if (frame !== 0) {
      cancelAnimationFrame(frame)
      frame = 0
    }
  }

  // 减动效有效值变化时动态挂/摘监听（用户在设置页切三档开关立即生效）
  onMounted(() => {
    const stop = watchEffectCompat(reduced, bind, unbind)
    onBeforeUnmount(() => {
      stop()
      unbind()
    })
  })
}

/** reduced 变 true → unbind；变 false → bind。见报告 §2.4 门 2。 */
function watchEffectCompat(
  reduced: Ref<boolean>,
  onEnable: () => void,
  onDisable: () => void
): () => void {
  // 实现用 vue 的 watch(reduced, ...)：immediate 时按当前值绑定/不绑定。
  // （执行 AI 直接内联到 useCardShine 里也行，别单独导出这个辅助函数。）
  throw new Error('由执行 AI 按上方注释实现（vue watch immediate）')
}
```

> 注：上面 `watchEffectCompat` 的占位是刻意的——执行 AI 应把这段逻辑用
> `watch(reduced, cb, { immediate: true })` 内联进 `useCardShine`，而不是照抄一个
> 抛异常的函数。其余代码可直接采用。**导出的两个纯函数（`cornerDent` /
> `edgeProximity`）是给单测用的**，实现时保持签名不变。

### 4.2 `base.css` 新增（全部追加在文件末尾「EP 细节对齐」之前，自成一段）

```css
/* ── 卡片玻璃光效（2026-09-30 设计执行报告）：鼠标跟随的边缘高光 + 四角内凹 ──
 * 三个生效门：精确指针媒体查询 / 减动效（JS 侧 useCardShine 摘监听）/
 * 指针在卡上。变量由 composables/useCardShine.ts 写入，CSS 只负责渲染。
 *
 * ⚠️ 命名：不叫 .k12-glass —— 那是 backdrop-filter 毛玻璃类（上方 L415 已占用）。
 * ⚠️ 本段所有 --k12-shine-* / --k12-dent-* 变量只在 :root 与这里出现一次
 *    （P-158：同一自定义属性两处定义会被静默覆盖）。
 * ⚠️ 边框/底色/投影配方一概不动 —— 光效是叠加层，皮肤唯一来源仍是
 *    .k12-card / SurfacePanel 的既有规则（visual-edges 守卫盯着的那些）。 */

:root {
  /* 光斑半径（径向渐变），决定「阳光」打多宽 */
  --k12-shine-radius: 190px;
  /* 边缘环带宽：压在 1px 边框上的发光细环 */
  --k12-shine-edge: 1.5px;
  /* 高光色：带学段色（accent 派生混白）——学段一换，光色自动跟着换；
   * 不写死 rgba，纪律与 --k12-shadow-* 相同（守卫 visual-edges.test.ts 的口径） */
  --k12-shine-bright: color-mix(in srgb, var(--k12-accent) 42%, #FFFFFF);
  /* 受压暗部：前景色派生，让内凹边缘读出「陷进阴影」 */
  --k12-shine-shade: color-mix(in srgb, var(--k12-fg) 18%, transparent);
  /* 内部光泽：白 wash，有效强度 = alpha × --k12-shine-inside(JS, ≤0.5) ≤ 8% */
  --k12-shine-wash: color-mix(in srgb, #FFFFFF 16%, transparent);
}

/* 挂载点：谁要效果谁加 .k12-shine（opt-in，不全局默认 —— 虚拟列表里卡片多，
 * 监听器按卡片计，让接入方自己决定范围）。需要 position: relative 放置叠加层。 */
.k12-shine {
  position: relative;
  /* 四角圆角 = 基础语义档 + 内凹量。--k12-shine-r 允许接入方覆盖基础档
   * （SurfacePanel 的 r-inset/r-control 档），默认跟卡片档。 */
  border-radius:
    calc(var(--k12-shine-r, var(--k12-r-card)) + var(--k12-dent-tl, 0px))
    calc(var(--k12-shine-r, var(--k12-r-card)) + var(--k12-dent-tr, 0px))
    calc(var(--k12-shine-r, var(--k12-r-card)) + var(--k12-dent-br, 0px))
    calc(var(--k12-shine-r, var(--k12-r-card)) + var(--k12-dent-bl, 0px));
}

/* 边缘环：mask 挖出「边框带」，两层径向渐变（亮环 + 受压暗部）都只画在带内。
 * inset: 0 而不是 -1px —— 卡片可能 overflow: hidden（SurfacePanel flush 档），
 * 出框 1px 会被裁。border-radius: inherit 让环实时跟随四角内凹。 */
.k12-shine::before {
  content: '';
  position: absolute;
  inset: 0;
  border-radius: inherit;
  padding: var(--k12-shine-edge);
  background:
    radial-gradient(
      circle 160px at var(--k12-shine-x, -999px) var(--k12-shine-y, -999px),
      var(--k12-shine-shade),
      transparent 60%
    ),
    radial-gradient(
      circle var(--k12-shine-radius) at var(--k12-shine-x, -999px) var(--k12-shine-y, -999px),
      var(--k12-shine-bright),
      transparent 70%
    );
  -webkit-mask: linear-gradient(#fff 0 0) content-box, linear-gradient(#fff 0 0);
  -webkit-mask-composite: xor;
  mask: linear-gradient(#fff 0 0) content-box, linear-gradient(#fff 0 0);
  mask-composite: exclude;
  opacity: 0;
  transition: opacity var(--k12-dur-state) var(--k12-ease-state);
  pointer-events: none;
  z-index: 1; /* 盖住卡面内容（含沙箱 iframe），但不接事件 */
}

/* 内部光泽（可选加强层）：低透明度白 wash 从光斑向内渗。
 * 对比度预算见报告 §2.3 —— 验收时盯 muted 小字，发糊就整层删。 */
.k12-shine::after {
  content: '';
  position: absolute;
  inset: 0;
  border-radius: inherit;
  background: radial-gradient(
    circle var(--k12-shine-radius) at var(--k12-shine-x, -999px) var(--k12-shine-y, -999px),
    var(--k12-shine-wash),
    transparent 65%
  );
  opacity: var(--k12-shine-inside, 0);
  pointer-events: none;
  z-index: 1;
}

@media (hover: hover) and (pointer: fine) {
  .k12-shine:hover::before {
    opacity: 1;
  }
}
```

**关于全局减动效兜底**：`base.css` 既有规则（`prefers-reduced-motion: reduce` 与
`[data-k12-reduced-motion='on']` 两块）会把所有 `transition-duration` 压到 0.01ms，
光效的淡入淡出自动失效——这正是想要的；但 rAF 驱动的变量写入它们收不掉，所以
JS 侧的 `useReducedMotion()` 摘监听是**主防线**，CSS 兜底是辅。两边都要有，
与 `useReducedMotion.ts` 文件头的纪律一致。

### 4.3 接入点改造（分两期，一期必做、二期可选）

**一期（必做）——内容页卡片：`SurfacePanel.vue`**

1. `defineProps` 加 `shine?: boolean`（默认 `false`，显式 opt-in）；
2. 根元素加 `:class="{ 'k12-shine': shine }"` 与 `ref="rootRef"`；
3. script 里：

```ts
const rootRef = ref<HTMLElement | null>(null)
// 只有显式开 shine 的实例才挂监听（enabled 逻辑在 composable 内部
// 由 reduced-motion 门控制；这里再叠加一个 props 开关）
watch(
  () => props.shine,
  (on) => { /* on: 绑定；off: 解绑 } },
  { immediate: true }
)
```

   实现时把 §4.1 的 `useCardShine` 扩一个 `enabled: Ref<boolean>` 参数即可
   （签名变为 `useCardShine(el, enabled?)`，默认 `enabled = true`）；
4. 三个圆角档类补基础档变量（`.sf--r-inset` 等各加一行）：

```css
.sf--r-inset { border-radius: var(--k12-r-inset); --k12-shine-r: var(--k12-r-inset); }
.sf--r-card  { border-radius: var(--k12-r-card);  --k12-shine-r: var(--k12-r-card); }
.sf--r-control { border-radius: var(--k12-r-control); --k12-shine-r: var(--k12-r-control); }
```

   ⚠️ 这三条规则体现在 `SurfacePanel.vue` 的 scoped style 里（它们本来就在那），
   加变量声明不算改皮肤配方，`visual-edges` 守卫不扫这个文件的四层规则；
5. 各页面接入：`<SurfacePanel shine>` 先在 **Quiz.vue / Knowledge.vue / Settings.vue**
   的主内容卡上开（这三页卡片少、静态，最适合首验收）。

**一期（必做）——对话内联卡片：四个卡片组件根元素**

`cards/AnimationCard.vue`（根元素 L615 `class="k12-card anim"`）、`QuizCard.vue`、
`CodingCard.vue`、`ProgressCard.vue`：根元素追加 `k12-shine` 类 + `ref` +
`useCardShine`。这四个组件根上就是 `.k12-card`，基础圆角档默认值正确，不需要
`--k12-shine-r`。

**二期（可选，默认不做）——对话消息条 `Chat.vue` 的 `chat__entry`**

虚拟列表里卡片多、每张挂监听有内存成本（虽然不 hover 时零 rAF）。等一期验收
通过后由用户拍板要不要铺。**执行 AI 不要顺手铺**。

### 4.4 单元测试（新建 `desktop/tests/card-shine.test.ts`）

仓库纪律：`node --test` + TS 禁 parameter property。两层：

1. **纯函数**（不挂 DOM）：`cornerDent` / `edgeProximity` 的边界——指针在角上
   得 MAX_DENT、超过 FALLOFF 得 0、中心对称性；
2. **守卫**（读文件断言，风格照抄 `visual-edges.test.ts`）：
   - `base.css` 里 `--k12-shine-bright` 必须从 `var(--k12-accent)` 派生
     （`color-mix` 正则，同守卫对 `--k12-shadow-edge-*` 的做法）；
   - `.k12-shine:hover::before` 的 opacity 规则必须包在
     `@media (hover: hover) and (pointer: fine)` 里；
   - `useCardShine.ts` 必须引用 `useReducedMotion`（防未来有人删掉减动效门）；
   - 全仓 `k12-glass` 与 shine 实现不得混用（防命名回收导致两个效果串台）。

## 5. 红线约束（违反 = 返工，逐条来自仓库现行规则）

1. **不动三件套**（D-106）：底色差 + 两支线 + 单侧投影的既有声明一字不改；
   光效是**叠加层**，`opacity: 0` 起步，无 hover 时视觉与现状完全一致。
2. **阴影/效果令牌唯一来源**：所有 `--k12-shine-*` 只在 `base.css` 的 `:root`
   定义一次（P-158 静默覆盖教训）；不写死 `rgba(0,0,0,…)`，一律 `color-mix`
   从 `--k12-accent` / `--k12-fg` 派生（学段换肤自动跟随，这是 `visual-edges`
   守卫对投影令牌的同等纪律）。
3. **不手改** `tokens.generated.css`；**不碰** `tokens.source.json`（改了色值就要
   重建后端动画皮肤 `server/scripts/build_animation_skins.py`，本需求不需要）。
4. **减动效三档**：JS 侧必须走 `useReducedMotion()` 的**有效值**；CSS 侧依赖
   既有全局兜底。减动效开启 = 效果整体关闭，不做降级形态。
5. **精确指针门**：hover 态样式必须包 `@media (hover: hover) and (pointer: fine)`。
6. **纯渲染进程**：不新增 IPC 通道、不进 6 事件词表、不碰主进程/sidecar
   （`check:docs` 通道数、architecture-guards 都不受影响才对）。
7. **性能红线**：`pointermove` passive；rAF 单例；收敛即停帧（不留常驻动画循环）；
   不用 `backdrop-filter` / SVG filter / `will-change`（最后一项会常驻合成层，
   卡片多的页面吃显存）。
8. **TS 单测禁 parameter property**（`constructor(private x)` →
   `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`）。
9. **字号/排版零改动**：本需求不碰任何 `font-size`、行高、间距 token。
10. **动画卡片 iframe 沙箱红线**（`AnimationCard.vue` 文件头三条）不受影响：
    叠加层 `pointer-events: none`，不拦截 iframe 的任何交互。

## 7. 验收标准

**机器判据（必须全绿）**
- `cd desktop && npm run typecheck` 零错误；
- `npm test`（含 `check:api` / `check:tool-schema` / `check:contrast --strict` /
  `check:docs` + 全部 node --test，含新增 `card-shine.test.ts`）零失败。

**视觉判据（`npm run dev` 真机走查，四条全过才算完）**
1. 指针贴卡片边缘移动：**最近的边缘**持续亮起带学段色的细环，光斑跟手无明显
   滞后（lerp 0.2 的跟随感约 100ms，比「卡」快、比「瞬移」柔）；
2. 指针贴近某个圆角：**只有该角**圆角变大内凹、边缘出现弱暗部；移到对角，
   凹陷平滑转移；
3. 指针离开卡片：光效与内凹约 150–200ms 内弹回原状，卡片回到与改造前
   **逐像素一致**的静态外观；
4. 边缘处的 muted 小字（角标、脚注）在光效扫过时不发糊；发糊 → 删 `::after`
   内部光泽层（其余不动），重走查通过。

**边界判据**
- 系统开减动效（或设置页三档开关拨到「开启」）：鼠标怎么晃卡片都毫无反应；
- 触屏/`pointer: coarse` 环境：无效果（代码层面监听就没挂）；
- 学段切换（小学低/高、初中、高中）：高光颜色随学段色自动变，无需改代码。
