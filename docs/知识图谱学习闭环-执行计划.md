## 0. 一句话

依赖图谱里选中一个知识点 → 点「开始学习这个知识点 →」→ **自动发一轮「学习计划」请求** →
对话里得到一份学习计划 → 对话底部出现**常驻的巩固双路**（去闯关练一练 / 现在考考我）。

## 1. 三条需求 → 差距

| # | 需求 | 现状 | 差距 |
| --- | --- | --- | --- |
| ① | 点击即跳转**并自动发送** | 只把一句话**预填**进输入框，学生还要自己按发送 | 改成真发一轮；必须走「显示文本 / wire 文本」双轨 |
| ② | 自动生成**学习计划** | 模型没有「学习计划」的格式与流程概念 | wire 里给结构化指令 + system prompt 增补一节计划纪律 |
| ③ | 学完后给**巩固入口** | 对话里没有任何这类操作区；但两条链路本身都现成 | 新增巩固操作区 + 计划会话状态；动作全部复用现有链路 |

## 3. 交互流程

```
① 依赖图谱：选中「循环结构」→ 检查器 → 点「开始学习这个知识点 →」
        │  chat.send(显示文本, wire文本)  +  ui.show('chat')        ← 不再预填
        ▼
② 对话页：学生气泡显示人话（「我想开始学「循环结构」，帮我安排一下学习计划」）
        │  wire：【学习计划】前缀 + kp_id + 计划结构指令（学生看不见）
        ▼
   模型（可调 rag_search 检索教材）产出计划：学习内容 / 时间安排 / 步骤 / 阶段目标，
   并在末尾口头引导「学完可以用下方的按钮检验」
        │  该轮 done → 前端按 requestId 认领为「计划轮次」→ planReady
        ▼
③ 巩固操作区出现（计划会话激活期间常驻）：
        路A「去闯关练一练」→  quiz.selectLevel(kpId) + ui.go('quiz')
        路B「现在考考我」  →  send(显示文本, wire文本) → generate_quiz → 答题卡就在对话里
```

## 4. ★ 需要你拍板的四个决策点

| # | 决策 | 我的建议 | 代价 / 备选 |
| --- | --- | --- | --- |
| D1 | **推翻**「点击只预填、不替学生消耗云端调用」 | 推翻。理由：一次点击换一份计划，是这个按钮存在的意义 | 每次点按钮都会消耗一次调用；实施时把 `prepareQuestion`/两处 `goLearn` 的注释改成新口径并记 D-xxx，防止后人「修」回去 |
| D2 | 「学完了」怎么判定 | **不做判定**：不新增事件种类（6 事件词表冻结），计划轮次 done 后巩固区**常驻**，学生自己决定何时点 | 备选是前端识别「我学完了」关键词 —— 更脆，不建议 |
| D3 | 巩固区的形态 | **对话流末尾常驻一条操作条**（只动 `Chat.vue`） | 备选「挂在计划气泡下方」语义更贴，但要再改 `components/ChatMessage.vue`（多一个文件、多一处插槽机制） |
| D4 | 两个入口是否都改 | **都改**（图谱 + 学习地图），同一个语义不能一处会发一处不会 | 只改图谱会让两个入口行为不一致 |

## 6. 每期的验收判据

- **一期**：`npm run typecheck` ✅；`node --test tests/plan-request.test.ts` 全绿；真机点一次按钮 → 消息**直接发出**（不必按发送键），学生气泡是人话，DevTools 里看不出 kp_id。
- **二期**：模型产出的是**计划形态**（有步骤/顺序，不是一段泛泛介绍）；重启后回看那条气泡**仍是人话**（翻译生效）。
- **三期**：计划轮次 done 后底部出现两个按钮；路 A 跳到闯关页且该关已选中；路 B 触发 `generate_quiz`，答题卡出现在对话里；切换会话后巩固区消失。
- **收尾**：`npm test` 全量 + `npm run guards:mutation`（本仓库纪律：改守卫/消息对后验「真的会红」）。
