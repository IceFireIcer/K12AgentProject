## 0. 基准：**正文 16px**（2026-09-18 整体抬升）

> 使用者是 **K12 学生**，会长时间盯着看。原来 14px 的中文在 1440 宽窗口上确实偏小 ——
> 阅读费劲、眼睛容易累，这是**用眼健康**问题，不是审美偏好。
> 所以整条阶梯一起抬了一档（不是只抬正文：只抬正文会让它顶到「次级正文」那一档，
> 层级差被吃掉，「标题比正文还小」会重新出现）。
> 容器尺寸跟着长：侧栏 248→264、顶栏 64→72、阅读栏 820→880。
> **行高** `--k12-lh-body` 1.7→1.75（字号变大后每行字数变少，行间距的绝对像素也变大，
> 1.75 让连续读三行的负担更轻 —— 长时间阅读的主要疲劳来源是**行间跳转**，不是单字大小）。

## 1. 字号阶梯：档位 = 用途，一一对应

写在 `src/renderer/src/assets/base.css` 的 `:root`（**唯一来源**，不要在页面里写 `font-size: 15px`）。

| token | 值 | 用途 | 反例（曾出错的地方） |
| --- | --- | --- | --- |
| `--k12-fs-hero` | 40px | 仅对话页空态问候 / hero 数字（全站唯一） | — |
| `--k12-fs-h1` | 32px | **页面身份行**（每页一条，全页最大视觉焦点） | 统计磁贴里的小数字不该用它 |
| `--k12-fs-h2` | 24px | 区块标题（当前关卡、分块标题、页面里的大分区） | — |
| `--k12-fs-h3` | 20px | 卡片 / 卡头标题、卡内小标题、抽屉标题、空态主信息 | 正文不要用它（正文 = body 16） |
| `--k12-fs-body-lg` | 18px | **仅顶栏页面名**（chrome）、重要引导文案 | 页面名不该比内容还重 |
| `--k12-fs-body` | 16px | 正文 | — |
| `--k12-fs-body-sm` | 14px | 次级正文、列表项、可读的键值、按钮文字 | — |
| `--k12-fs-caption` | 13px | meta、单位、脚注、主路径提示 | 这是 meta 的正确档位 |
| `--k12-fs-label` | 12px | **仅角标（≤4 字）** | ✗ id / 标签 / 关系 / 层级徽标 / 说明文字 |

> ★ 2026-09-27 按《前端界面设计优化建议报告》§1.1 重构：档位从 8 档改成语义化 9 档，
> 删掉 17px 这个异类（顶栏页面名并入 `body-lg` 18px），并给出明确倍率
> `body 16 → h3 20 (×1.25) → h2 24 (×1.5) → h1 32 (×2) → hero 40`。
> **旧名（micro/xs/sm/md/lg/title/xl/2xl）保留为别名一版**（迁移兼容层，下一轮删除）；
> 守卫在 `tests/design-tokens.test.ts`，变异条目 70–74。

**判据（阶段 B2）**：`--k12-fs-label`（旧名 micro）只允许出现在**角标语义**的元素上，两条出路任选其一：

1. **选择器名含角标词** —— `badge` / `chip` / `tag` / `pill` / `count` / `num` / `dot` / `step` / `idx` / `key` / `mark` / `level`。
2. **在声明 micro 的那条规则里显式写 `k12-mark`**，例如：
   ```css
   .chat__compat {
     font-size: var(--k12-fs-label);
     /* k12-mark：「跨学段兼容」是 5 字 chip —— 名字看不出是角标，标注给审计看 */
   }
   ```

其余一律用 `--k12-fs-caption` 起步。

> ⚠️ **为什么有第 2 条**：审计工具的第一版只用英文类名词表，于是
> `.qz__key`（选项字母 A/B/C）与 `.chat__compat`（「跨学段兼容」）这两个**真角标**
> 被判越界，被迫升级 —— 升完之后它们与相邻 meta 同权，
> 「这是角上的一个记号」这层意思**反而被抹掉**。**工具的判据在逼设计做坏事**，
> 所以改判据、留一条可 grep 的出口，而不是改设计去迁就工具。

> ⚠️ **抬升阶梯时三条关系必须重新核对**（最容易破的就是它们）：
> ① 顶栏页面名（`body-lg` 18px）**严格小于**内容区身份行（`h1` 32px）；
> ② 正文（`body` 16px）严格大于任何 meta（`caption` 13px / `label` 12px）；
> ③ `label` 只给 ≤4 字角标，其余一律 `caption` 起步。

> 历史教训：11px 曾是全站**最高频**字号。用它写 id、关系、说明，
> 结果 meta 与角标同权、层级整个塌掉。

## 2. 阅读节奏：四档（8 点网格）

写在 `base.css`（**唯一来源**）。

| token | 值 | 用途 |
| --- | --- | --- |
| `--k12-gap` | 16px | **卡片之间**（并列卡片） |
| `--k12-gap-block` | 24px | **块之间**：正文 → 步骤 → 要点 → 引用 → 卡片 |
| `--k12-gap-section` | 40px | **章节之间**：页面里的大区块分隔 |
| `--k12-gap-msg` | 32px | **消息之间**：一轮对话是一个单元 |

> ★ 2026-09-27 按优化报告 §1.2 调整：基础间距阶梯改为 **4/8/12/16/24/32/40/48**（严格 8 点网格，
> 20px 不再是间距档），语义间距从三档扩到四档（block 20→24、msg 36→32、新增 section 40）。
> 守卫在 `tests/spacing-grid.test.ts`，变异条目 75–76。

**段落之间没有 token**：行高 1.7 自身就产生了足够停顿，不要再加 margin。

> 依据：眼睛靠**间距差**分辨层级，不靠字号差。改造前对话页实测 ——
> 消息间距 20px 比段落的视觉间距（35.8px）还小，块间与段落同为 12px，
> 四个层级里三个挤在同一个值上。这是**节奏**问题。

## 3. 页面身份行 + 主路径提示

用共享组件，**不要各页自己写**（否则会立刻散开成 18/20/22）：

```vue
<PageIdentity
  main="这一页在讲什么"      <!-- 不是重复顶栏的页面名！ -->
  meta="统计口径 / 数据来源"  <!-- 可选 -->
  hint="先做什么，再做什么"    <!-- 主路径提示（D1），内容页必填 -->
/>
```

- `main` 落到 `.k12-identity__main`（24px/650），`hint` 落到 `.k12-path`（13px/muted）。
- **对话页例外**：不插身份行（正文才是内容），身份由空态 hero 承担。
  但空态 hero 的字号必须 ≥24px（它要压过顶栏 17px）。
- 规格页（`views/system/*`、`views/dev/*`、404）**不加**身份行与主路径提示。

**主路径提示示例**（写"怎么做"，不写"这是什么"）：

| 页面 | hint |
| --- | --- |
| 教材知识库 | 先按学段筛，再点行看分块详情 |
| 依赖图谱 | 先选根节点，再沿边看前置 / 后继 |
| 学习档案 | 先看 hero 的掌握度走向，再看下面三段叙事 |
| 闯关练习 | 先选关卡，再逐题作答 |
| 动画讲解 | 先挑模板，再在舞台上播放 |

## 4. 焦点规则（最高优先级）

> **内容区的最大字号元素必须是主对象，不能是 chrome。**

- 顶栏页面名 = 17px（chrome，退后）。
- 每个内容页内容区最大 ≥ 24px，且**严格大于** 17px。
- 卡片标题 18px、正文 16px 均在顶栏之上或附近，都不得**等于或大于**身份行。

守卫：`node scripts/audit-layout.mjs`（断言 7b）。

## 6. 动效：本版为零

**不新增** `transition` / `animation` / `@keyframes` 装饰性动效。
只保留状态本身（`:hover` / `:focus-visible` 的颜色与描边变化），
且过渡必须用 `--k12-dur-state` + `--k12-ease-state`（不要自己写时长）。

> 目的：让设计只能靠材质、留白、字体层级与颜色站住 —— 动效会掩护静态缺陷。

### 6.1 减少动效（2026-09-27，优化报告 §3.3 的三档开关）

**两个层次各管一半，缺一不可**：

| 层 | 谁负责 | 落点 |
| --- | --- | --- |
| CSS | `base.css` 的两块规则 | 媒体块 `@media (prefers-reduced-motion: reduce)` 带 `:root:not([data-k12-reduced-motion='off'])`；属性块 `[data-k12-reduced-motion='on']`（内容与媒体块一致） |
| JS | `useReducedMotion()`（**有效值**）/ `scrollIntoViewRespectingMotion()` | 滚动、定时器、动画沙箱（`server/resources/templates/_shared/runtime.js` 读自己的媒体查询并把时长归零） |

**三档的语义（设置页「外观主题 → 减少动效」）**：

| 档位 | `<html>` 属性 | 语义 |
| --- | --- | --- |
| 自动（默认） | `auto` | 跟随系统（媒体查询说了算） |
| 开启 | `on` | 强制减动效（系统没开也生效） |
| 关闭 | `off` | 完整动效（**覆盖系统偏好**，否则第三档是假选项） |

状态的唯一真相是 `stores/reducedMotion.ts`（`localStorage` 键 `k12.reducedMotion`）；
写它 = 同时写属性 + 落盘，所以「点一下立刻生效」是同一条链路上真的发生的事。

## 7. 操作位置（阶段 D2）

| 位置 | 承载什么 |

| `PageActions`（页面顶部，吸顶） | **页面级**操作：导出、刷新、重建索引 |
| 卡片头 | **对象级**操作：这一条的展开 / 重命名 |
| 卡脚 | **状态提交**：保存 / 提交 / 运行 |

吸顶实现见 `PageActions.vue`；各页只需覆盖两个变量对齐自己的内边距：


## 8. 可达性：模态必须收束焦点

抽屉 / 对话框 / 浮层打开时必须：**焦点移入 → Tab 在层内循环 → 关闭归还触发元素**。

```ts
const panel = ref<HTMLElement | null>(null)
useFocusReturn(panel, () => open.value)
```

配合既有的 `useEscape`（Esc 关闭）一起用。纯展示型浮层（hover 菜单）不要用。

### 8.1 页面级 Tab 顺序（优化报告 §3.1：这是"未文档化"的那一格）

焦点沿 DOM 顺序走，**规定顺序**如下（前三段都在外壳里，与页面无关）：

1. **「跳到主内容」**（`.skip-link`，`AppShell.vue`）—— 整页第一个可聚焦元素，平时视觉隐藏、聚焦时显形；
2. 侧栏导航（`.sb__nav` 里的页面按钮）→ 侧栏底部状态；
3. 顶栏控件（模型 chip → 学段 chip → 窗口按钮）；
4. 内容区里的 `PageActions`（页面级动作，如导出 / 刷新 / 重做本关）；
5. 内容区主体（自上而下，按各页自己的 DOM 顺序）；
6. 浮层 / 模态（打开时焦点移入，见 §8 的契约）。

**为什么第 1 条要有**：不改的话，键盘用户每次进页都要先 Tab 过侧栏 8 个按钮 + 顶栏 4 个控件
才够得到正文；跳转链接把这一步压成一次 Tab。目标容器 `#k12-content` 带 `tabindex="-1"`，
所以锚点跳转后**焦点真的落进内容区**（只写 `href` 会滚动但焦点仍在链接上）。

### 8.2 非模态浮层：移入 / 归还，但**不锁 Tab**（2026-09-27 补）

| 浮层类型 | 判据 | 契约 |
| --- | --- | --- |
| **模态**（对话框、原文抽屉） | 有 `aria-modal="true"` | `useEscape` + `useFocusReturn(panel, isOpen)`：移入 → **Tab/Shift+Tab 层内循环** → 归还 |
| **非模态**（可拖拽追问窗、只读机制浮窗） | 只有 `role="dialog"` | `useEscape` + `useFocusReturn(panel, isOpen, { trap: false })`：**只移入与归还，不接管 Tab** |

> 非模态为什么不能锁 Tab：追问窗要能"一边看动画一边问"，把焦点锁在窗里学生就回不到页面。
> 这条是 2026-09-27 实测补的缺口（两个浮窗当时只有 Esc、没有焦点契约），守卫见
> `tests/keyboard-a11y.test.ts` 第 4 条。

### 8.3 焦点环（`focus-visible`）

全站基线在 `base.css`：`*:focus-visible { outline: 2px solid var(--k12-accent); outline-offset: 2px }`
（**低特异度**，Element Plus 自己的规则仍可覆盖，不跟组件库抢皮肤）。
需要"换形态表达"的元素在各自组件里覆盖：列表项用背景、图谱节点用描边、卡片用内描边。
