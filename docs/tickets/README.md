## 每次开工前

1. 扫一眼 `docs/业务陷阱清单.md` 中对应模块的陷阱与「业务验收口径」（票尾已标注相关条目）。
2. 确认该票 `Blocked by` 全部完成；关卡类票未过关不进下一阶段。
3. 收工时：勾选验收条件、追加 `## 进度`、**当天做一次 git 提交**（`type(scope): 中文摘要`），并留 30 分钟报告素材。

> **常驻守卫**（每次改动都跑，落 `desktop/tests/architecture-guards.test.ts`）：
> 渲染进程无直连 sidecar 的 HTTP、渲染进程无 Node 内置模块、Electron 侧无原生数据库模块、
> **学生代码绝不在主进程执行**、契约与 `openapi.json` 一致、6 事件词表冻结（`delta | citation | payload | blocked | done | error`）、
> 聊天事件流必须经 preload 白名单 IPC 通道送达（**守卫一律正向断言**，不写「禁止某历史实现」式断言）、
> Tool 名 → 事件 `kind` 映射完整登记。
