### 2. ★ 孤儿进程与端口占用（实测，直接喂给票 02）

本票验收时真实撞到了一次风险 #4：

1. 手动起 sidecar 做探活，用完 `kill` 掉 —— **端口 8756 仍是 LISTENING**。
   原因：`uv run python -m app.main` 里 `uv` 是父进程、python 是孙进程，
   `kill` 只终止了 `uv`，**python 孙进程活成了孤儿**。
2. 随后启动 Electron：它 spawn 的 sidecar 绑定 8756 失败，**exit code=3**，
   应用显示「启动失败：sidecar 进程意外退出（code=3）」。

两个必须带进票 02 的结论：

- **杀进程树不是可选优化**：必须 `taskkill /PID <pid> /T /F`（`/T` 是关键）。
- **必须用握手自报的 python pid，不能用 `child.pid`**：实测 UI 显示的 `进程 PID` 是 4508（`uv` 包装器），
  而真正监听端口、需要被杀的 python 是 **44156**（孙进程）。只杀 4508 会留下孤儿 + 占住的端口。
- **附带的好消息**：失败路径是**对的** —— 没有白屏，给出了可读中文错误（执行文档 §7.4 第 3 条的要求）。

### 3. stdout 从第一天就是干净的

探活期间确认 sidecar 的 **stdout 为空**，日志（含中文）全部落在 stderr。
这是刻意从第一天做对的：`uvicorn.run(log_config=None)` + 根 logger 钉在 stderr。
票 02 的握手通道因此不会被任何库输出污染，**不需要回头清理**。

`GET /health` 实测响应（camelCase，与 `desktop/src/main/bridge/client.ts` 的 `HealthPayload` 一致）：

```json
{"status":"ok","version":"0.1.0","embedderReady":false}
```

`embedderReady=false` 是**当前应有状态**（模型未下载），且不影响 sidecar 判活 —— 与设计一致。

### 5. 留给票 03 的一处架构注意（来自脚手架实现）

当前主进程产物是 **CJS**（`package.json` 未设 `"type": "module"`），以保证 preload 产物路径
`join(__dirname, '../preload/index.js')` 与 `__dirname` 都成立。
但 **Pi 是纯 ESM**：票 03 接入时，`externalizeDepsPlugin()` 会把 Pi 变成 `require()`，
**必然失败**。票 03 需要在「主进程产物切 `format: 'es'`」与「不 externalize Pi」之间做选择并实测。
**这条不是猜测，是必须提前知道的坑** —— 记在这里，免得到时按「依赖装错了」去排查。
