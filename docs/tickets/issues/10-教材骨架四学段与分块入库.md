# 10 — 教材骨架四学段 + 分块入库

**What to build:** 四学段 `knowledge/` 骨架（人工定主线骨架 + AI 批量填充 + 抽检清单）、固定元数据格式、`build_kb.py` 一键建 `kb.sqlite`（chunk + 向量 + FTS5）。为什么在这个顺序：它**只依赖 01**，与 Pi 主线完全解耦——是单人开发下唯一的并行机会，也是 11（RAG）的唯一前置。**内容编写耗时失控是拖垮全盘的头号风险**：本票只求骨架成型与入库链路正确，四学段做深与全量抽检归 23。

**Blocked by:** 01 双端脚手架与依赖基线

**Status:** ready-for-agent

- [ ] `server/knowledge/{primary-low,primary-high,junior,senior}/` 四学段目录均有内容，**每学段至少 8–12 个知识点**；每篇 Markdown 带元数据（front-matter 或同名 `.json`），字段与 §8.3 DDL 严格对齐（**元数据字段随手改会让建索引直接报错**）
- [ ] chunk 元数据 schema 固定：`chunk_id, text, embedding, grade_level, chapter_title, section_title, knowledge_point, content_type, parent_chunk_id, token_count`；构建后断言**无空字段**
- [ ] 节级 chunk 300–600 token，超长拆分；父子 chunk 就位（子块检索、命中后回父块作上下文）
- [ ] 学段错位检查：低学段文本不含「算法」「特征向量」等超纲术语，高中学段不出现「小朋友」类错位语气；用术语文表脚本检查并输出报告（跨学段复用必须**改写**而非搬运）
- [ ] `manifest.json` 的依赖关系每条 `from` / `to` 都能在知识点表里找到；**悬空引用报错并中止，不静默跳过**
- [ ] `server/app/store/` 落地 `kb.sqlite` 的连接 + 幂等迁移器（`schema_version`）+ 仓储；`server/scripts/build_kb.py` 一键建库
- [ ] **建索引幂等**：脚本先清表再写，连续执行两次 chunk 行数完全相同（否则调试期数据翻倍）
- [ ] `chunk_vec USING vec0(embedding float[512])` 的 rowid **显式取 `chunk.rowid`**（错位会导致检索结果张冠李戴）；512 维从 `server/app/config.py` 的常量取，**不散落硬编码**（升级 bge-base 768 维时要同步改 vec0 维度并重建索引）
- [ ] `chunk_fts USING fts5(text, content='chunk', content_rowid='rowid', tokenize='trigram')`——**默认分词器不支持中文，必须 trigram**
- [ ] embedding 写 BLOB 用 `dtype='<f4'`（小端一致），读取侧按同端序还原
- [ ] `server/scripts/fetch_embedding_model.py` 幂等拉取 `BAAI/bge-small-zh-v1.5`（约 90MB，落 `server/resources/models/fastembed/`，**不入 git**）；模型缺失时 `build_kb.py` 明确报错而不是静默产出空向量；`/health` 的 `embedder_ready` 如实反映
- [ ] 提交一次 + 报告素材一条：教材为何用「人工骨架 + AI 填充 + 抽检」而不是 PDF 解析（链路更短更可控，且避开 AI 幻觉的不可控面）
