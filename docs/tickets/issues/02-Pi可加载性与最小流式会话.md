# 02 — Pi 可加载性 + 最小流式会话

**What to build:** 在**不接 UI** 的前提下，证明 Pi Agent SDK 能真正跑起来并拿到大模型的流式回复。这一步刻意把「运行时版本问题」与「打包问题」分离——先确认能装、能跑，再去撞打包。

本票原本要裁决「Electron 内置 Node 是否满足 Pi 的 `engines`」。

> **该裁决已完成（2026-09-16 实测，勿重开）**：Electron 44.4.1 内置 **Node 24.21.0**（Chrome 152），
> 满足 Pi `0.85.1` 的 `engines.node >= 22.19.0`。**不需要降 Pi 到 `0.74.2`，也不需要评估升级 Electron 的成本。**
> 本票只需确认实际安装的 Electron ≥ 44。

**Blocked by:** 01 — 恢复代码与数据基线

**Status:** ready-for-agent

- [ ] 安装 Pi 并锁定 `^0.85.1`（0.85.0 在 Electron 中会崩）
- [ ] 确认实际安装的 **Electron ≥ 44**（低于 44 才需要处理 `engines` 问题）
- [ ] 用 `createAgentSession` + `ModelRuntime.create({ authPath, modelsPath })` 跑通最小会话，配置指向**本应用自己的目录**，不读写 `~/.pi/agent`
- [ ] 配置 DeepSeek（含自填 BaseURL / ModelID 的通道），能拿到**流式**回复
- [ ] **同时设置 `systemPromptOverride`**，确认最终 system prompt 中不含本机安装路径
- [ ] 记录实际导入图（包根导入拖入了什么），为下一票的打包风险提供事实依据
- [ ] 写一个可重复执行的冒烟脚本，后续回归可直接复用
