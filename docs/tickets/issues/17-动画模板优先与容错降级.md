# 17 — 动画模板优先与容错降级

**What to build:** 让动画「几乎不会失败」：6–8 个内置模板覆盖主要知识点，LLM 只做「选模板 + 填参数 + 写文案」，自由生成仅作模板未命中时的补充路径；产出经校验，不合格则重试 ≤3，仍失败就降级为 `fallback_text` + 静态 SVG。**重试逻辑必须写在 Tool 的 `execute()` 内部**——`tool_execution_end` 是只读通知，回写不了任何结果。

**Blocked by:** 16（动画沙箱 + RPC 协议 + nonce 资源托管）

**Status:** ready-for-agent

- [ ] `server/resources/templates/` 下 6–8 个动画模板落位，至少覆盖：排序、神经网络、决策树、梯度下降、循环、变量；每个模板 = 参数化的自包含 HTML 片段 + 参数 schema
- [ ] 默认路径 = 模板命中：LLM 只输出「模板 id + 参数 + 文案」，TS 侧不做自由生成，`AnimationPayload.source == "template"`（自由生成仅在未命中时触发，此时 `source == "generated"`）
- [ ] `AnimationPayload` 六字段齐全且语义正确：`concept, html, duration_ms, fallback_text, fallback_image, source`；`fallback_text` 非空、`fallback_image` 为可用 SVG dataURL，否则视为不合格
- [ ] 校验器在 `execute()` 内先跑：检查 HTML 内联了动画库、无外部 URL、含 `ready` 上报、结构可解析；不通过即进入重试
- [ ] 重试**硬上限 3 次**（陷阱：重试无上限烧额度），计数用 Extension 内 `Map<toolCallId, retryCount>`——**不放 State、不依赖任何事件回写**（`tool_execution_end` 只读）
- [ ] 3 次仍失败 → 降级为 `fallback_text` + 静态 SVG，作为**正常 payload** 下发（走 `payload` 事件），不发 `error`；界面不白屏，轨迹里标 `degraded`
- [ ] **人为注入错误演练**（业务验收口径）：在某个模板里插一行 `throw new Error("boom")` → 观察到重试与最终降级；留证据（降级后的界面截图 + 轨迹片段），**演练后把注入删掉并再跑一次确认恢复**
- [ ] 模板内**不内联任何 CDN**（陷阱：沙箱断网白屏）：动画库与依赖从本地读取后内联进 HTML 字符串，`grep -Ei "https?://|unpkg|jsdelivr|cdn"` 对 `server/resources/templates/` 与生成的 HTML 均零命中
- [ ] **凭据不进 HTML**：生成的 HTML 内不得出现 API Key、baseURL、本机绝对路径；加一条测试或扫描脚本断言（凭据只存在于主进程内存/本地配置）
- [ ] 模板未命中场景也有兜底输出（自由生成失败 → 同上降级链），用一个刻意编造的 kp 实测
- [ ] 6–8 个模板逐个手测可播放（每个模板至少一张截图），避免「模板写了但跑不起来」
- [ ] 动画生成耗时可控：记录模板命中路径与自由生成路径各自的端到端耗时（模板命中应在秒级），数值记入票尾
