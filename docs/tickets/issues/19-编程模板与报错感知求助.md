# 19 — 编程模板与报错感知求助

**What to build:** 把编程从「能跑代码」做成「会教」：按知识点预置代码模板（排序 / 决策树 / 神经网络，含 TODO 标记），运行报错自动翻译成面向学生的中文提示，学生可手动求助，连续失败 3 次后主 Agent 主动介入，`CodingHint.level` 逐级加深。**提示的价值在引导，不许直接给答案。**

**Blocked by:** 18（Monaco + Pyodide Worker 隔离）

**Status:** ready-for-agent

- [ ] `get_code_template` Tool + `server/app/routes/code.py` + `server/resources/templates/` 三处打通，返回 `CodeTemplate{kp_id, language:"python", scaffold, expected_behavior}`，`scaffold` 含明确的 `TODO` 标记
- [ ] 至少 3 组模板落位并逐个实测「填完 TODO 即可通过」：排序、决策树、神经网络（各留一份填空前后可运行的证据）
- [ ] 模板离线可用：断网时进入编程卡片仍能取到模板（本地文件读取，不经 LLM）
- [ ] **报错感知**：把 Pyodide 的 traceback 解析成面向学生的中文反馈（`CodeEvaluation.feedback`），至少覆盖 4 类常见错误——缩进错误、名字未定义、类型错误、索引越界；每类留一条「原始报错 → 中文反馈」样例
- [ ] 手动求助按钮 → `get_coding_hint` 返回 `CodingHint{level, hint}`，`level` 从 1 起逐级加深 1→2→3，且同一 kp 内不会跳级
- [ ] **不直接给答案**（陷阱：直接给答案）：level 1 只指方向、level 2 给结构性提示、level 3 才贴近答案骨架；三条 hint 文本人工过一遍，贴进票尾
- [ ] **连续失败 3 次主动介入**：失败次数阈值作为常量集中定义（默认 3），达阈值后主 Agent 主动在对话流里插一条引导——**用既有对话输出，不新增第 7 个事件类型**
- [ ] 失败计数按 kp 与轮次隔离，答对后清零；换到下一个知识点时不带上一轮的计数（写一条断言或可复现步骤）
- [ ] 端到端演示（§15 的 5:30–7:00 环节）走通：写错代码 → 报错提示 → 点求助 → 按提示改对 → 运行成功；留 4 张连续截图
- [ ] `evaluate_code` 与 `get_coding_hint` 的结果经 `TOOL_TO_KIND` 映射为 `kind: "coding"` 的 `payload` 事件，前端编程卡片按 `kind` 分发渲染
- [ ] 断网演练：拔网后模板、报错提示、分级求助仍可用；LLM 相关路径不可用时走 `error` 事件（`degraded: true`）而非崩溃
- [ ] `npm run typecheck` 与契约 `--check` 通过
