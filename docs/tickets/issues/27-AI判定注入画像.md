# 27 — AI 判定注入画像（`buildJudgePrompt` 追加 persona）

**What to build:** 把 `profile_tags` 的**白名单投影摘要**注入第二层学段判定的 `buildJudgePrompt`，
让判定手里有「学生自己说的年级 + 系统观察到的风格」，解决 D-073 那个老问题（高中生提问也很朴素、判不出来）。
改动**全在主进程**，不碰契约、不碰后端、不新增 HTTP。

**Blocked by:** 25（标签体系地基）

**Status:** ready-for-agent

> 本票是票 26 的一部分，**单列以便独立验收**：即使五问 UI 还没上线，只要 `profile_tags` 有行，
> 判定用的 persona 摘要就应当生效。

- [ ] `Layer2Judge` 的入参加 `persona?: string`（可选，缺省时行为与旧版**逐字节一致**）
- [ ] `buildJudgePrompt` 多接 `persona`，并**追加在末尾**（不插进既有段落中间，避免打乱已有前缀缓存布局）
- [ ] 注入内容**只来自白名单投影**：`source=declared` 与 `source=observed` 分组展示，observed 带置信度；
  字段集合 ⊆ `LLM_VISIBLE_TAGS`（守卫 G-C / G-A）
- [ ] ★ **不注入**：掌握度明细、错题清单、老师/家长说过的话 —— 对判学段没帮助，只会稀释 prompt
- [ ] 画像块**顺序固定、不带 `ts` / 相对时间**（D-032 / P-163）；块内不放任何每轮会变的量
- [ ] `runtime.ts` 在调 judge 前取一次 summary，**与已有 profile 预取并行**，不新增 HTTP 请求
- [ ] persona 摘要来源是**后端投影后的标签**，不是原始 Q&A；概括产出的标签在写库时已过白名单，**读时再过一次**
- [ ] `memory_switch=0` / `parent_consent=0` 时摘要为空（闸在写/读两层，G-F / G-G）
- [ ] 引导模式下**不注入画像块**（`ONBOARDING_DISABLED_SECTIONS` 含 `profile-block`）
- [ ] 验收：同一段朴素提问，注入 persona 前后 `suggestedGrade` 的变化可复现；无画像时与旧版行为一致；
  provider / HTTP 调用计数不因本票增加
- [ ] `npm run typecheck` 通过（契约面一个字没改，`check:api` 不受影响）
