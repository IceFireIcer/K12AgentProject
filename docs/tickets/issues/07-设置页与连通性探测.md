# 07 — 设置页 + 连通性探测

**What to build:** 设置页可填「供应商名称 / BaseURL / APIKey / ModelID」四项并**真实探测连通性**，配嵌入配置三选一；配置落 `userData/config.json`，API Key 仅本地、不回显明文、不入日志。为什么在这个顺序：它只依赖 05 的 IPC 通道，与 06 的对话链路并行（06 先用 config.json 手填跑通）；它解阻塞 23 的最终打包（未配好供应商不能算可交付）。

**Blocked by:** 05 IPC 事件通道 + preload 白名单

**Status:** ready-for-agent

- [ ] `desktop/src/renderer/src/views/Settings.vue`：四项自填 **供应商名称 / BaseURL / APIKey / ModelID**（赛题硬要求，**不得写死 DeepSeek**，必须支持下改供应商）；另加嵌入配置 `EmbeddingConfig.mode` 三选一（`local_fastembed` / `cloud_api` / `none`，选 `cloud_api` 时出现 baseUrl / apiKey / modelId 三栏）
- [ ] 链路为 渲染进程 → IPC（`ipc/channels.ts` 白名单）→ 主进程 `bridge/client.ts` → `PUT /api/settings`；`server/app/routes/settings.py` + `settings_store.py` **原子写** `userData/config.json`（临时文件 + rename，避免半写坏配置）；渲染进程不直连 HTTP
- [ ] API Key 仅本地：不写日志、不上传、UI 只显示掩码；**掩码语义 = 未修改则保留原值**——用户没动这一栏时不得把 `******` 写回磁盘（自测：保存两次后 Key 仍可用）
- [ ] `POST /api/settings/probe` 做**真实连通性探测**（`GET /models` 或发一条 1-token 请求），返回 `{ok, message}`；失败原因（401 / 连接超时 / DNS / 404）**可读回显到设置页**，不是只吐 `false`
- [ ] **BaseURL 规范化必须显式约定**：默认填 `https://api.deepseek.com/v1`（OpenAI 兼容习惯），而 Pi 内置 DeepSeek provider 是 `https://api.deepseek.com`（**无 `/v1`**）——两种形式都要探测通过，并把该差异写进设置页提示文案；**不允许出现「默认值能跑、用户改一下就连不上」**
- [ ] 探测与保存解耦：探测失败给出警告但仍允许保存（离线场景可用），探测结果不静默吞掉
- [ ] 日志脱敏过滤器**保留 `%s` / `%(name)s` 占位符**（无脑把 `record.msg` 擦成 `***` 会让 `getMessage()` 抛 `TypeError: not all arguments converted during string formatting`）；用一条带参数的日志写单测验证
- [ ] `GET /api/settings` 读回与磁盘一致（关掉重开窗口仍在）；Key 读回时仍是掩码
- [ ] 截图两张（探测成功 / 探测失败回显）存入报告素材；`npm run typecheck` + `node --test` 全绿；提交一次
