## 进度

### ✅ 已交付（提交 `b72fa90`）

`server/app/settings_store.py` 原子写：**临时文件与正式文件同目录** → `fsync` → `os.replace`，
不留残留临时文件。JSON 损坏时原文件改名为 `config.json.corrupt-<UTC 时间戳>` 后继续启动（设置页坏掉不该让整个应用起不来）。

**掩码语义（已实测）**：提交空值或提交回显的掩码**不会抹掉**已存的 Key；只有显式「清除」才真的写空。
`GET /api/settings` 读回仍是掩码。

**探测用标准库 `urllib`**（`server/app/routes/settings.py`），因此 `pyproject.toml` 一行没改
（`httpx` 只在 dev 组）。

★ **探测矩阵（实测）**：

| 场景 | 结果 |
| --- | --- |
| `/v1` 形式正确 | `ok` |
| 缺 `/v1` | 可读 404 文案，**直接给出该替换成哪个 URL** |
| Key 错误 | 401 文案 |
| 端口无人监听 | 「连接被拒绝」，**2.0s** 返回 |
| 黑洞地址 | 「连接超时」，**3.0s** 返回 |

**决策：什么都「不规范化」，探测的就是将来保存下来的那个地址。**
理由见 `docs/report-material/decisions.md` 的 **D-022**：OpenAI 兼容网关里两种写法都可能才是对的那个，
静默改写会重新制造「默认值能跑、用户改一下就连不上」这个故障。

`server/tests/test_settings_store.py` 等 **40 条测试**通过。

### ✅ 补强交付（2026-09-17）：供应商预设 + 拉取模型 + 设置真正生效

**起因**（两处实测故障，均为「看起来能用、一按就炸」）：

1. **默认 ModelID 不存在**：契约默认 `deepseek-chat`，而 Pi 内置 deepseek 目录只有
   `deepseek-v4-flash` / `-vision-exp` / `-pro` → `getModel()` 返回 `undefined` → 首轮对话必炸。
2. **设置与 Pi 从未接上**：设置写 `config.json`（Python 管），
   Pi 读 `students/<id>/pi-agent/agent/models.json`（TS 管）；
   且旧 `ensureModelsJson()` 是「存在就一个字节都不动」，首轮写下的值成了死值 →
   **设置页改完、重启应用，Pi 用的还是旧值**。

**补强后的链路**：

```
设置页（预设下拉 / 拉取模型 / 四项手填）
  → IPC → 主进程 → PUT /api/settings → config.json（原子写，Key 明文仅本地）
                                    ↓
主进程启动先读：GET /api/settings/runtime（含明文 Key，token 鉴权，**渲染进程无此通道**）
  → createChatRuntime → writeModelsJson（由设置派生）→ setRuntimeApiKey（只进内存）
                                    ↓
保存设置后：热切换 applyLlmConfig()（改 provider/模型/Key，**对话历史保留**）
            失败则销毁会话 → 下一条消息按新配置重建（仍然生效）
```

**新增能力**：

| 能力 | 位置 | 说明 |
| --- | --- | --- |
| 供应商预设下拉 | `Settings.vue` + `GET /api/...` 之外的「预设」通道 | Pi 内置 40 个 provider 的端点与模型清单，**离线可用**（`ModelRuntime.create({modelsPath:null})`） |
| 拉取模型 | `POST /api/settings/models` + `settings:fetch-models` | 端点实时清单与 Pi 预设**合并去重**，两个来源分开标注；端点失败也仍有预设候选 |
| `providerId` | 契约 `LlmConfig` / `LlmConfigIn` / `StoredLlm` | Pi 的 provider id；与纯显示的 `providerName` 分工。入参 `None`/空串 = **占位即保留** |
| 运行时配置接口 | `GET /api/settings/runtime` | 含明文 Key，**仅主进程**（G13 守卫断言前端无入口） |
| 模型回落 | `resolveModelForProvider()` | 设置的模型不在目录里 → 回落该 provider 第一个可用模型 + 可读日志，**不抛** |

**三条实测坑**（详见 `pitfalls.md` P-048…P-051）：

- **P-048** 默认值与外部目录不一致（默认值是跨边界的契约，需核对）；
- **P-049** 两侧单测全绿而链路是断的（跨层需要有端到端断言）；
- **P-050** 只读学段徽章**早于 sidecar** 建会话 → 设置本次运行内永不生效（顺序假设错误）；
- **P-051** 热切换只改了「谁发请求」，门禁仍读过期快照 → 出现「Key 配好了却说没配」。

**验收记录（真机，非单测）**：

| 场景 | 结果 |
| --- | --- |
| 冷启动（**中途不碰设置页**） | 日志 `已补上启动时没读到的设置：provider=zai model=glm-5-turbo` —— 启动竞态自愈生效 |
| 设置页切预设（deepseek → zai） | 端点与模型名自动带出，`dirty` 置位，候选 chips 同步换成 7 个 zai 模型 |
