# 07 — 设置页 + 连通性探测

**What to build:** 设置页可填「供应商名称 / BaseURL / APIKey / ModelID」四项并**真实探测连通性**，配嵌入配置三选一；配置落 `userData/config.json`，API Key 仅本地、不回显明文、不入日志。为什么在这个顺序：它只依赖 05 的 IPC 通道，与 06 的对话链路并行（06 先用 config.json 手填跑通）；它解阻塞 23 的最终打包（未配好供应商不能算可交付）。

**Blocked by:** 05 IPC 事件通道 + preload 白名单

**Status:** ready-for-human

- [x] `desktop/src/renderer/src/views/Settings.vue`：四项自填 **供应商名称 / BaseURL / APIKey / ModelID**（赛题硬要求，**不得写死 DeepSeek**，必须支持下改供应商）；另加嵌入配置 `EmbeddingConfig.mode` 三选一（`local_fastembed` / `cloud_api` / `none`，选 `cloud_api` 时出现 baseUrl / apiKey / modelId 三栏）
- [x] 链路为 渲染进程 → IPC（`ipc/channels.ts` 白名单）→ 主进程 `bridge/client.ts` → `PUT /api/settings`；`server/app/routes/settings.py` + `settings_store.py` **原子写** `userData/config.json`（临时文件 + rename，避免半写坏配置）；渲染进程不直连 HTTP
- [x] API Key 仅本地：不写日志、不上传、UI 只显示掩码；**掩码语义 = 未修改则保留原值**——用户没动这一栏时不得把 `******` 写回磁盘（自测：保存两次后 Key 仍可用）
- [x] `POST /api/settings/probe` 做**真实连通性探测**（`GET /models` 或发一条 1-token 请求），返回 `{ok, message}`；失败原因（401 / 连接超时 / DNS / 404）**可读回显到设置页**，不是只吐 `false`
- [x] **BaseURL 规范化必须显式约定**：默认填 `https://api.deepseek.com/v1`（OpenAI 兼容习惯），而 Pi 内置 DeepSeek provider 是 `https://api.deepseek.com`（**无 `/v1`**）——两种形式都要探测通过，并把该差异写进设置页提示文案；**不允许出现「默认值能跑、用户改一下就连不上」**
- [x] 探测与保存解耦：探测失败给出警告但仍允许保存（离线场景可用），探测结果不静默吞掉
- [x] 日志脱敏过滤器**保留 `%s` / `%(name)s` 占位符**（无脑把 `record.msg` 擦成 `***` 会让 `getMessage()` 抛 `TypeError: not all arguments converted during string formatting`）；用一条带参数的日志写单测验证
- [x] `GET /api/settings` 读回与磁盘一致（关掉重开窗口仍在）；Key 读回时仍是掩码
- [ ] 截图两张（探测成功 / 探测失败回显）存入报告素材——**未完成：仓库内无截图**
  （本节记录的探测矩阵来自对探测函数的实测输出，不是截图证据；`npm run typecheck` + `node --test` 已绿）

## 进度

### ✅ 已交付（提交 `b72fa90`）

`server/app/settings_store.py` 原子写：**临时文件与正式文件同目录** → `fsync` → `os.replace`，
不留残留临时文件。JSON 损坏时原文件改名为 `config.json.corrupt-<UTC 时间戳>` 后继续启动（设置页坏掉不该让整个应用起不来）。

**掩码语义（已实测）**：提交空值或提交回显的掩码**不会抹掉**已存的 Key；只有显式「清除」才真的写空。
`GET /api/settings` 读回仍是掩码。

**探测用标准库 `urllib`**（`server/app/routes/settings.py`），因此 `pyproject.toml` 一行没改
（`httpx` 只在 dev 组）。

★ **探测矩阵（实测）**：

| 场景 | 结果 |
| --- | --- |
| `/v1` 形式正确 | `ok` |
| 缺 `/v1` | 可读 404 文案，**直接给出该替换成哪个 URL** |
| Key 错误 | 401 文案 |
| 端口无人监听 | 「连接被拒绝」，**2.0s** 返回 |
| 黑洞地址 | 「连接超时」，**3.0s** 返回 |

**决策：什么都「不规范化」，探测的就是将来保存下来的那个地址。**
理由见 `docs/report-material/decisions.md` 的 **D-022**：OpenAI 兼容网关里两种写法都可能才是对的那个，
静默改写会重新制造「默认值能跑、用户改一下就连不上」这个故障。
