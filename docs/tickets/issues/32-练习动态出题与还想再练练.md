# 32 — 练习页动态出题（做完内置题自动追加 + 「还想再练练」）

**What to build:** 给独立练习页（`views/Quiz.vue` + `stores/quiz.ts`）补一条**个性化出题闭环**：
做完一关内置题后在后台按答题情况生成新题追加到列表尾部；学生还可以点「还想再练练」再要一批。
施工图：`docs/练习动态出题-功能实现计划.md`（v1，2026-10-01）。

**基线口径（计划里钉死的）**

1. **契约零改动** —— 复用 `POST /api/quiz/variants`（登记）、`GET /api/quiz/generated/{id}`（复用读回）、
   `POST /api/quiz/grade`（判分）三条既有端点；Python 侧一行不改。
2. **先登记、后下发** —— 登记失败的那一批**绝不**发给渲染层（后端判不了分的题发出去，学生提交必 404）。
3. **题号是纯展示序号**（合并列表下标 + 1），不落库、不进契约；稳定标识仍是 `qid`。
4. **自动阶段上限 20**（`AUTO_PHASE_LIMIT`）、**每次续练 10 题**（`MORE_BATCH`）；
   历史生成题与本轮新题**一起**计入 20（不分来源）。
5. **「做完」= 每道内置题至少判分过一次**（不要求全对）——答错可重试是本产品的既有节奏，
   「卡在错题上」的学生恰恰最需要个性化题。
6. **练习页不开对话**：不新增 Pi Tool、不进 6 事件词表、不新增 push 通道（刷题不烧云端对话）。

**Blocked by:** 无（契约零改动，不依赖任何在途票）

**Status:** done（实现与机械验收完成；§8 的手工走查需配好 API Key，留给需求方）

## 验收条件

- [x] ★★ **自动追加**（真机：内置题判完列表 6 → 20；后端日志两次登记 10 + 4 道）：内置题全部判分过后几秒，新题出现在列表尾部、题头带「智团团出的题」；
      生成期间重做 / 切关 / 翻题不被阻塞；同一关**只自动触发一次**（`autoFiredKp`，重做本关不重置）
- [x] ★★ **20 上限与连续编号**：自动阶段任意时刻列表 ≤ 20 题、题号 1…N 连续无跳号；
      截断放在渲染层投影（`questions` computed），不动后端 `limit` 语义
- [x] ★★ **本地保存与复用**：换关卡再回来 / 重启应用后，此前生成的题仍在列表里且能正常判分
- [ ] ★★ **「还想再练练」**：位于最后一题之后（list 尾部 / single 收尾卡动作区），
      每次恰好 +10 题、编号从当前总数之后顺延（20 → 21、再点 → 31）；点击期间防连点；
      必须用 `el-button`（收尾卡已有 `.k12-cta`，一屏只允许一个主色填充）
- [x] ★★ **降级可读**：无 API Key → auto 静默不生成、按钮路径给一句可读中文（不是错误卡、无 5xx 字样）；
      登记失败 → 该批不下发；生成中切关 → 迟到响应丢弃（请求序号判据）
- [x] ★ **载荷纪律**：`context` 逐条白名单投影（条数 ≤ 200、文本限长、脏条目丢弃）；
      请求里**没有** studentId / gradeLevel（主进程注入）
- [x] ★ **沙箱演示态**：两条通道都被 `demoBlocked()` 拦截（与 `quizGrade` 同判据）
- [x] ★ **学生面文案**：只有「还想再练练」五个字，机制说明进 `<TeacherGate>`；
      `student-view-discipline.test.ts` 过检

> ⚠️ **「还想再练练」按钮本体的点击**：无头探针能把 20 题里的 14 题判完，但判完最后一题才能让按钮出现，
