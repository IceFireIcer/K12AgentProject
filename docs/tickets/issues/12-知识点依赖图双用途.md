# 12 — 知识点依赖图双用途

**What to build:** 依赖图（邻接表 + 内存缓存 + 递归 CTE）导入与查询打通，并同时服务两个用途：**推荐路径**（掌握某知识点后推荐后继）与**检索扩展**（补入前置知识点内容）。为什么在这个顺序：11 的检索主链路已通，依赖图才谈得上「扩展检索上下文」；它是 15（闯关闭环顺序）与 21（学段推断联动）的前置，也是创新性维度要讲的双用途之一，**两个用途都要保留，缺一个就少一条演示动作**。

**Blocked by:** 11 RAG 四级降级链 + 学段隔离

**Status:** ready-for-agent

- [ ] `server/app/knowledge/deps.py`：`knowledge_dependencies` 邻接表 + 内存缓存 + 递归 CTE；`GET /api/graph/deps/{kp_id}` 返回 `DepNode[]`
- [ ] **`from → to` 语义全项目一致：`from` 是前置、`to` 是后继**，写进模块注释与契约 docstring（方向搞反是静默错——图看着没错，推荐与扩展全错）
- [ ] 递归 CTE **必须带 `depth` 上限**（如 `WHERE p.depth < 10`）+ `SELECT DISTINCT kp_id, MIN(depth) GROUP BY kp_id ORDER BY depth`（**无上限则遇环死循环**）
- [ ] 导入阶段 **DFS 环检测**：有环时**报出具体路径**（如 `A→B→C→A`），不是只报「检测到环」
- [ ] 悬空引用处理：`to_kp_id`（或 `from_kp_id`）在 `kp` 表不存在时**报错并中止导入**，不静默跳过
- [ ] **用途一（推荐路径）可演示**：答对「变量」后，`GET /api/profile/{student_id}` 的推荐项是依赖图里的后继（不是随机取或按顺序取下一个）
- [ ] **用途二（检索扩展）可演示**：问「循环」时，返回的 `Citation[]` 里含「变量」相关内容（**在 citation 里可见**）；扩展只作补充上下文且**有数量上限**，不得把 top-k 挤满
- [ ] 图规模可见（知识点数 / 边数）并能用脚本一行输出（报告与答辩可用）
- [ ] `server/tests/` 两个单测：① 故意带环的 fixture → 断言错误信息里含完整环路路径；② 悬空 `to_kp_id` → 断言导入中止且错误信息含缺失的 kp_id
- [ ] `npm run typecheck` 与常驻守卫不回退；提交一次 + 一条报告素材（记录双用途的演示动作与截图位置）
