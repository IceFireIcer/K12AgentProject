# 22 — 内容安全终审与脱敏

**What to build:** 把安全做成链路而不是补丁：输入侧敏感词 / 越狱意图轻量检查 → 流式输出 → 生成结束后**整段终审** → 违规则撤回该条消息并替换为 `blocked.safeText`；双重过滤（JSON 词表 + LLM 自审 prompt）；再在 Pi 的 provider 边界用 `before_provider_request` / `before_provider_headers` 做第二道脱敏，保证 API Key 与模型 I/O 不明文入日志。

**Blocked by:** 08（主 Agent + 6 Extension 骨架 + 轨迹导出）

**Status:** ready-for-agent

- [ ] `server/app/safety/guard.py` + `server/resources/sensitive-words.json`（可扩展词表）落位，输入侧对敏感词与越狱意图做轻量检查并留拦截日志
- [ ] 终审在**流结束之后**执行，不阻塞首 token（陷阱：审核拖慢响应）：记录开/关终审两种情形的首 token 延迟，两值接近，数值记入票尾
- [ ] 违规处置：发 `blocked` 事件 `{requestId, reason, safeText}`，前端**撤回该条消息**并替换为 `safeText`（不新增第 7 个事件类型）
- [ ] 撤回有过渡提示（如「刚才的内容不适宜，已为你换成…」），不是突兀闪变（截图或录屏留证）
- [ ] 双重过滤各有一条可复现用例：① 命中 JSON 词表；② 词表未命中但 LLM 自审判违——两者都走同一条 `blocked` 路径
- [ ] `desktop/src/main/safety/review.ts` 与 Python 侧职责清晰：终审判定与安全文本的产生在 sidecar，主进程只做事件投递与撤回协调（不出现第二套判定口径）
- [ ] **日志脱敏保留占位符**（陷阱：擦 `record.msg` 导致格式化炸）：新增单测断言脱敏后 `record.getMessage()` 不抛 `TypeError: not all arguments converted during string formatting`，含 `%s` 与 `%(name)s` 两种形态
- [ ] API Key 与模型 I/O 明文不入日志：用真实 key 的前 8 位扫描 `userData/logs/` 全量日志，零命中；日志里模型请求体只保留脱敏摘要
- [ ] provider 边界脱敏：`before_provider_request` / `before_provider_headers` 两个 hook 已注册，对 `Authorization` 头与请求体敏感字段做审计 / 脱敏，各配一条单测
- [ ] 本地服务安全：sidecar 只绑 `127.0.0.1`；`/api/*` 缺 `X-Auth-Token` 一律 401（含 CORS 场景下 401 仍带 `Access-Control-Allow-Origin`）；`/resources/animation/*` 仍走票 16 的 nonce，**未回退成公开路由**
- [ ] 架构守卫测试一律**正向断言**（不写「禁止某历史实现」式断言）：聊天事件流必须经 `ipcMain` / `webContents.send` + preload 白名单通道送达
- [ ] 合规核对：最小化采集、不采集生物特征（与票 20 的字段清单一致），并把沙箱三重隔离、宿主路径防泄漏（`systemPromptOverride`）两条写进验收记录
