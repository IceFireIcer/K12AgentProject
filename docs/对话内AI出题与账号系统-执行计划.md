## 三、分期计划

### 期一 · 让「现在考考我」走 **AI 现场出题**
- `study/plan-request.ts`：`buildQuizAskMessage` 点名**变式生成**能力（「就这个知识点现场出 3 道**新**题：换数字/换问法/可含开放题；**不要直接给教材原题**，除非我明确要教材题」）。
  ★ 先例：编程求助的 wire 就点名了工具名，不属于新手法。
- `main/agent/prompts/baseline.ts`：「学习计划」那节补一条同口径（与两个工具的自述一致，避免模型读到互相矛盾的指引）。
- **验收**：点一次 → `generated_question` 出现该 kp 新行；卡片来源标签为「智团团出的题」。

### 期二 · 卡片真的「开起来」
- `payload` 卡片落地时**自动滚到卡片**（复用页面已有的「回到最新」滚动机制，不新增滚动监听）。
- 卡片上方标来源（「智团团刚出的 N 道题」/「教材配套题」）。
- **验收**：点完按钮**不用手动滚**就能看到卡片并直接作答。

### 期三 · 推翻「不恢复卡片」：卡片随会话落盘 + 回看恢复
设计（沿用本仓已验证过的先例 `k12Opening`：**元数据跟着消息走**）：
1. 主进程在 `payload` 事件到达时，把该轮的卡片写进 Pi 会话的一条 **`custom` 条目**（Pi 的 `appendCustomEntry`：**只落盘、不进模型上下文**，不会污染对话）；
2. `projectTranscript`（主进程，唯一投影口径）读回它，挂到对应的那条助手消息上；
3. 渲染层**已经支持**恢复的卡片（`restoredCards`，`api/events.ts:159-170`）—— 缺的只是主进程这一侧；
4. **白名单**：可恢复 = 练习卡 / 编程卡 / 进度卡等「载荷自洽」的类型；**动画卡不恢复**（一次性 nonce 早已过期，重放就是伪造交互 —— 这条保留）。
- ⚠️ 实施前需再核实一件事：Pi 的 `appendCustomEntry` 在当前锁定的版本里是否可用（`runtime.ts` 的注释说它存在；若签名不符，退路是同目录下的 `.cards.jsonl` 侧车文件 + 同一投影口径）。
- **验收**：出完题 → **刷新/重启** → 回看那一轮，卡片仍在且能继续作答（判分仍走 Python）。

### 期四 · 生成题的**复用闭环**（大部分已有，补齐入口与说明）
- 已有：个性化学习合并展示 + 「重做本关」。
- 要补：① 每道题标出「智团团出的题」而不是只标整份来源；② 卡片上给一句「这几道题也会出现在**个性化学习**里」+ 一键跳转（`ui.go('quiz')` + `selectLevel`）；
  ③ 巩固条加「**换一批**」（同知识点再现场出 3 道，生成题本来就落库，学生想多练很自然）。
- **验收**：对话里出的题 → 个性化学习里能看到、能重做；在个性化学习里做过的题 → 判分与掌握度在对话侧一致（同一份 Python 判分）。

### 期五 · 本地**账号系统**与账号管理（最大的一块）
> 定位：**本机多档案**，不是联网账号、也不是鉴权。一家一台电脑、兄弟姐妹各用各的，或同一个人不同学段各留一份进度。

- **数据层（Python，已有基础）**：`students` 路由补齐 `GET /api/students`（列表：id/昵称/学段/最近活动）、`POST /api/students`（建号）、`PATCH /api/students/{id}`（改名/学段）、`DELETE /api/students/{id}`（删号）。
  ★ 每个账号一个目录 `students/<id>/`（`learning.db` + `pi-agent/` 会话）——**已经是现成布局**，删号 = 删目录（二次确认 + 明确「不可恢复」+ 建议先导出档案）。
- **主进程**：新增通道 `accounts:list / accounts:create / accounts:rename / accounts:delete / accounts:switch`；
  `resolveActiveStudentId()` 改成「**当前账号**」（落在 `config.json` 的一个字段里），`K12_STUDENT_ID` 仍是最高优先级改道口；
  切号 = 先 dispose 旧运行时再装配新的（与切会话同一条纪律），并清空所有缓存的学生态（五问/画像/进度/日志）。
- **渲染层**：① **首次启动的账号选择页**（没有账号时直接引导创建：昵称 + 学段）；② 侧栏身份卡点击 → **账号管理**（切换/新建/改名/删除/导出档案）；
  ③ 顶栏与侧栏的姓名/学段全部跟着当前账号走；④ 新账号第一次进入 → **自然进入五问冷启动**（现成流程，无需特判）。
- **迁移**：已有 `student_001` 数据**原样**成为第一个账号（不动目录、不导数据），启动时若发现「有目录但账号表为空」则自动登记为「同学」。
- **不可越界**（写进决策，防止后人误解安全模型）：账号**不是**权限边界 —— 后端不鉴权、界面隐藏不等于拿不到；真正被强制的仍是三条硬边界（学段隔离在 SQL / 判分只在 Python / 学生代码只在 Worker）。
- **验收**：建两个账号 → 各自五问、各自进度、各自会话与生成题互不可见；切号后顶栏/侧栏/进度全部跟着变；删号后目录消失、列表更新；`K12_STUDENT_ID` 仍能覆盖当前账号（自动化用）。
