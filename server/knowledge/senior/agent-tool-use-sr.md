## 机制、边界与关联

工具调用模块（Tool Use，工程上常称 function calling / 工具编排）是智能体连接外部世界的接口层，使其能力从「参数化记忆」扩展为「可检索、可计算、可执行」。

机制上，每个工具以结构化接口声明（名称、参数模式、返回格式）注册；大语言模型根据当前子目标输出结构化的调用请求，运行时执行该调用并把返回结果拼回上下文，形成「思考—调用—观察」的迭代。检索类工具通常与 RAG 配合（4.2.1）：查询改写、向量召回、重排共同决定召回质量，而召回质量直接决定回答的事实上限。

在闭环中，工具调用承接规划模块（4.4.2）的任务清单，为执行模块准备素材。多工具场景还需处理编排顺序、参数校验、并行调用与失败重试。

局限与思辨：一是工具结果不可信时会被「以讹传讹」，因此必须保留来源并提示核验（6.1、7.1）；二是检索到的材料可能超出学段，需要分层适配后再呈现（7.4）；三是工具滥用会增加延迟与成本，规划器需要判断「何时该查、何时可直接作答」。
