## 一、为什么不用列表就够了

初中我们已经能用列表装一批数据、用循环算平均值。这份程序在四十个分数上跑得很好。那为什么做模型时还要换一套工具？

看一个具体场景。要让一张 28×28 的手写数字图片（784 个像素值）做一次线性变换，对每个像素求一个加权和，用列表 + 循环是这样：

```python
total = 0
for i in range(784):
    total += weights[i] * pixels[i]
```

784 次循环，算一张图还好。可是训练时要同时处理 128 张图片、重复几万轮——那就是几百亿次循环。Python 的循环每次都要做一遍「取值—相乘—累加」的解释执行，**在这个量级上慢得没法用**。

NumPy 提供的**数组**（`ndarray`）解决的正是这件事：它把「一整批数字」当做一个整体来运算，底层的循环用编译好的 C 代码一次跑完。

```python
import numpy as np

pixels = np.array([[120, 34, ...], ...])       # 形状 (28, 28)
weights = np.random.rand(28, 28)               # 形状 (28, 28)
score = (pixels * weights).sum()               # 一行，等价于上面的 784 次循环
```

同样的计算写成 `(pixels * weights).sum()`，**没有任何显式循环**，速度通常是纯 Python 循环的几十倍到上百倍。这种写法叫**向量化**（vectorization）——不是「一次算一个」，而是「一次算一批」。

## 二、形状（shape）是读懂报错的钥匙

NumPy 里最重要的概念不是函数，而是**形状**。每个数组都有一个 `shape` 属性，表示每一维有多少个元素：

```python
a = np.zeros((3, 4))
print(a.shape)          # (3, 4)，3 行 4 列
print(a.ndim)           # 2，几维
print(a.size)           # 12，一共多少个元素
print(a.dtype)          # float64，每个元素的类型
```

绝大多数 NumPy 报错，读到最后一句都是在说两件事之一：**形状对不上**（`operands could not be broadcast together with shapes (3,4) (4,3)`），或者**索引越界**（`index 5 is out of bounds for axis 0 with size 5`）。所以排查时第一件事永远是：把两边的 `shape` 打印出来。

形状里最常打交道的两个操作：

- **变形**：`a.reshape(2, 6)` 把 12 个元素重新排成 2 行 6 列，元素总个数必须不变；`a.reshape(-1)` 把多维拉平成一维（`-1` 表示「这一维让程序自己算」）。
- **加一维**：`a[np.newaxis, :]` 或 `a.reshape(1, -1)` 在最前面加一个长度为 1 的维度。这在批量运算里非常常见——把一张图变成「一批里的一张图」，形状从 `(28, 28)` 变成 `(1, 28, 28)`。

还有一个必须建立的习惯：**统一数据类型。** NumPy 数组的元素类型是统一的（都是整数或都是小数）。如果混着来，整数除法、溢出这类问题会悄悄发生——两个整数数组相除，得到的可能不是你想要的结果。

## 三、切分数据与统计

NumPy 的另一大用处是**切分**和**统计**，这正好是机器学习流程里天天要做的事。

```python
X = np.random.rand(100, 4)      # 100 条样本，每条 4 个特征
y = np.random.rand(100)         # 100 个答案

# 切片：前 80 条做训练，后 20 条做测试
X_train, X_test = X[:80], X[80:]
y_train, y_test = y[:80], y[80:]

# 统计：一次算完一整列
print(X.mean(axis=0))     # 每一列的均值，得到一个长度 4 的数组
print(X.std(axis=0))      # 每一列的标准差
print(X.min(axis=0), X.max(axis=0))
```

这里有一个**必须记住的实战细节**：切分之前要先打乱顺序。

```python
order = np.random.permutation(len(X))
X, y = X[order], y[order]
```

原因很实在：真实数据往往**是按某个顺序排列**的——按班级、按日期、按类别。如果直接取前 80 条做训练，很可能前 80 条全是同一个班的，测试集里却装着另一个班。这种模型在测试时成绩很好，换一批真实数据就崩掉。打乱这一步只要一行代码，但漏掉它造成的错误**从结果上完全看不出来**，只会让所有评估数字失去意义。

`axis` 这个参数也值得单独记一下：`axis=0` 表示「沿第 0 维（行）合并」，也就是**对每一列**做运算，结果的长度等于列数；`axis=1` 则相反。记不住的时候，打印一次形状比对一下，比背定义可靠。

想一想：一份 1000 条的气温数据按日期从 1 月排到 12 月，如果要预测未来的气温，直接打乱顺序切分是正确的做法吗？为什么这里反而不能随意打乱？
