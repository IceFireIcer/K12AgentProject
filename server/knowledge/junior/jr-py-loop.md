## 一、为什么需要循环

先看一个真实的麻烦。要打印 1 到 5 的平方，你可以这样写：

```python
print(1 * 1)
print(2 * 2)
print(3 * 3)
print(4 * 4)
print(5 * 5)
```

五遍还能忍，可如果要求打印 1 到 1000 的平方呢？写一千行显然不行。更麻烦的是：这段代码每次只做「改一个数、再算一遍」这种重复动作。

**循环就是为「重复」准备的语法**。同样的任务写成循环只需要两行核心代码：

```python
for i in range(1, 1001):
    print(i * i)
```

`range(1, 1001)` 会依次产生 1、2、3 … 1000；每产生一个数，就把下面缩进的那一行执行一次。缩进就是「这些代码属于循环体」的标志，Python 靠缩进判断范围，所以**缩进写错会直接改变程序的意思**，这是初学者最容易掉的坑。

循环的价值不只是省字。更重要的是：它把「处理一批数据」变成了一件稳定的事。全班 40 个分数、一整个文件的几千行记录，都是同一种处理方式重复作用在每一份数据上——这正是程序比人可靠的地方：它不会漏掉第 37 个。

## 二、for 与 while 两种写法

Python 里最常用的循环有两种，选哪一种取决于你知道不知道要重复多少次。

**for 循环：次数已知或要遍历一批数据。**

```python
scores = [88, 92, 75, 60]
total = 0
for s in scores:
    total += s              # 等价于 total = total + s
average = total / len(scores)
```

这段代码就是「求平均分」的完整实现：`total` 负责累加，`for s in scores` 依次把每个分数交给循环体。这种「遍历列表逐项处理」的写法是数据处理里出现频率最高的模式。

**while 循环：次数未知，靠条件决定停不停。**

```python
guess = 0
while guess != target:
    guess = int(input("再猜一次："))
```

只要条件为真就继续。适合「猜数字」「一直问到用户说停」这类场景。

无论哪种循环，都有一个**循环变量**（上面的 `i`、`s`）承担「这一轮轮到谁」的职责。它的名字同样要写清楚：遍历分数就叫 `s` 或 `score`，不要用 `a`。

## 三、循环里最容易踩的五个坑

循环的语法很短，出错的地方却很集中。下面五条几乎覆盖了初学者 90% 的问题。

**坑一：缩进放错。** 想循环打印一次却在循环外面，重复代码就只执行了一遍；反过来，本该只执行一次的输出被缩进了，结果会打印几十遍。判断方法是问自己：这一行是「每轮都要做」，还是「全部做完之后再做一次」？

**坑二：死循环。** `while` 里忘了改变条件，循环永远不会停。比如 `while total < 100:` 里却没写 `total += ...`，程序会一直转，界面卡死。写 `while` 时养成习惯：先写循环体里让条件发生变化的那一行，再写其他内容。另外，标准输入里按 `Ctrl + C` 可以强制中断，这是你最后的安全绳。

**坑三：累加变量没清零。** 求完一组的和之后，如果忘了把 `total` 归零，下一组的结果会把这组也算进去，最后得到一个莫名其妙的大数。这类错误的特征很典型：**结果偏大，而且大得离谱**。所以「用完就清零」要写在累加变量出现的旁边。

**坑四：搞不清边界。** `range(1, 5)` 只产生 1、2、3、4，不含 5；`range(5)` 是 0 到 4。差一位（差一错误）在统计人数、切分数据时非常常见。实在记不住就打印一次看看：`print(list(range(1, 5)))`，一眼就明白。

**坑五：在循环里改列表。** 一边遍历一边删元素，会让迭代漏项。正确做法是先构造一个新列表，或者遍历它的副本。

把这五个坑记住之后，你会发现循环的写法其实只有两三种，真正的难点在「想清楚每一轮要做什么、什么时候停」——这也是编程最核心的能力。
