## 一、列表：一批同类数据排成队

变量一次只能装一个值。可是现实里的数据天生就是**一批**：全班 40 个分数、一周 7 天的气温、一条时间线上一百次测量。给每一个都起个名字，显然做不到。

**列表**解决的就是这个问题：把一批数据按顺序排在一起，共用一个名字。

```python
scores = [88, 92, 75, 60, 95]
print(scores[0])      # 88，第一个
print(scores[-1])     # 95，最后一个
print(len(scores))    # 5，一共几个
print(sum(scores) / len(scores))   # 82.0，平均分
```

有三点必须记住。

**第一，位置从 0 开始数。** `scores[0]` 是第一个，`scores[4]` 是第五个。这一点和「第几个」的日常说法差一位，是初学者最常犯的错。`scores[5]` 会直接报错（越界），报错信息通常是 `IndexError: list index out of range`。

**第二，列表能和循环配合。** 这是它真正有用的地方：

```python
total = 0
for s in scores:
    total += s
```

`for s in scores` 会依次把每个分数交给循环体。上一节学的循环，加上这一节的列表，「处理一批数据」这件事才算真正成形。

**第三，改列表要小心。** `scores[0] = 90` 会把第一个改成 90；`scores.append(70)` 在末尾加一个；`scores.remove(60)` 删掉第一个值为 60 的元素。注意 `remove` 是按**值**删，不是按位置；按位置删要用 `del scores[0]` 或 `scores.pop(0)`。

## 二、字典：一条记录有好多字段

列表按位置存，适合「一堆同类的东西」。但很多数据是**一条记录分好几个字段**——比如一位同学的成绩单：姓名、学号、语文、数学、英语。

如果只用列表，你会写成 `["小明", 1001, 88, 92, 75]`，然后必须记住「第 0 位是姓名、第 2 位是语文」。三个字段还行，十个字段就彻底记不住了。

**字典**就是为这个准备的：每一项由一个**名字（键）**和一个**值**配对。

```python
student = {"name": "小明", "score": 88, "grade": "初一"}
print(student["name"])       # 小明
student["score"] = 92        # 改掉某个字段
print(student.get("age", "未填写"))   # 没有这个键时给个默认值，不报错
```

字典有两个实用优点。第一，**取值靠名字**，不用数位置，代码读起来就是一句人话。第二，用 `student.get("age", "未填写")` 这种写法可以在键不存在时给一个默认值，避免程序直接崩掉——读真实数据时这非常常见，因为表格里总有空格子。

## 三、合起来用：一张表格

真实的数据处理几乎都是这两种结构套在一起：**列表装很多条记录，字典装一条记录的各个字段。**

```python
students = [
    {"name": "小明", "score": 88},
    {"name": "小红", "score": 92},
    {"name": "小刚", "score": 75},
]

total = 0
for s in students:
    total += s["score"]
print(total / len(students))     # 85.0
```

这段短短六行代码，就是「读一张成绩单、算平均分」的完整实现。看懂它，你就掌握了 Python 数据处理最核心的一个套路。

再往前走一步，还要学会**筛选**：

```python
passed = [s for s in students if s["score"] >= 80]
```

这一行会挑出所有 80 分以上的同学。这种写法叫列表推导式，看起来紧凑，意思就是「遍历 students，把符合条件的挑出来，组装成一个新列表」。

## 四、四个最常踩的坑

**坑一，以为切片会复制。** `a = scores` 只是让两个名字指向同一份列表，改 `a` 会连 `scores` 一起改。真正复制要用 `a = scores[:]` 或 `list(scores)`。这个坑在「先备份一份再处理」的时候特别容易踩到，表现为「我明明只改了副本，原始数据怎么变了」。

**坑二，用不存在的键。** `student["age"]` 在键不存在时会报 `KeyError`，用 `.get()` 才安全。

**坑三，边遍历边删。** `for s in scores: scores.remove(s)` 会漏掉元素，因为删掉一个之后后面的位置全部前移。正确做法是构造一个新列表。

**坑四，嵌套结构太深。** 列表里套字典里再套列表，看着很灵活，但调试时会非常痛苦。建议最多套两层，再深就拆开、给中间结果起个名字。

想一想：如果用这两种结构表示「一周七天每天的最高气温」，你会怎么组织？如果还要带上「当天下没下雨」，结构该怎么改？
