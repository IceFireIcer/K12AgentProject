# 列表与字典：把一批数据放在一起

> **一句话核心**：列表把一批数据按顺序排好，字典给每份数据配一个名字，方便按顺序取或按名字查。

## 小学低年级

你的铅笔盒里放着好几支笔，它们排成一排。

要拿第二支，你从左边开始数：第一支、第二支，拿到了。

列表就像这一排笔：很多东西放在一起，按顺序排好，从前往后数就能找到想要的。

字典像另一种盒子：每个小格子上写着名字，写着「橡皮」的格子里就放橡皮。不用数，看名字就知道在哪儿。

想一想：你的书包里，哪样东西最好用「排队数」的办法找到？

## 小学高年级

列表和字典都是把**一批**数据放在一起的办法，区别在于「怎么找」。

列表是按顺序排的：一堆分数放在一起，第一个、第二个、第三个……按位置就能取出来。适合「一整批同样的东西」——全班成绩、一周的气温、一整篇文章里的词。

字典是按名字查的：给每份数据配一个名字（键），用名字直接找到内容。适合「每份数据有自己标签」的情况——比如「语文：92」这样的成绩单，用科目名就能查到分数。

两者常常一起用：一份名单是列表，名单里的人各有姓名和年龄，那就是「列表里装着字典」。

划重点：按顺序用列表，按名字用字典。

## 初中

列表和字典是两种最基本的**容器**：它们把多个值聚成一个整体，可以用一个名字管理。

列表是有序序列，靠**位置**取用。要注意下标从 0 开始：第一个元素是 [0]，最后一个可以用 -1 表示。列表支持增、删、改，长度也会随增删变化，所以「边遍历边增删」容易出错——遍历途中长度变了，容易漏项或越界。

字典是**键值对**的集合，靠**键**取用。键在同一个字典里必须唯一，重复赋值会覆盖旧值；而值可以是任何类型，包括另一个列表或字典。查一个不存在的键会报错，所以常用「先判断键在不在」的写法。

选哪个，取决于你之后怎么问数据：要「从头到尾挨个处理」用列表；要「按名字直接拿到」用字典。混用的典型是「列表里放字典」——一批记录，每条记录有若干字段，这也是后端返回数据最常见的样子（见 2.2.2 的数据处理流程）。

易错点：把「位置」和「键」弄混（用整数下标去查字典），以及忘记下标从 0 起。

## 高中

列表与字典是两种**数据组织方式**，选择它们本质上是选择访问模型：列表提供**按序访问**，字典提供**按键映射**。这个选择会直接影响查找代价——在一段无序数据里按内容查找需要逐项比较，而字典用哈希把「按键查」做到接近常数时间。这是计算机科学里最早、也最实用的一组成本权衡。

实现层面：列表通常是连续存储的引用数组，按下标访问很快，但在中间插入或删除需要搬动后续元素；字典是哈希表加冲突处理（也有的语言用平衡树实现有序映射），因此字典**不保证按插入顺序之外的顺序遍历**，且键需要可哈希。这解释了两类常见约束：为什么字典的键不能用列表，以及为什么列表的中间插入在数据量大时明显变慢。

使用层面的经验：结构要跟着**问法**走，而不是反过来。如果程序总在问「第几个」，用列表；总在问「名字对应的值是什么」，用字典。两者嵌套（列表装字典、字典装列表）能表达树的形状，是后续学习结构化数据、乃至 4.2.1 里「把教材切成可检索的片段」这类真实工程问题的基础。

边界：容器的选择不是越「快」越好。小数据量下差异可忽略，而**可读性**的收益更实：一段用字典表达「字段：值」的代码，比用两个平行列表更不容易错位。这与 8.1 的命名规范同属一个主题——让代码表达意图，把性能留给真的需要的地方。
