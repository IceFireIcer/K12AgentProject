## 1. 目标

依赖图**同时**服务两个用途（创新点，**两个都要实现**）：
① 推荐路径规划；② 检索上下文扩展。

## 2. 任务清单

- [ ] 导入 `knowledge_dependencies`（邻接表）；**导入阶段 DFS 环检测**
- [ ] **用途一 · 推荐路径**：掌握「变量」→ 推荐「循环」为下一步
- [ ] **用途二 · 检索扩展**：学生问「循环」→ 自动把「变量」内容纳入检索范围
- [ ] `GET /api/graph/deps/{kp_id}` 端点

## 3. 关键 SQL（递归 CTE，向上找全部前置）

```sql
WITH RECURSIVE prereq(kp_id, depth) AS (
  SELECT from_kp_id, 1 FROM knowledge_dependencies WHERE to_kp_id = :kp
  UNION
  SELECT d.from_kp_id, p.depth + 1
  FROM knowledge_dependencies d JOIN prereq p ON d.to_kp_id = p.kp_id
  WHERE p.depth < 10
)
SELECT DISTINCT kp_id, MIN(depth) AS depth FROM prereq GROUP BY kp_id ORDER BY depth;
```

## 5. 陷阱

| # | 陷阱 | 说明 |
| --- | --- | --- |
| 1 | **环导致递归 CTE 死循环** | `depth` 上限**必须加**；导入阶段先做环检测。 |
| 2 | 依赖方向搞反 | `from → to` 语义全项目一致（**`from` 是前置，`to` 是后继**），写进注释。 |
| 3 | 悬空节点 | `to_kp_id` 在 `kp` 表里不存在 → 导入时**报错而非静默跳过**。 |
| 4 | 检索扩展放大噪声 | 前置内容只作补充上下文，**要有数量上限**，别把 top-k 挤满。 |
