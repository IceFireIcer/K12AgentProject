## 1. 目标

提供**可写可跑可调试**的 Python 环境，并与动画沙箱、主线程三方隔离。

## 2. 任务清单

### 2.1 编辑器与运行

- [ ] **Monaco Editor**（VS Code 同款）接入
- [ ] **Pyodide + 独立 Web Worker**，与动画沙箱、主线程**三方隔离**
- [ ] **离线**：Pyodide 资源自托管于 `desktop/resources/`，**不依赖 CDN**
- [ ] 预置 `numpy`；`matplotlib` 视包体积决定（超预算则砍）
- [ ] **Worker 懒加载**（进编程卡片才加载）
- [ ] **超时中断**（Pyodide 需用 `setInterruptBuffer`，防无限循环卡死）

### 2.2 代码模板

- [ ] 按知识点预置模板（**排序 / 决策树 / 神经网络**）
- [ ] `CodeTemplate`：`scaffold`（含 TODO 标记）+ `expected_behavior`

### 2.3 求助机制

- [ ] 编程 Extension 注册 `get_code_template` / `get_coding_hint` / `evaluate_code`
- [ ] **自动感知报错 + 手动求助按钮**
- [ ] 连续失败 N 次（建议 3）后主 Agent 主动介入，`CodingHint.level` **逐级加深**
- [ ] **提示要引导而非直接给答案**（教学价值所在）

### 2.4 ★ 安全边界（**v2 新增硬约束**）

- [ ] **`evaluate_code` 绝不在主进程执行学生代码** ——
      必须经 IPC 转发给渲染进程的 **Pyodide Worker** 执行，结果回传
- [ ] **加架构守卫测试**断言主进程不含执行学生代码的路径

> **原因**：Pi 的 Extension 与 Agent **同进程且拥有完整系统权限**。
> 在主进程执行学生代码 = 无沙箱裸奔。

## 3. 验收标准（DoD）

- [ ] 能写能跑 Python，返回 stdout / stderr
- [ ] 报错时学生看到**友好提示**（不是 Python traceback 原文）
- [ ] 学生代码**无法接触 sidecar / 文件系统 / 网络**（可现场演示）
- [ ] 无限循环被中断，UI 不卡死
- [ ] 连续失败 3 次后**主 Agent 主动介入**且提示逐级加深
- [ ] **架构守卫测试：主进程无执行学生代码路径**

## 4. 陷阱

**完整清单见 `docs/业务陷阱清单.md` 第 7 节**。要点：

| # | 陷阱 | 说明 |
| --- | --- | --- |
| 1 | **Pyodide 体积大 / 加载慢** | **本地自托管 + 懒加载**。 |
| 2 | **误以为两边共享 Python** | Pyodide 与 sidecar 是**两个独立运行时**，学生代码**绝不接触 sidecar**（**报告要讲**）。 |
| 3 | **无限循环卡死 UI** | 必须在 Worker 里 + `setInterruptBuffer` 超时中断。 |
| 4 | **Monaco 与 vite 打包** | 需要 worker 配置，**不配会在生产构建报错**。 |
| 5 | 直接给答案 | 提示按 `level` 递进。 |
| 6 | **CDN 依赖** | 任何 CDN 引用都会在**断网演示时翻车**。 |
