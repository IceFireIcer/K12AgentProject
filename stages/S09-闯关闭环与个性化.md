## 1. 目标

把「答题」升级为**闯关**；掌握度回流画像，影响下一轮难度 —— 形成**自适应学习闭环**。

## 2. 任务清单

### 2.1 闯关状态机

- [ ] `progress` 表驱动：`locked → learning → quizzed → mastered`
- [ ] 解锁规则：**「掌握度 ≥ 阈值 且 该关已 quizzed」才解锁后继**（写进注释）
- [ ] 关卡顺序由**依赖图拓扑序**决定（S07 产出）
- [ ] 答对 → 解锁下一关；答错 → 走 `next_hint`，`CodingHint.level` 逐级加深

### 2.2 UI

- [ ] 进度条组件（**轻量 CSS，不引游戏引擎**）
- [ ] 徽章解锁动画 + 徽章墙（用 CSS transition/animation，**不引 Anime.js**）
- [ ] 答对/答错的即时反馈动效

### 2.3 个性化闭环

- [ ] 画像更新（掌握度 / 偏好 / 薄弱点）——**每轮末执行**
- [ ] **薄弱点回流**：下一轮检索/出题优先覆盖薄弱点
- [ ] `GET /api/profile/{student_id}` 画像端点
- [ ] **冷启动**：新学生无历史 → 按学段给默认路径（**无 `progress` 行要兜底初始化**）
- [ ] Dashboard 视图：掌握度分布 + 推荐下一步

## 3. 验收标准（DoD / 关卡 D）

- [ ] 答对 → 下一关解锁，进度条前进，弹徽章；答错 → 出现提示，**关卡不解锁**
- [ ] **掌握度影响推荐**：连续答错某知识点后，下一轮更可能再考它（**可演示数据流**）
- [ ] **冷启动**：新建学生 → 直接可用，有默认推荐路径
- [ ] **重启应用后：进度、徽章、掌握度全部还在**
- [ ] 徽章/进度**无外部依赖**（纯本地资源）

## 4. 陷阱

| # | 陷阱 | 说明 |
| --- | --- | --- |
| 1 | 状态不一致 | 前端展示**必须以后端 `progress` 表为准**，不要前端各存一份。 |
| 2 | 解锁条件含糊 | 规则要写死并写进注释（见 2.1）。 |
| 3 | **闭环断裂** | 画像更新要在**每轮末**执行，且下一轮**要真的读它**。 |
| 4 | 徽章动画依赖 | 用 CSS，**不引 Anime.js**（留给动画卡片）。 |
| 5 | 冷启动空指针 | 新学生没有 `progress` 行时要能**兜底初始化**。 |

> **v2 说明**：原「LangGraph 条件边实现自适应」的说法作废 —— 现在由 **Tool 结果 + 画像回流**实现。
> **但业务规则不变**：解锁条件、限幅、冷启动兜底、以后端为准，这四条照旧。
