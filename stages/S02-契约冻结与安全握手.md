## 3. ★ 冻结的接口契约（**v2 继续有效**）

- **契约来源**：**pydantic 唯一来源** → OpenAPI → `openapi-typescript` 生成 `api-types.ts`（**生成物不手改**）。
- **字段命名**：Python `snake_case` → JSON `camelCase`（`alias_generator=to_camel`）；`extra="forbid"`。
- **6 个事件词表（一字不改）**：`delta | citation | payload | blocked | done | error`。
- **SubAgent payload**：`AnimationPayload` / `CodeTemplate` / `CodingHint` / `CodeEvaluation` / `QuizPayload` / `QuizResult`。

## 4. 陷阱（**四个真 bug，全部由端到端验收暴露**）

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | **★ 无 token 时前端看到 `TypeError: Failed to fetch` 而非 401** | **Starlette 中间件是洋葱结构**，最后 `add_middleware` 的在最外层。CORS 加在鉴权内层 → 鉴权提前 return 的 401 **不带** `Access-Control-Allow-Origin`，浏览器把 401 **伪装成网络错误** | **CORS 必须最后 add**；补回归测试 |
| 2 | 日志抛 `TypeError: not all arguments converted` | 脱敏改写 `record.msg` 把 `%s` 擦成 `***`，`record.getMessage()` 的 `msg % args` 崩了 | 保留 `%s`/`%(name)s`/`%d` 占位符 |
| 3 | 最有用的鉴权日志被抹成 `Authorization: *** ***` | 脱敏把值位置的 `Bearer` 也当凭据擦了 | 加非凭据词白名单 |
| 4 | 架构守卫正则**永远匹配不到** | `stripComments()` 顺手把模板字符串也抹了 → 守卫形同虚设 | 修正后**立刻抓出一处真实违规** |

**另 3 个 codegen 坑**：`openapi-typescript` 的 `.bin` 是 shell 脚本（用 node 执行报错 → 改编程式 API）；
`models_json_schema()` 定义在 `$defs` 下；该函数**只接受 BaseModel**（传枚举要拆开用 `TypeAdapter`）。

## 5. 与 v2 的关系

**继续有效**：pydantic 契约链、codegen `--check`、token 鉴权、脱敏过滤器、架构守卫。

**必须返工（唯一一处）**：渲染进程↔主进程传输层 **HTTP+SSE → IPC**。
> 理由：编排移入主进程后，同进程通信走 HTTP 是绕远，且 IPC 天然没有跨源/鉴权问题。
> **但 6 事件词表一字不改**，前端解析/分发语义可复用（只是取数来源从
> `fetch().body.getReader()` 换成订阅回调）。
> **`EventSource` 禁令保留**在架构守卫中——防止有人回退到 SSE 时又踩一次鉴权 header 的坑。

**v2 需新增**：
- 删除 `Intent` 枚举（路由改为 LLM 选 Tool）。
- **Tool 名 → 事件 `kind` 映射**冻结登记（执行文档 9.3）。
- **Pi Tool 的 TypeBox 参数 ↔ pydantic 模型一致性断言**（防「pydantic 改了、Tool 没改」的静默漂移）。
